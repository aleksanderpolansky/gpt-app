## Изменение

Версия V1_0_2 сохраняет функциональный объём V1_0_1 и дополнительно исправляет защитный контроль списка изменённых файлов. Предыдущий runner корректно создал новый компонент как untracked-файл, но проверял только `git diff --name-only`, который не показывает новые untracked-файлы. Поэтому gate ошибочно видел только `page.tsx`, останавливал релиз и выполнял безопасный rollback. Теперь gate объединяет tracked diff и `git ls-files --others --exclude-standard`, после чего требует ровно два ожидаемых файла.

Также сохранено исправление четырёх блокирующих ошибок ESLint `react-hooks/set-state-in-effect`, обнаруженные предыдущим runner до commit/push. Начальная загрузка смысловых связей теперь обновляет React state только из асинхронных callbacks; чтение `relationsZone` выполняется через `useSearchParams`; сброс несуществующей зоны не требует эффекта; очистка поиска выполняется в пользовательских обработчиках открытия/закрытия зоны.

На странице карточки объекта наблюдения добавлена интерактивная «Карта связей ОН». Текущий ОН расположен в центре. Вокруг него отдельными зонами показываются прямой родитель, дети, соседи и активные типизированные смысловые связи из существующего API отношений.

Карта использует уже установленный `@xyflow/react`, то есть новый графический движок и новая зависимость не добавлялись. Глобальный zoom/pan выполняется средствами React Flow.

## Плотность и масштабирование

- каждая зона рассчитывает плотность независимо;
- 0–4 карточки: обычный режим;
- 5–9: компактный;
- 10+: плотный;
- текст не уменьшается ниже 11 px;
- при переполнении показывается агрегатор «+ N ещё»;
- в режиме фиксированного размера карточки не уменьшаются, внутри зоны используется прокрутка;
- перегруженная зона не уменьшает карточки в остальных зонах.

## Развёрнутая зона

Зону можно развернуть поверх страницы, искать внутри неё и открыть отдельно в новой вкладке через параметр `relationsZone`. В развёрнутой смысловой зоне используется существующий менеджер смысловых отношений, поэтому создание/деактивация связи не получает нового обходного API. Создание нового ОН ведёт в существующий маршрут создания. Для структурной зоны «Дети» используются существующие маршруты создания промежуточного и листового ОН, когда это разрешено текущим объектом.

## Ограничение этого этапа

Карта не создаёт новую модель фактов и не придумывает API для целевых/референтных/расчётных значений. Такие зоны должны подключаться отдельным этапом после проверки фактических контрактов хранения значений параметров.
