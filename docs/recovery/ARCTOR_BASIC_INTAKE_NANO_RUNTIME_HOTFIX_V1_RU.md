DB schema change: NONE

## Решение этапа

Базовый анализ сохранённой активности остаётся узким и выполняет только две задачи: извлекает явно сообщённые измеримые параметры и ищет подходящую уже настроенную типовую активность. Никакие ЦО/ОН, стандартные связи, факты или индивидуальный анализ на этом этапе не применяются.

## Исправление выбора базовой модели

Предыдущий runtime пытался определить Nano-модель через отдельную строку таблицы `ai_model_tiers`. Это создавало лишнюю точку отказа и в production привело к безопасному fallback. Теперь Nano-модель берётся из уже существующего серверного каталога AI-Навигатора `navigatorModelCatalog`, который является источником утверждённого имени модели для tier `nano`.

Бюджетный preflight, usage accounting, `store=false`, ноль автоматических retries и общий fail-soft fallback сохраняются.

## Когда типовая активность считается доступной для поиска

Типовая активность передаётся базовой модели как кандидат только если у неё есть активный impact profile и в этом профиле есть хотя бы одна связь с ЦО/ОН.

Если у типовой активности нет связанного ЦО/ОН, она ещё не представляет готовый стандартный сценарий и не должна предлагаться пользователю как найденный вариант. Поэтому при пустой онтологии или при ещё не настроенных связях список подходящих типовых активностей естественно остаётся пустым.

При этом параметры всё равно извлекаются из сообщения. Например для `сегодня подтянулся 15 раз` базовый анализ должен показать `Повторения: 15`, даже если ни одна типовая активность пока не готова к применению.

## Масштабирование кандидатов

Сначала сервер дешёво ранжирует пользовательские типовые активности по текстовой близости и оставляет до 96 лучших. Только для этого ограниченного набора проверяется наличие активного профиля и хотя бы одной связи с ЦО/ОН. После фильтрации в Nano отправляется не более 24 названий кандидатов.

Таким образом модель не получает каталог ЦО/ОН, impact profile, факты или историю пользователя; она получает только текст активности и названия уже готовых типовых активностей.

## Границы этапа

- `activity_template_id` автоматически не назначается;
- impact profile автоматически не применяется;
- `activity_object_facts` не создаются;
- ЦО/ОН не создаются и не изменяются;
- кнопки будущих действий не добавляются;
- действия после выбора типовой активности остаются отдельным будущим блоком;
- semantic clean-start reset остаётся отдельным будущим этапом.

## Acceptance

1. Ввести новую активность через правую колонку.
2. Убедиться, что справа остаётся только подтверждение фиксации активности.
3. Открыть активность через Журнал в рабочем месте анализа.
4. Для текста с явным числовым показателем увидеть этот показатель.
5. Пока нет типовой активности с активным профилем и хотя бы одной связью ЦО/ОН, увидеть сообщение, что подходящая типовая активность не найдена.
6. После будущего добавления ЦО/ОН и настройки профиля та же схема сможет передать готовую типовую активность Nano для точного смыслового сопоставления.
