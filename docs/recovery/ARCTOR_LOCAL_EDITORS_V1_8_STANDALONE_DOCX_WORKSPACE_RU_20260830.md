# ARCTor Local Editors V1.8 — standalone DOCX workspace

Дата: 2026-08-30
Baseline: `634e8c067e769fc823c622f321c8492f03ae09dc`

## Исходное состояние

V1.7.1 закрыт с PASS и опубликован в `main`. На desktop DOCX при увеличенном масштабе снова позволяет добраться до левого и правого края. На смартфоне, особенно во встроенном браузере Messenger и при большом масштабе, доступ к левому краю всё ещё может быть неудобным из-за ограниченной ширины редактора внутри общей оболочки ARCTor.

Документ остаётся local-only: содержимое DOCX не отправляется на сервер ARCTor и не сохраняется в серверном или постоянном браузерном хранилище.

## Решение V1.8

Добавить общий полноэкранный контейнер локального редактора и первым подключить к нему DOCX.

Пользовательский поток:

1. Открыть DOCX как сейчас на `/local-editors`.
2. Нажать «Развернуть редактор».
3. Редактор остаётся тем же React-экземпляром и тем же локальным `File` в памяти браузера, но занимает весь viewport поверх общей оболочки ARCTor.
4. При входе в полноэкранный режим документ автоматически подгоняется по ширине нового viewport.
5. Пользователь может редактировать и менять масштаб обычными средствами CasualOffice.
6. «Завершить редактирование» или `Esc` возвращает обычное отображение `/local-editors` без закрытия файла и без потери несохранённых изменений.

## Архитектурный lock

Создан `LocalEditorStandaloneFrame` как общий контейнер, который далее можно повторно использовать для XLSX и mind map. Он не создаёт новую вкладку браузера и не сериализует документ между окнами, поэтому local-only boundary сохраняется без дополнительных механизмов передачи файла.

Полноэкранный режим реализован через fixed overlay, блокирует прокрутку фоновой страницы и поддерживает выход по `Esc`. Он не делает сетевых вызовов, не использует LocalStorage/SessionStorage/IndexedDB и не добавляет API-маршруты.

## Что не меняется

- `@casualoffice/docs@1.4.2` остаётся текущим DOCX-движком.
- V1.7 mobile fit и V1.7.1 horizontal-overflow compatibility rule сохраняются.
- SQL: 0.
- Миграции БД: 0.
- Серверное хранение документа: 0.
- Новые document-content API: 0.

## Acceptance

Обязательно проверить после публикации:

- desktop: обычный режим и полноэкранный режим;
- smartphone: полноэкранный режим занимает всю ширину и высоту доступного viewport;
- вход в полноэкранный режим выполняет fit-to-width;
- после увеличения можно использовать штатную горизонтальную прокрутку редактора;
- «Завершить редактирование» возвращает обычную страницу с тем же открытым документом;
- `Esc` выходит из полноэкранного режима на desktop;
- несохранённые изменения не теряются при переключении режима;
- сохранение DOCX локально работает в обоих режимах;
- Console не получает новых CSP/runtime ошибок.

## Следующая точка

После production acceptance V1.8 закрыть текущий этап DOCX и перейти к XLSX Editor V1, используя тот же `LocalEditorStandaloneFrame` для полноэкранного рабочего режима.
