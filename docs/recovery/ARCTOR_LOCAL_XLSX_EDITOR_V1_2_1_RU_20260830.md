# ARCTor Local XLSX Editor V1.2.1 — selection + normal-view fit

Дата: 2026-08-30
Baseline: adc97a51bff52db74609e6fad1f06f4c676c2195
Release: ARCTOR_LOCAL_XLSX_EDITOR_V1_2_1_SELECTION_FIT_HOTFIX_R6

## Причина

После V1.2 структурные операции использовали внутреннее состояние выбранной ячейки, но desktop range selection Tabulator не синхронизировал начало активного диапазона обратно в это состояние. В результате визуально выбранная ячейка могла отличаться от координаты, относительно которой вставлялись строки и столбцы.

В обычном режиме /local-editors XLSX-редактор также мог расширять центральную колонку страницы и уводить правую часть верхней панели за правую колонку приложения.

## Решение

1. ArctorTabulator публикует начало активного desktop range selection через onRangeSelectionChange.
2. LocalSpreadsheetEditor использует тот же handleCellClick для одиночного клика и начала range selection, поэтому верхний индикатор «Выбрано» и структурные операции получают одну координату.
3. Обычный XLSX-контейнер и его родитель получили min-width/max-width/overflow boundary; горизонтальная прокрутка остаётся внутри самой таблицы, полноэкранный режим не меняется.

## Границы

- SQL: 0
- migrations: 0
- document/server spreadsheet storage: 0
- содержимое XLSX не отправляется на сервер ARCTor
- правила блокировки структурных операций для формул/merge/filter/named ranges сохранены

## Acceptance

- Нажать D7: индикатор должен показать D7.
- Вставка строки выше/ниже выполняется относительно 7-й строки.
- Вставка столбца слева/справа выполняется относительно D.
- Undo/Redo сохраняет корректные координаты.
- В обычном режиме верхние кнопки XLSX видны без горизонтальной прокрутки всей страницы.
- Внутренний горизонтальный скролл таблицы сохранён.
- Полноэкранный режим не изменён.

## Точка продолжения

После production acceptance V1.2.1 продолжить развитие локального spreadsheet editor: CSV/новая пустая таблица, затем форматирование, размеры строк/столбцов, фильтры и сортировка.
