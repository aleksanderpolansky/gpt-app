PROBLEM
-------
The existing PP3 recurrence parser recognized forms such as:

каждую неделю
каждые 2 недели

but did not recognize natural Russian expressions such as:

раз в две недели
каждые две недели
раз в три недели

Therefore input such as:

Тестовая задача раз в две недели

was saved through the normal quick-capture contour but no recurrence rule
was created.

FIX
---
Extended the existing PP3 recurrence parser.

No new recurrence model was introduced.

Supported Russian interval forms now include:

раз в 2 недели
каждые 2 недели
раз в две недели
каждые две недели
раз в три недели
каждые три недели

The same construction is supported for days and months.

Russian number words 1..12 are supported.

EXPECTED SEMANTICS
------------------
раз в две недели
=> frequency_code=weekly
=> interval_count=2

каждые три недели
=> frequency_code=weekly
=> interval_count=3

раз в два дня
=> frequency_code=daily
=> interval_count=2

раз в два месяца
=> frequency_code=monthly
=> interval_count=2

MATERIALIZATION
---------------
Existing PP3B2 semantics remain unchanged.

For weekly recurrence:

interval_count=2

means a 14-day step between materialized weekly occurrences.

The existing bounded horizon remains 56 days by default.

TASK SHELF
----------
The current task shelf excludes recurrence definition/source activities before
all task bucket classification.

Current diagnostic:

recurrenceSourcesExcluded

The old repository PP3B2 validator still expects the older field:

recurrenceSourcesExcludedFromUnscheduled

That legacy static check is stale.

PP4E2C therefore used a current-state compatibility validator preserving all
other PP3B2 architecture checks.

PRODUCTION SMOKE
----------------
1. Open /projects.
2. Select an existing project.
3. Click "Добавить задачу".
4. Enter:

   Тестовая задача раз в две недели

5. Press Send.
6. Verify the existing editor opens immediately.
7. Close/save the editor.
8. Verify the project source card has recurrence interval 2 weeks.
9. Verify materialized occurrences are separated by 14 days.
10. Verify the recurrence definition/source itself is not shown as an
    executable task.
11. Verify materialized occurrences appear in Calendar.
12. Verify the source recurrence definition cannot be completed directly.

IMPORTANT UI NOTE
-----------------
The recurrence definition may still display:

Режим планирования: Без даты

inside the ordinary schedule editor.

This alone is NOT a recurrence failure.

Recurrence is a separate semantic dimension from schedule_mode_code.

The decisive production checks are:
- recurrence rule exists;
- interval_count=2;
- project card shows recurrence;
- materialized occurrences exist;
- occurrences are 14 days apart.
