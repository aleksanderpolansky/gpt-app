# ARCTor — журнал обработки сигнала куратора V2

Дата: 2026-09-03

## Решение

Техническая цепочка отдельных событий больше не является основным представлением для куратора.
Основной журнал показывает рабочие блоки в обратном хронологическом порядке — сначала последнее действие.

Текущие блоки:
1. Добавление активности.
2. Приём в работу.
3. Определение типовой активности.

Внутри каждого блока показываются человек, время, результат и комментарий. Технические коды событий сохранены и доступны в раскрываемом разделе, поэтому доказательная история не теряется.

## Назначение

Журнал должен отвечать куратору на три вопроса сразу:
- на каком этапе сейчас находится сигнал;
- кто сейчас отвечает за его обработку;
- что было сделано последним и почему.

Это представление является основой для дальнейшего делегирования между кураторами.

## Источник активности

Для текущего канала `manual_chat` + `activity_ai_lab_quick_capture:*` журнал отображает:
«ручной ввод через правую панель ИИ».
В будущем в тот же блок могут быть добавлены часы, внешний программный интерфейс и другие источники без изменения общей структуры журнала.

## Идентичность участников

Для пользовательской активности имя берётся из `app_users`.
Для новых действий куратора в журнал дополнительно сохраняется снимок имени и электронной почты на момент действия.
Для старых действий имя восстанавливается по сохранённому `curatorAppUserId`.

## Комментарии

При определении типовой активности куратор может сохранить комментарий до 1500 символов. Комментарий является частью неизменяемой записи действия и показывается в соответствующем рабочем блоке.

## Что не меняется

- исходная активность пользователя;
- ОН;
- связи;
- параметры;
- типовые активности;
- системная онтология.

На этом этапе изменяется только представление журнала и метаданные будущих действий куратора в существующем append-only журнале.

## Точка продолжения

Следующий этап после проверки V2 — реализовать явную передачу сигнала другому куратору с отдельным событием «Передано в работу», новым ответственным, причиной передачи и сохранением полной истории назначений.
