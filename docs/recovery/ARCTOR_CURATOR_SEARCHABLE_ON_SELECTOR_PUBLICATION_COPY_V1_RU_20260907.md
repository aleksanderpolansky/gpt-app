## Решения

1. Устаревшая модель «системный черновик → отдельная публикация» удаляется из интерфейса куратора. Подтверждение системного ОН куратором уже является публикацией: объект ownerless, active, global и сразу доступен всем пользователям.
2. Выбор родительского ОН переводится с обычного HTML `select` на поисковый combobox.
3. Такой же combobox используется при выборе уже существующего листового ОН, чтобы поведение выбора было единообразным.
4. Поиск работает по локализованному названию и описанию, каноническому английскому названию и описанию, а также по `canonical_key`.
5. Поиск нечувствителен к регистру и диакритике, поддерживает части слов и несколько поисковых токенов.
6. Структурные ограничения применяются до поиска: для нового листа доступны только промежуточные родители; для нового промежуточного — корни и промежуточные ОН. Поиск не обходит правила онтологии.
7. В выдаче показываются локализованное название, роль/статус, определение и, если оно отличается, английское каноническое название.

## Изменение read model API

`/api/admin/reality-curator/signals/object-bootstrap` дополнительно передает для вариантов выбора:
- `description` — локализованное определение;
- `titleEn` — каноническое английское название;
- `descriptionEn` — каноническое английское определение.

Запись ОН, RLS, БД, миграции и контракт публикации не меняются. `systemPublished=true` сохраняется.

## Проверки release-runner

До изменения исходников runner проверяет точный `main`, `HEAD`, `origin/main`, чистоту рабочего дерева, точные Git blob двух изменяемых baseline-файлов, отсутствие нового combobox в baseline, TypeScript и baseline ESLint. Затем patcher сначала выполняется на временной копии текущих production-файлов.

После изменения обязательны:
- dedicated source validator;
- TypeScript `--noEmit`;
- ESLint измененных файлов строго `0/0`;
- полный ESLint без регрессии;
- `git diff --check`;
- production build;
- отдельный code commit;
- отдельный recovery commit;
- push, fetch, проверка `origin/main` и чистого worktree.

Runner поддерживает безопасные состояния fresh / code-only resume / recovery-commit resume / already released и откат до исходного состояния до push.

## Live acceptance

На странице куратора:
1. Проверить, что текст про отдельную публикацию отсутствует и системный ОН описан как сразу доступный всем после подтверждения куратора.
2. В выборе родителя ввести часть названия, например `физич`.
3. Ввести слово из определения, например `энерг`.
4. При русской локали ввести английское `physical` и убедиться, что находится тот же ОН.
5. Выбрать найденного родителя и убедиться, что структурные ограничения сохраняются.
6. При наличии системных листьев проверить тот же поиск в «Существующий листовой ОН».

## Точка продолжения

После live acceptance продолжить построение системной онтологии для сценария подтягиваний. Следующий создаваемый ОН выбирается через новый поиск, без ручного прокручивания длинного списка.
