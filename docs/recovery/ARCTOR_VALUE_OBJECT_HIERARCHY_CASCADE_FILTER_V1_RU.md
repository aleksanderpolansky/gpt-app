# ARCTor.app — Value Object Hierarchy Cascade Filter V1

Дата: 2026-08-26
Release: `ARCTOR_VALUE_OBJECT_HIERARCHY_CASCADE_FILTER_V1`

## Исходная точка

Подтверждённый production baseline перед релизом: `main @ 8e915a0ac469c7f68a42551d279c66fa8f7c82b5`.

Каталог `/value-objects` уже имеет три представления — `Дерево / Карточки / Карта`, текстовый поиск, структурные фильтры по роли узла и сортировку. Все представления используют один объединённый набор глобальных системных и личных ЦО/ОН.

## Решение V1

Добавляется каскадный иерархический фильтр ветви ЦО/ОН.

1. По умолчанию виден только select `Корневой объект`.
2. После выбора корня появляется select его непосредственных дочерних объектов.
3. После выбора дочернего объекта следующий select появляется только если у выбранного объекта есть собственные дети.
4. Глубина каскада не ограничена фиксированными уровнями.
5. Пустое значение следующего select означает: оставить выбранным текущего родителя и показывать всё его поддерево.
6. Изменение любого более высокого уровня отбрасывает все более глубокие выборы.
7. Выбранный объект означает `этот объект + все структурные потомки`.
8. Поиск и фильтр роли (`Корни / Промежуточные / Листы / Черновики`) продолжают работать совместно с выбранной ветвью.
9. В Tree выбранный объект становится локальным верхним узлом представления. При дополнительном поиске/role filter показывается путь от совпадения только до выбранного локального корня, а не до глобального корня.
10. Cards получают тот же отфильтрованный набор из родительского компонента.
11. Map получает тот же набор через `visibleIds`.

## UX

Desktop:

- блок `Дерево / Карточки / Карта` остаётся слева;
- первый select иерархии располагается сразу справа от `Карта`;
- последующие select появляются справа по мере выбора;
- ширина одного поля компактная: 220 px, на очень широком экране 240 px;
- при нехватке ширины поля автоматически переносятся на следующую строку внутри той же панели;
- tree actions (`Развернуть все / Свернуть все`) остаются справа.

Mobile / narrow layout:

- сначала `Дерево / Карточки / Карта`;
- каскадные поля идут под переключателем;
- один столбец на смартфоне, два на промежуточной ширине.

При активной ветви появляется компактная строка полного пути `A › B › C` и действие `Сбросить`.

## Инварианты

- один structural parent сохраняется;
- никакие ЦО/ОН не создаются и не изменяются фильтром;
- фильтр является read-only presentation state;
- descendants не вычисляются через дополнительный API request;
- hierarchy filter одинаково ограничивает Tree, Cards и Map;
- изменение/удаление выбранного в пути объекта сбрасывает потенциально невалидный путь;
- существующие операции создания, удаления и reparent не получают новых write-маршрутов.
