# ARCTOR_VO_TREE_TABLE_V1

Дата: 2026-08-22
Source baseline: `16687ab28aa41224459e0dabee8d04619be41028`
DB schema change: NONE

## Контекст

После очистки старого каталога ЦО/ОН и закрытия `ARCTOR_VO_CREATE_DELETE_UX_V1` были созданы первые реальные рабочие ветви:

- `Human body → Musculoskeletal system → Back muscles → Latissimus dorsi`;
- `Activity → Physical activity → Pull-ups → Narrow-grip pull-up`.

Карточный каталог остаётся полезным для чтения описаний и визуального просмотра объекта, но плохо показывает реальную иерархию и размер ветвей. Для дальнейшего построения рабочей онтологии нужен плотный структурный режим до начала полноценного Mind Map.

## Решение

Добавить на `/value-objects` второй способ представления тех же `value_objects`: **Tree Table**. Источник истины не меняется. Новых таблиц и новых семантических сущностей нет.

Tree Table строится непосредственно по `parent_value_object_id` и показывает:

- глубину узла через визуальный отступ;
- root / intermediate / leaf;
- прямых детей;
- всех потомков ниже;
- leaf-потомков ниже;
- статус;
- прямую ссылку на карточку объекта.

Ветви можно сворачивать и разворачивать. При поиске или структурном фильтре совпавшие объекты показываются вместе с их предками, чтобы не терялась иерархия.

## Режимы

На странице доступны два режима:

1. `Tree` — основной рабочий режим для анализа структуры и количества ЦО/ОН;
2. `Cards` — прежнее карточное представление, сохранённое без удаления.

Tree является режимом по умолчанию.

## Визуальный контракт

Сохраняется корпоративный стиль ARCTor:

- primary `#3b6ef8`;
- soft blue `#eef2ff`;
- фон `#f5f6fb`;
- белые поверхности;
- мягкие границы и скругления;
- компактная типографика и метки статуса/роли.

В качестве дополнительного визуального ориентира при проектировании использован предоставленный `High-Fidelity Dashboard Design(20260822-141957).zip`; он служит референсом плотности, дерева и табличной иерархии, но не заменяет собственный дизайн ARCTor.

## Mobile

На узком экране desktop-таблица не сжимается до нечитаемого вида. Используется компактный древовидный список с теми же отступами, ролью, статусом, счётчиками и ссылкой на объект.

## Что не входит

- React Flow не добавляется;
- semantic relations не визуализируются;
- drag/reparent не добавляется;
- создание ЦО прямо в строке дерева пока не добавляется;
- схема БД не меняется.
