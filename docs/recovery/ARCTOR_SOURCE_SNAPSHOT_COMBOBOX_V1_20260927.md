# ARCTOR_SOURCE_SNAPSHOT_COMBOBOX_V1 — 2026-09-27

## Причина

После разрешения источников snapshot без системного назначения UI содержал два
раздельных элемента:

1. `Поиск состояния…`;
2. обычный select `Источник: факт-срез состояния`.

Первое поле только фильтровало второй список. Пользователю было неочевидно, что
ввод сам по себе ничего не выбирает. При росте каталога ОН обычный длинный select
также плохо масштабируется.

## Решение

Оставлен один элемент:

`Источник: факт-срез состояния`

Он является searchable combobox:
- показывает текущее выбранное состояние;
- при вводе текста фильтрует все активные системные листовые ОН ветви
  `Состояния и потребности`;
- выбор делается прямо из выпадающего результата;
- поддерживаются мышь, ArrowUp, ArrowDown, Enter и Escape;
- при изменении текста выбранный `snapshotValueObjectId` сбрасывается, чтобы
  исключить скрытое сохранение старого источника.

Формат `SourceResolution`, API, БД, runtime snapshot lookup и multiplier не меняются.

## Проверки

- новый validator searchable-combobox UI;
- существующий `validate-source-snapshot-unassigned-state-v1.mjs`;
- существующий behavioral `validate-source-from-snapshot-v1.cjs`;
- snapshot UI regression;
- ESLint;
- TypeScript;
- production build.

## Контрольный сценарий

В системной типовой активности:
`Масса -> Употребление добавленного сахара`

выбрать:
`Прямое значение -> если отсутствует, рассчитать`

В едином поле:
`Источник: факт-срез состояния`

ввести:
`сах`

и выбрать:
`Текущая масса сахара на чашку кофе`.

Отдельного поля `Поиск состояния…` больше быть не должно.
