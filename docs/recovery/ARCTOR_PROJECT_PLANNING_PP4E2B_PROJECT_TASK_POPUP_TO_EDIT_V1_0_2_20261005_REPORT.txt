USER PROBLEM
------------
On /projects, clicking "Add task" previously prepared the right AI rail.
The cursor/focus change in that narrow right column was not obvious enough
to the user.

REQUIRED UX
-----------
1. Click "Add task".
2. Open a popup over the Project page.
3. Show the current project context and an activity input.
4. Use a Send arrow analogous to the AI right rail.
5. After Send, do not require the user to:
   - notice the right rail,
   - return to Projects,
   - locate the new task,
   - open the card,
   - click Edit.
6. Immediately open the created planned activity in the existing canonical
   card, already in edit mode.

PROCESSING LOCK
---------------
This is only an alternative INPUT UI.

The processing contour is unchanged.

The popup sends to the existing endpoint:

POST /api/activity/quick-capture

with:

temporalDirection=future
projectContextId=<selected project>

Therefore the existing behavior remains responsible for:

- writing the activity to the existing activity journal;
- creating the canonical planned activity_event;
- linking it with project context;
- background basic intake analysis;
- recurrence recognition and bounded materialization where applicable.
