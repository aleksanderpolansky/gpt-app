## Решение

Подтвержденный куратором системный объект наблюдения является общей частью модели ARCTor и после подтверждения становится доступен всем пользователям для просмотра и использования.

Системный ОН:
- не имеет личного владельца;
- имеет `scope_code=global`;
- имеет `origin_type_code=system_model`;
- имеет `status=active`;
- имеет общую видимость;
- не получает признак скрытия из обычного каталога.

Личные ОН остаются доступны только своему владельцу. Пользовательский каталог объединяет активные системные ОН и личные ОН текущего пользователя, но не показывает личные ОН других пользователей.

## Что изменено

1. Создание системного ОН куратором теперь сразу формирует активный системный объект вместо скрытого черновика.
2. Новый системный объект больше не получает `system_hidden_from_observation_ui=true`.
3. Родителем нового системного объекта может быть только уже активный системный объект.
4. `/api/value-objects` возвращает активные системные ОН общего каталога вместе с личными ОН текущего пользователя.
5. В репозиторий добавлена миграция, соответствующая уже примененному изменению базы.

## Ошибка первого runner и урок

Первый runner остановился после создания code commit и до recovery commit/push: автоматически сформированный recovery-checkpoint содержал пробелы в конце строк, поэтому `git diff --cached --check` завершился ошибкой.

Rollback вернул HEAD к исходной точке, но повторное копирование byte-snapshot поверх `git reset --hard` оставило три ложных изменения окончаний строк в рабочем дереве.

Исправление V1.0.1:
- очистка разрешена только для точно известного остатка первого запуска и только если различий по смыслу нет;
- recovery-checkpoint очищается от пробелов в конце строк до staging;
- после уже созданного commit rollback использует `git reset --hard` как окончательный источник истины и не копирует поверх него snapshot tracked-файлов.
