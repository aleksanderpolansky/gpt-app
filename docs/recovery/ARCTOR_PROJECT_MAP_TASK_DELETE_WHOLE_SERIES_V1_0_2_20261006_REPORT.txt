ROOT_CAUSE=
The existing DELETE endpoint did not delete a task from project planning.
It only changed activity_events.status to cancelled.
project_activity_links remained active, so the project API continued to return
the planned activity and the card remained on the map.
A second DELETE then failed because the route accepted only
draft/planned/confirmed statuses and rejected the already-cancelled row.

PRODUCT_DELETE_CONTRACT=
This patch implements audit-preserving whole-task logical deletion:
- resolve a recurrence occurrence back to its source task;
- include source + all materialized recurrence occurrence activity_event ids;
- end active/paused recurrence rule(s);
- cancel active/rescheduled recurrence occurrence lineage rows;
- cancel active planned activity_event rows;
- cancel related calendar projections;
- deactivate project activity relations;
- deactivate all active project_activity_links for the task/series;
- preserve activity_events and recurrence lineage rows as audit/history records.

WHY_NOT_HARD_DELETE=
Hard physical deletion of activity_events could cascade into or conflict with
historical, analytics, semantic, and audit references. The user-visible task is
fully removed from project/future planning surfaces while technical lineage is
preserved.
