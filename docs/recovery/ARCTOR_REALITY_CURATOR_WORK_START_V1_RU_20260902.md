# ARCTor — рабочая проверка сигнала куратором V1 — recovery checkpoint

Дата: 02.09.2026

## Цель

После автоматического поступления сигнала в очередь куратор получает первое реальное ручное действие без использования термина «разбор», который в ARCTor уже относится к работе ИИ.

Пользовательский термин этапа: **«Взять в работу»**.
Название процесса: **«Рабочая проверка сигнала»**.

## Реализованный путь

После пяти автоматически зафиксированных событий Journey Log V1 добавляются два новых неизменяемых события:

6. `curator_work_started` — куратор взял сигнал в работу.
7. `existing_typical_activity_checked` — куратор завершил ручную проверку существующих типовых активностей текущего профиля.

Второе событие хранит результат:
- подходящая типовая активность найдена + идентификатор и снимок названия;
- подходящей типовой активности в текущем профиле не найдено.

## Правила

- старые события журнала не изменяются;
- повторное нажатие не создаёт дубликат благодаря детерминированному идентификатору события;
- проверку существующих активностей нельзя завершить до события «Взять в работу»;
- выбранная существующая типовая активность повторно проверяется сервером: она должна принадлежать пользователю и активному профилю исходного события и быть активной;
- никакие ОН, связи, параметры и типовые активности на этом этапе не создаются и не изменяются;
- запись идёт только в `activity_processing_logs` как продолжение фактически пройденного пути;
- список типовых активностей читается только из текущего профиля исходной активности.

## Интерфейс

На карточке сигнала:
1. до начала — кнопка «Взять в работу»;
2. после начала — блок «Проверка существующих типовых активностей»;
3. куратор может загрузить список активных типовых активностей текущего профиля, отфильтровать его и выбрать найденную активность;
4. либо зафиксировать «Подходящей активности нет»;
5. после успешного сохранения действие появляется в блоке «Фактически пройденный путь».

## Следующая точка

После результата `existing_typical_activity_checked` следующий этап должен определить природу проблемы:
- существующая типовая активность найдена → проверять распознавание/синонимы;
- подходящей активности нет → проверять, чего именно не хватает: типовой активности, ОН, связи, параметра или нескольких элементов.
