# ARCTor Local XLSX Editor V1.2 — строки, столбцы, Undo/Redo

Дата: 2026-08-30
Baseline: `c747c0b58d5cdb1e7f1da339c0c2a2457939d1be`

## Исходное состояние

XLSX V1/V1.1.1 принят пользователем на desktop и smartphone: файл открывается локально в обычной странице, по требованию разворачивается, ячейки редактируются, локальная копия сохраняется. Mobile reveal и keyboard fallback закрыты. Серверное хранение содержимого XLSX отсутствует.

## Цель V1.2

Добавить структурное редактирование простых XLSX-листов и единый Undo/Redo для изменений книги:

- выбор активной ячейки кликом/тапом;
- вставка строки выше/ниже;
- удаление строки;
- вставка столбца слева/справа;
- удаление столбца;
- Undo/Redo для одиночного редактирования ячейки, массовой вставки и структурных операций;
- история ограничена 40 операциями и очищается после успешного локального сохранения.

## Safety lock

V1.2 сознательно блокирует вставку/удаление строк и столбцов, если книга содержит хотя бы один из признаков, для которых безопасное обновление ссылок ещё не реализовано:

- формулы/array formulas;
- объединённые ячейки;
- autofilter;
- named ranges.

Это не ограничивает обычное редактирование разрешённых ячеек и Undo/Redo. Lock нужен, чтобы не сдвигать данные при сохранении, оставляя формульные ссылки или именованные диапазоны на старых координатах.

## Модель истории

Каждая операция сохраняет `before` и `after` snapshot только затронутого worksheet через `structuredClone`. История не использует скрытую history-модель Tabulator: `history: false` в XLSX-view делает workbook state единственным источником истины. Undo/Redo может переключить пользователя на лист, к которому относится отменяемая операция, и восстановить соответствующий worksheet.

После успешного `Save XLSX locally` история очищается и dirty-state становится false. Следующая операция снова начинает новую локальную историю.

## Структурные изменения

Для простого листа с данными операция переносит cell objects по новым адресам и синхронно сдвигает `!rows` или `!cols`. `!ref` корректируется по выбранной операции. Ячейки, их стили, комментарии и hyperlinks перемещаются вместе с cell object.

Если пользователь выбирает строку/столбец за пределами текущего used range и операция не меняет структуру книги, операция блокируется с понятным сообщением и не создаёт history entry.

## UX

Над таблицей появляется горизонтально прокручиваемая компактная панель:

- выбранная ячейка (`A1`, `B7` и т.п.);
- Undo / Redo;
- строка выше / ниже / удалить;
- столбец слева / справа / удалить.

На смартфоне панель прокручивается горизонтально и не уменьшает рабочую ширину самой таблицы. Логика обычный режим → fullscreen только по кнопке → завершить редактирование сохраняется без изменений.

## Acceptance

1. Открыть простой XLSX без формул/merge/filter/named ranges.
2. Выбрать B3; индикатор должен показать B3.
3. Вставить строку выше/ниже и убедиться, что данные сдвигаются без потери.
4. Удалить строку и восстановить через Undo; затем Redo.
5. Повторить для столбцов.
6. Изменить одну ячейку → Undo → Redo.
7. Вставить диапазон → Undo → Redo.
8. Сохранить локально, открыть сохранённую копию и сверить структуру.
9. Открыть книгу с формулой: структурные кнопки должны быть disabled с пояснением, обычное разрешённое редактирование остаётся доступным.
10. Smartphone: обычный режим и fullscreen по требованию; горизонтальная панель не ломает таблицу.
11. Network: содержимое XLSX не отправляется на сервер.
