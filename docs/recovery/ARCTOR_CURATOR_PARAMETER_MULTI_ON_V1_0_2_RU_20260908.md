## Исправление

Исправлена логика назначения объектов наблюдения параметрам типовой активности.

Раньше первое решение по измеримому объекту автоматически переводило параметр в состояние завершённого сопоставления. Теперь:

- один параметр может иметь 1..N связанных листовых объектов наблюдения;
- отдельное назначение ОН не завершает параметр;
- действие `measurable_object_mapping_continued` открывает следующий цикл назначения для того же параметра;
- действие `measurable_object_mapping_set_confirmed` отдельно подтверждает, что полный набор ОН этого параметра сформирован;
- историческое ранее назначенное ОН остаётся в наборе, но без нового события подтверждения параметр считается незавершённым;
- после подтверждения набора текущего параметра конструктор переходит к следующему параметру;
- база данных и SQL-схема не изменялись, состояние хранится в существующей `activity_processing_logs`.

## Интерфейс

После появления хотя бы одного связанного листового ОН показываются отдельные действия:

- «+ Добавить ещё ОН»;
- «Все ОН этого параметра назначены».

В списке параметров показывается количество и перечень уже назначенных листовых ОН.

## Точка продолжения

После выкладки требуется отдельное браузерное evidence сценария, которое этот release-runner физически не выполняет:

1. после первого назначенного листового ОН параметр остаётся текущим;
2. действие «+ Добавить ещё ОН» открывает ещё один цикл назначения для того же параметра;
3. несколько назначенных ОН отображаются как один набор текущего параметра;
4. только действие «Все ОН этого параметра назначены» переводит конструктор к следующему параметру.

До получения такого evidence кодовые проверки считаются завершёнными, а браузерная проверка остаётся отдельным post-release evidence, а не предположением runner.
