# M-0197 / ARI-04.07.04 — граница глобального поиска и приватных связей актора

Мастер-задача: «Запретить выдачу actor-private relations из глобального search endpoint.»

## Находка по SOURCE_INTAKE (79 файлов)
- Публичный `GET /api/feed/ontology-index` выбирал `value_objects` по `scope_code=global` и `status=active`; отдельной проверки owner-null и `origin_type_code=system_model` в запросе не было.
- Эндпоинт **не обращался** к `value_object_relations` и не возвращал отношения напрямую. Подтверждённая утечка приватных связей в предоставленном снимке **не обнаружена**.
- `POST /api/value-objects/indexed-lookup` требует Auth0 и активного актора, по намерению показывает свои и общие ОН, а не публичный глобальный каталог. Сама SQL RPC `arctor_on_indexed_lookup_v1` в текущем пакете **не предоставлена**, поэтому её реальная RLS-защита не доказана.
- `GET /api/value-objects/[id]/graph-neighbors` флагом отключён по умолчанию и разводит системную/акторную таблицы; отрицательные runtime RLS-тесты не выполнялись.

## Исправление M-0197
1. В *публичном* каталоге запрашиваются только активные объекты `scope=global`, `origin=system_model` и `owner_user_id IS NULL`, `owner_actor_id IS NULL`.
2. Поверх фильтров SQL выполняется fail-closed проверка каждой возвращённой строки. При некорректном источнике целиком отдаётся 503, без частичного вывода.
3. Публичный API принимает только параметр `locale`, запрещая actor/scope/relation параметры и дублирующийся locale.
4. `parentId` выводится только если родитель входит в фактическую публичную выдачу, чтобы не раскрывать идентификаторы невидимых объектов.
5. Ответ содержит только id/title/parentId/role/facet. Никакие relation rows, owner ids или metadata_json не сериализуются.

## Принципиальные ограничения
- Это точечная локальная защита публичного маршрута. Не утверждается, что приватные данные сейчас утекали.
- Запрет может исключить ранее выдававшиеся несистемные глобальные ОН. Требуется функциональный обзор до деплоя.
- Приёмка CODE означает принятие локального кода, **не** runtime-подтверждение Auth0/RLS/Supabase и **не** проверку всех глобальных endpoint'ов.
- В рамках SEC-06 `OPEN_BLOCKER` релиз остаётся `BLOCKED`, динамические отрицательные тесты — `NOT_EXECUTED`. Нет SQL, API-вызовов, Git commit/push и деплоя.
- Отдельные будущие проверки: RPC indexed-lookup, source/target scope in system relation table, runtime negative cross-actor, production performance.
