# M-0190 / ARI-04.06.04 — symmetric reverse duplicate guard

Статус: CODE candidate / LOCAL MODULE ONLY. **Не** API integration, Supabase write, миграция, проверка реальной схемы или автоматическая приёмка.

Точная задача мастер-плана: «Для симметричных связей исключить обратный дубль A↔B.»

## Контракт

- Повторно используется принятый канонизатор M-0188 `detectCanonicalRelationDuplicatesV1`. Симметричность задаётся только записью зарегистрированного relation type; по имени связи не угадывается.
- Для обратных пар A→B и B→A *одного канонического симметричного типа* с совпадающими контекстом, утверждением и границами действия возвращается `SYMMETRIC_REVERSE_DUPLICATE` / BLOCK. Для прямых ориентированных связей — `NOT_APPLICABLE`.
- Сравнение времени следует включительным границам M-0189 (`valid_to >= valid_from`); точные одинаковые интервалы допускают BLOCK, явно непересекающиеся временные записи не дублируются, частично неизвестные и перекрывающиеся с различными границами идут на REVIEW. Требуются RFC3339 instants с UTC offset.
- Исторические `rejected` / `inactive` записи остаются историей, дают REVIEW, но не доказывают отсутствие отношения.
- Разные или неполные контексты и несовместимые знаки утверждения/эффекта не считаются идентичными доказанными фактами; REVIEW.
- Некорректный или неполный реестр типов, ошибочные даты, дубли ID дают fail-closed BLOCK, без попытки утверждать связь.
- Никаких `DB/API/network/Git/ledger` записей, повышения статуса или подтверждения истинности источника. Функция чистая и детерминированная.

## Ограничения

M-0190 обрабатывает только дубликат **обратной** симметричной пары. Дубликаты той же ориентации, alias normalization и прочие виды должны по-прежнему проверяться M-0188. M-0187 выполняет семантические проверки, M-0189 — временны́е границы. Эти модули не объединяются в production API на данном микрошаге.

После успешного локального применения M-0190 остаётся `CODE/PENDING`. Для принятия нужен отдельный acceptance gate и квитанция `docs/recovery/ARI_MASTER/04/0190_EVIDENCE.md`. Следующий шаг M-0191 не начинается.

Безопасность: `SEC-06 OPEN_BLOCKER`, dynamic negative runtime `NOT_EXECUTED`, release `BLOCKED`.
