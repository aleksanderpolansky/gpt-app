**Сайт:** `arctor.app` (Vercel production; факт успешного деплоя конкретного коммита требует отдельной проверки)
**Программа:** ARCTor Reality Intelligence, ARI-00—ARI-11, 615 микрошагов
**Последний принятый шаг:** `M-0061` (принято 59 из 615, 2 шага имеют ранее оформленный статус WAIVED)
**СЛЕДУЮЩИЙ:** `M-0062` — различать совпадение по пути/предку и релевантность самого ОН. Ни M-0062, ни M-0097—M-0110 пока не приняты.

## Что уже подтверждено

- Эталонный рабочий Gold Corpus: 156 сценариев; сохранено 69 ранее выполненных оценок. Не все 156 сценариев имеют оценку; независимые метрики требуют проверки полноты и утечек.
- M-0058: 7 семантически пересекающихся сценариев исключены из независимого расчёта метрик, но сохранены в Gold.
- M-0059: 63 области проверки (7 языков × 3 ветви × 3 роли).
- M-0060: 42 области имеют необрезанные перечисления кандидатов, 21 область ветви «Системы и структуры» остаётся неполной. `Recall@20 = N/A`.
- M-0061: документированы существующие ОН за пределами top-20. Полнота всей онтологии не доказана.

## Индексированный поиск: статус

В этом коммите добавлены **только** три отдельных файла экспериментального, opt-in поиска:

1. `src/app/api/value-objects/indexed-lookup/route.ts` — API-роут, возвращающий 404, пока `ARCTOR_ON_INDEXED_LOOKUP_V1` не равно `enabled`.
2. `src/lib/ontology-research/indexedLookupContractV1.ts` — контракт ввода/пагинации.
3. `scripts/tests/arctor-indexed-lookup-contract.test.mjs` — автономные тесты контракта.

**Не выполнено:** SQL-модернизация; установка `pg_trgm`; создание `arctor_on_indexed_lookup_v1` в Supabase; включение флага; интеграция в существующий интерфейс; проверка изоляции двух пользователей; нагрузочные испытания на миллионах ОН. До выполнения этих пунктов новый поиск не может считаться работающим или безопасным. Старый поиск сохранён без изменений.

Read-only SQL-анализ Supabase: 803 строки `value_objects`, 739 активных явно публичных системных ОН, 1 системный ОН с противоречивой приватностью, 49 активных приватных пользовательских ОН; `pg_trgm` и RPC отсутствуют. **Не исполнять старую SQL V1.** Исправленная V2 миграция — проект для дальнейшего ревью, а не текущая миграция.

## Обязательные инварианты

- Существующая трёхветвевая онтология ОН, UUID, структурные/семантические отношения, типовые активности, факты и пользовательские миры НЕ заменяются и не пересоздаются.
- Должен существовать поиск по **всему разрешённому каталогу**, без скрытого ограничения первыми 5 000 объектов; число отображаемых результатов — отдельная настройка.
- Поиск конкретных магазинов должен проверять идентичность (адрес, признаки, связи) и дубли; это не готово только от индекса названия.
- Приватные ОН не должны становиться видимыми по совпадениям чужого поискового запроса.
- Неполный каталог / обрезанная выдача не доказывают отсутствие ОН и не дают право автоматически создавать дубликат.
- Не изменять счётчик 615 микрошагов при внеплановом техническом исправлении. ARI-03 предусматривает контракт M-0097—M-0103, лексический поиск и пагинацию M-0104—M-0110, последующие локализации, гибридный поиск и испытания.

## Для продолжения в новом диалоге

1. Прочитать этот файл из **актуального `main` GitHub**, сверить текущий `HEAD` и актуальный production deployment.
2. Для детальных доказательств использовать локальный, **не публикуемый** `docs/recovery/ARI_MASTER` и последнюю квитанцию `M0061_OWNER_ACCEPTANCE_RECEIPT` / checkpoint. Этот файл содержит только публичное резюме, не заменяет полный приватный ledger.
3. Продолжить строго с **M-0062** после проверки текущего локального ledger. На каждом этапе различать `STAGED`, `ACCEPTED`, `DEPLOYED` и `LIVE_VERIFIED`.
4. Не добавлять SQL, автопубликацию новых объектов или включение experimental-search без отдельного gate с проверкой RLS/двух пользователей.
