# M-0095 — отсутствующие переводы: NULL только при доказанной идентичности

**Статус:** `ACCEPTED_READONLY_NULL_POLICY_LIMITED`. Это утверждение политики классификации, **не** материализация NULL в Supabase и **не** доказательство пробелов перевода каждого ОН.

В M-0094 подтверждены 791 активный ОН, 738 локализованных записей с названием типа value_object, но привязка `entity_key` к конкретному UUID ОН **не проверена**. Следовательно, нельзя вычислять число отсутствующих переводов по формуле `791 - rows(locale)`.

Правило: если для конкретных ОН + поля + языка + scope **проверена** идентичность и проверен полный набор записей, отсутствие соответствующего перевода материализуется как JSON/SQL `null` (`MISSING_VERIFIED_NULL`). Если привязка, область, источник, статус или версия не подтверждены, состояние `UNVERIFIED_*` либо `EXISTING_UNVERIFIED`, а не ложный NULL и не утверждённый перевод. Для состояния UNVERIFIED поле значения вообще отсутствует; JSON/SQL NULL разрешён только для MISSING_VERIFIED_NULL.

Никаких fallback-переводов по умолчанию, автоматического допущения английского, машинного утверждения, новых текстов, изменений БД и включения индексированного поиска.
