# M-0113 / ARI-03.04.03 — отличие алиаса одного ОН от broader/narrower разных ОН

## Цель по мастер-плану
«Различить алиас одного ОН и broader/narrower отношения между разными ОН». Утверждённые алиасы на семи языках сохраняют общий UUID, если их идентичность уже подтверждена куратором. Семантическая связь между ДВУМЯ РАЗНЫМИ UUID не создаёт алиас или перевод и не меняет структурного родителя.

## Изменения
- Дополняется только существующий `src/lib/ontology-research/localeAliasIndexV1.ts`.
- Добавляется независимый **чистый** реестр `buildBroaderNarrowerIndexV1`: у каждой связи явно указаны UUID более общего и более частного ОН; статус проверки, рецензент, версия и SHA-256 evidence.
- Только verified записи предоставляются для lookup; candidate/rejected учитываются как пропущенные.
- Для отсутствующей связи `absenceProven=false`. `aliasEquivalenceEstablished=false` всегда. Никакого автоматического выбора UUID.
- `between`, `broaderOf`, `narrowerOf` работают ТОЛЬКО по предварительно авторизованным входным данным. Нет транзитивности, обратного утверждения, синтаксического перевода или работы с БД.
- Коллизия названий по-прежнему показывает нескольких кандидатов без автоматического объединения.

## Испытания
63 новых автоматических теста + 289 обязательных регрессионных тестов M-0104—M-0112; TypeScript strict. Инсталлятор проверяет все предыдущие версии по хешам, чистоту tracked Git, приватный ledger/checkpoint, повторный запуск; при провале предикатов возвращает диагностический ZIP.

## Ограничение
Это НЕ научно верифицированная база отношений, НЕ онлайн-поиск, НЕ подключение к API и НЕ установление фактических родительских связей в онтологии Supabase. Синтетические UUID тестов не являются реальными ОН. Никаких SQL, платных AI вызовов, commit/push/deploy.
