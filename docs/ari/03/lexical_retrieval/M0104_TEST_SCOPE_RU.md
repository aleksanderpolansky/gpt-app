# ARCTor ARI-03.03.01 / M-0104 — реальные регрессионные тесты существующего поиска

## Цель
Впервые после серии DESIGN-шагов создать файл тестов непосредственно в рабочем репозитории `gpt-app` и реально выполнить его против существующих модулей `contextSearchV2.ts` и `ari02EnhancedSearch.ts` на закреплённом Git HEAD.

## Что принимаем
- Файл `scripts/tests/ari03-m0104-lexical-baseline.test.cjs` существует в реальном рабочем дереве и **не является только содержимым ZIP**.
- Действующие исходные TypeScript-модули проверены через Git blob SHA и загружены штатным локальным компилятором TypeScript.
- `node --test scripts/tests/ari03-m0104-lexical-baseline.test.cjs` выполняет 13 тестов: 13 PASS, 0 FAIL, 0 SKIP.
- Полное название «Ночной сон» получает больший вес, чем частичное; path-only ниже прямого; одинаковые оценки детерминированы; разные UUID и роли остаются разными объектами; лимит выдачи не скрывает число совпадений.
- Протокол прогона, SHA файлов, квитанция и резервная копия журнала сохранены в приватном `docs/recovery/ARI_MASTER`.

## Ограничения
Тесты подтверждают поведение двух **старых** модулей, а не реализацию будущего `lexicalRetrievalV1.ts`. Часть будущего контракта ещё не реализована: строгая нормализация `ё/е` из M-0100, отдельная реализация UUID-lookup, полномасштабные verified aliases, безопасный индекс, E2E и реальная изоляция по владельцам.

M-0105 является **первым микрошагом реализации нового взвешенного lexical retrieval**, M-0110 — подключение к маршруту приложения с выключенным feature flag. На M-0104 не изменяем production-модуль, Supabase, API, env, feature flags, Git-историю, Vercel.

## При неудаче
Ошибки тестов или дрейф исходного SHA блокируют приёмку. Новый тестовый файл, если был скопирован, удаляется; приватный журнал не меняется. Никаких `git reset`, `git clean`, `git push` или сброса базы.

### Совместимость с действующей инфраструктурой

Используется существующий каталог `scripts/tests/` (а не отдельная структура тестов). Проверяются текущие модули, без создания нового API, маршрута или страницы. Результат `13 PASS` — только регрессия существующего исходного кода, не интеграция поискового индекса и не проверка точного UUID в реальной БД.

Диагностика V3: корректность Node TAP-формата и сохранение полного вывода при провале. Никакого изменения требований и числа тестов.
