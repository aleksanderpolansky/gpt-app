# M-0107 / ARI-03.03.04 — проверяемый приоритет собственного названия

**Оригинал микрошагa из неизменного плана:** «Запретить определению и пути перебивать прямое полное совпадение названия».

## Граница изменений

- Развивается **только** существующий файл `src/lib/ontology-research/lexicalRetrievalV1.ts`.
- Добавляется **один** тест в действующий каталог `scripts/tests`.
- Вспомогательные отчёты — в существующий `docs/ari/03/lexical_retrieval/`; приватные доказательства — в `docs/recovery/ARI_MASTER`.
- Нет новых страниц, маршрутов API, RPC, таблиц, миграций, индексации, коммитов, push или deploy.

## Приоритеты (фиксированные эвристические веса, не вероятности)

| evidence | weight | meaning |
|---|---:|---|
| exact title | 1000 | Полное собственное название объекта |
| verified exact alias | 850 | Только подтверждённый существующий алиас, подготовленный доверенным сервером |
| phrase prefix title | 650 | Название начинается с полного выражения |
| partial title | 340 | Совпадение по словам названия |
| description | 70 | Слабый контекст, не идентичность |
| definition | 60 | Слабый контекст, не идентичность |
| path | 20 | Слабый текст, не подтверждённое родство |

Входное поле `definitions` — **опциональный** доверенный текст, а не заявление о том, что этот текст уже правильно привязан к UUID в Supabase. Этап M-0094 не подтвердил привязку. Выдача никогда не устанавливает `confirmed=true`, не выбирает автоматически UUID и не делает выводов об отсутствующих ОН.
