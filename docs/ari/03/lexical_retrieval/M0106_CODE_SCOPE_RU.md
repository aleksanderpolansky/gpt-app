# M-0106 / ARI-03.03.03 — приоритет только подтверждённых алиасов

Задача в исходном плане: «Добавить alias приоритет только для verified aliases, не для гипотез ИИ». Это **CODE** в уже существующем `src/lib/ontology-research/lexicalRetrievalV1.ts` и тесты в существующей `scripts/tests`. Никаких новых страниц, API, таблиц, маршрутов или индексированных поисков.

## Изменения

- Сохраняем прежнее API функции `retrieveWeightedLexicalV1` и контракт ответа M-0105. Объект кандидата может содержать *необязательные* записи `aliases`.
- Вес прямого собственного названия `exact_title=1000`; точного **подтверждённого** алиаса `verified_exact_alias=850`; совпадения полного выражения в начале названия `650`; остальные уровни прежние (`340 / 70 / 20`).
- Алиас учитывается только если его язык равен языку запроса, статус `published`, источник `concept_aliases`, `curatorVerified=true`, `targetResolved=true`, `targetId` равен UUID переданного доступного кандидата и **весь** текст совпадает после строгой нормализации NFC. Несовпадающие/неопубликованные/неподтверждённые алиасы не дают совпадения. Структурные/семантические гипотезы ИИ НЕ являются алиасами.
- Алиасы не используются для автоматической фиксации тождественности, перевода, создания ОН, авторизации либо объявления отсутствия ОН. UUID с одинаковым названием остаются отдельными.
- Вся проверка источника, публикации, фактического существования целевого UUID и ACL остаётся на доверенном серверном вызывающем коде. **`curatorVerified:true` в пользовательском JSON не является доказательством!** Пока этот серверный источник не подключён, функция не должна получать клиентские псевдоподтверждения.
- Из M-0091 известны 89 алиасов с отсутствующими целевыми ОН. Пока связи не исправлены и не перепроверены в БД, **все 89 исключены** из точного поиска. Код не утверждает, что они исправлены.
- M-0107 и следующие микрошаги не выполняются досрочно; M-0110 — отдельное подключение к существующему API под feature flag.
