# ARCTor ARI-03.06.02 / M-0126 — Reciprocal Rank Fusion (CODE)

## Буквальное требование реестра

«Для первого варианта объединять ранги через RRF, не складывать несовместимые raw scores».

## Реализация

Расширен уже принятый модуль `src/lib/ontology-research/hybridRankerV1.ts` без изменения поведения экспортированной функции M-0125 `mergeHybridCandidatesByUuidV1`.

Новый экспорт `rankHybridCandidatesRrfV1(input)` сначала применяет ту же проверенную дедупликацию по UUID, проверку рангов, языков и коллизий scope. Затем для каждого уникального ОН рассчитывает **RRF(k=60)** по лучшему рангу из каждого источника:

`RRF(ON) = [lexicalRank != null ? 1/(60 + lexicalRank) : 0] + [vectorRank != null ? 1/(60 + vectorRank) : 0]`.

Ранг в отдельном источнике 1-based, не исходный score. Повторный UUID в одном источнике учитывается ровно один раз, по наименьшему значению ранга. Значения `rawScore` не читаются, не суммируются и не попадают в ответ. При равенстве RRF результатов применяется детерминированный порядок: меньший lexicalRank, меньший vectorRank, затем UUID по возрастанию (отсутствующий ранг — последний).

Метка `exactBoostApplied=false` принципиально остаётся: приоритет точного совпадения целого запроса и подтверждённого алиаса относится к M-0127. Трассировка причин/полей срабатывания относится к M-0128. Данные до вызова RRF **должны пройти RLS/authorization у вызывающей стороны** — этот математический модуль не обращается в БД и не выполняет проверку авторизации.

## Приёмка и ограничения

- Новые самостоятельные тесты: 105; полная регрессия M-0104—M-0125: 1205; всего 1310 PASS.
- Строгая компиляция TypeScript обязательна. Проверяются формула RRF, двухисточниковость, детерминизм, изоляция scope, сохранение старого контракта M-0125, отказ по ошибочному входу, отсутствие двойного счёта дублей.
- Нет SQL, доступа к OpenAI, оплаты, `git commit/push/deploy`, подключения нового ранжирования к production API.
- Изменение исходного `hybridRankerV1.ts` защищено SHA-256 и резервной копией; программа не перезапишет неожиданный локальный код. Журнал обновляется только после всех тестов и подтверждения владельца.
