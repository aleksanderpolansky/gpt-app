# ARCTor ARI-03.06.03 / M-0127 — post-boost полного запроса и проверенного алиаса (CODE)

## Дословная задача из мастер-реестра

«Ввести post-boost прямого совпадения с entire query и verified alias.»

## Алгоритм

Расширяется уже проверенный модуль `src/lib/ontology-research/hybridRankerV1.ts` **без изменения предыдущего кода** и экспортов `mergeHybridCandidatesByUuidV1` (M-0125) и `rankHybridCandidatesRrfV1` (M-0126). Добавляется `rankHybridCandidatesWithExactPriorityV1`.

Механизм принимает объединённые lexical/vector кандидаты, исходный текст и язык полного запроса, а также **доказательства совпадений из доверенного каталога**. Для сравнения используется Unicode NFKC, Unicode-пробелы и locale casefold; **вся** строка должна совпадать полностью. Подстрока, похожие слова, транслитерация, модельный вывод и непроверенные синонимы НЕ создают приоритет.

После RRF присваивается отдельная категория (не суммируя несовместимые raw scores): `2` — точное имя объекта, `1` — утверждённый *active verified* алиас, `0` — остальные кандидаты. Порядок: категория по убыванию, затем строго прежний порядок RRF (включая deterministic tie-break). При одинаковом UUID результат единственный.

`aliasStatus=pending/revoked` не даёт повышения. Неправильные evidence, неизвестные UUID и противоречивые области доступа приводят к отказу, а не частичному результату. При `enableExactPriority=false` сохранён исходный порядок RRF, чтобы можно было откатить новую логику без отката старого кода.

Внешняя сторона обязана проверять RLS и достоверность записей каталога, прежде чем подавать доказательства совпадения: математический ранжировщик не может сам доказать, что алиас действительно был утверждён в базе.

Трассировка *всех* оснований и полей совпадений относится к M-0128; здесь предоставляются лишь категория и вид найденного совпадения для тестирования порядка.
