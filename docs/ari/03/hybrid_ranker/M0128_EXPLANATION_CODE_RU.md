# ARCTor · M-0128 / ARI-03.06.04 — Объяснимость гибридной выдачи

**Точное требование MASTER:** «Собрать объяснение: lexical/vector/exact/alias, версия и поля срабатывания.» Режим: `CODE`.

## Реализация

Файл `src/lib/ontology-research/hybridRankerV1.ts`, новая чистая функция `explainHybridCandidatesV1`.

Она вызывает принятую в M-0127 функцию `rankHybridCandidatesWithExactPriorityV1`; ранги и значения RRF не изменяются. Для каждого UUID формируется объяснение:

- `reasons`: `lexical_rank`, `vector_rank`, `canonical_title_exact` и/или `verified_alias_exact` — строго по реально сработавшим источникам и приоритету;
- `catalogVersion`: явно предоставленная версия записи каталога ОН;
- `lexical`: позиция, вклад RRF, версия лексического индекса, `matchedFields` — **только поля, сообщённые лексическим адаптером**;
- `vector`: позиция, вклад RRF, версия индекса, версия embedding, модель, `embeddedFields` — **состав входного текста для embedding, а не утверждение о причинном влиянии каждого поля на сходство**;
- `exact`: вид `canonical_title` либо `verified_alias`, язык, версия поля, идентификатор подтверждённого алиаса (если применимо);
- `finalRank`, `rrfRank`, `rrfScore`, `rrfK` и фактическая политика ранжирования.

## Границы доказательств

Источники `lexical`, `vector`, доказательства совпадений `evidence` и информация о версиях передаются адаптером/каталогом **после его авторизации**. Функция не подключается к БД и не утверждает, что выполняет RLS. Если адаптер не знает, в каком именно лексическом поле сработало совпадение, он должен передать `unspecified`, а не выдуманное имя поля. Версии отсутствующих/неизвестных объектов не подставляются автоматически.

Fail-closed на неизвестный UUID, дубль provenance, конфликт scope/owner, недостаток записей, несовпадение источников, отсутствующую или неправильно оформленную версию поля, несоответствие title/alias фактическому результату M-0127. Алиасы со статусом `pending`/`revoked` не получают объяснение повышенного приоритета. Режим `enableExactPriority=false` сохраняет ранжирование M-0126; в этом режиме boost не заявляется.

Вся реализация M-0125/0126/0127 сохранена **побайтно как префикс** нового исходного файла. Никакие rawScore не смешиваются. Код без SQL, платных вызовов, сетевого доступа и самостоятельного подключения к live API.

## Пример семантики вывода

Для ОН, найденного обоими источниками и совпавшего по точному названию, объяснение покажет одновременно позиции lexical/vector, два RRF-вклада, `canonical_title_exact`, версии и поле названия. Для ОН, найденного только по вектору, будет только `vector_rank` и поля, входившие в embedding. Формирование таких полей не означает установление онтологической причинно-следственной связи.
