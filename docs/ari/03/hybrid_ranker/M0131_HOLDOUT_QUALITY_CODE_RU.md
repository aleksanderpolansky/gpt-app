# M-0131 / ARI-03.06.07 — Сопоставление качества гибридного ранжирования с ARI-02

**Точное задание:** «Сравнить nDCG, exact Hit@1 и false positives с ARI-02 на holdout».

## Реализация

- В `src/lib/ontology-research/hybridRankerV1.ts` добавлен чистый оценщик `scoreHybridHoldoutV1` с измерением `nDCG@5`, `Hit@1`, `exact Hit@1`, ошибочно найденных объектов на первом месте, пропусков, охвата и доли false positives в первой пятёрке.
- Настоящий базовый алгоритм запускается из `src/lib/ontology-research/ari02EnhancedSearch.ts`, а гибридный — из `rankHybridCandidatesStableTiesV1` (M-0130). Старые алгоритмы не переписываются.
- Для гибрида используются ранее сохранённые **два настоящих ответа OpenAI API** (M-0121) из локальной папки Downloads. Повторных API-запросов нет. Действительность кеша проверяется по model ID, числу/размерности векторов, SHA256 текстов и повторному вычислению метрик M-0121.
- Все три варианта используют одинаковые 18 ON и 36 одобренных владельцем запросов. Для ARI-02 в адаптере также передаются 17 замороженных русскоязычных **проектных** названий из исходного M-0121, но они не объявляются верифицированными именами действующего каталога.
- Ученые ограничения: Gold отобран и утверждён владельцем (не независимая выборка), 18 точных sanity-запросов, по одному запросу на шесть не-русских языков, ограниченная модель роли ON, нет проверки RLS или production API. Эти границы фиксируются в отчёте, а не скрываются.

## Особенность false positives

`FP@1` — доля запросов с **неправильным возвращённым** первым объектом. Пустой ответ считается пропуском, но не false positive; отдельный `missAt1` фиксирует оба случая. `fpShareOfReturnedTop5` — доля нерелевантных объектов среди **фактически возвращённых** пяти первых результатов; при разном числе результатов значение следует интерпретировать с учётом coverage. `exact Hit@1` оценивается только на 18 точных запросах.

## Приёмка

Микрошаг оценивает и сравнивает, а не гарантирует улучшение. Если гибрид уступает базовому по отдельным метрикам, это записывается как дефект/сигнал для последующей проверки, не скрывается. Критерий принятия — подлинные локальные векторы, фактический ARI-02, проверенные Gold/метрики, отсутствие дубликатов UUID, исполнение полных регрессий и положительная приёмка владельцем.
