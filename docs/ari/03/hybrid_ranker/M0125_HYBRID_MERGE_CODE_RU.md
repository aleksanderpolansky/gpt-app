# M-0125 / ARI-03.06.01 — объединение lexical/vector кандидатов по UUID

**Оригинальный мастер-план, CODE:** «Реализовать кандидатный merge lexical/vector по UUID с дедупликацией». Модуль устанавливается в `src/lib/ontology-research/hybridRankerV1.ts`, тесты — `scripts/tests/ari03-m0125-uuid-candidate-merge.test.cjs`.

## Контракт и поведение

- Принимает два списка кандидатов lexical и vector, каждый содержит UUID объекта наблюдения, локальный ранг, язык (`en/pl/es/de/cs/uk/ru`) и область (`global_system` либо `owner_private` с UUID владельца).
- Приводит UUID к нижнему регистру, объединяет кандидатов по UUID, оставляет **ровно одну запись на ОН**, даже если UUID встречается несколько раз в одном источнике и в обоих.
- Хранит лучшие **отдельные** ранги в lexical и vector; фиксирует наличие в источниках, число повторов и набор языков. Сырые значения score специально **не** суммируются и не сравниваются.
- Отвергает повреждённые записи, неподдерживаемые языки и коллизию областей доступа для одного UUID, не возвращая частичного результата.
- Обход кандидатов **временный**: сначала lexical по локальным рангам, затем только vector; UUID — стабильный tie-break. Этот порядок **не** является готовым гибридным релевантностным ранжированием. Механизм RRF предусмотрен M-0126; повышение приоритета точного совпадения — M-0127.
- Слияние не создаёт новые embeddings, не обращается к БД/API и не применяет проверку RLS. Доступы должны быть проверены до передачи кандидатов в функцию на соответствующем интеграционном этапе. Результат всегда помечается `authorizationEnforced:false`.
- Пустые списки допустимы, что не блокирует lexical-only fallback. Неверный источник обрабатывается как ошибка; вызывающая сторона принимает решение о fallback.
