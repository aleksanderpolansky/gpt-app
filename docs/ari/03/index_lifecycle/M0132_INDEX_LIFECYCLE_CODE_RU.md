# M-0132 / ARI-03.07.01 — жизненный цикл поискового индекса (CODE)

## Требование мастер-плана
«Ввести index_generation, source_hash и status fresh/stale/building/failed.»
Режим `CODE`; реализация: `src/lib/ontology-research/indexLifecycleV1.ts`. Следующие задачи M-0133—M-0138 не выполняются досрочно.

## Разработано

1. `calculateIndexSourceHashV1(source)` рассчитывает воспроизводимый SHA-256 по каноническому набору единиц ОН, сортированному по UUID+локали. Включает идентификатор модели, её версию, preprocessing-version, область видимости и владельца. Повторение одной пары UUID/локали отклоняется. Это **отпечаток источника**, а не гарантия подлинности данных или независимой экспертной проверки.
2. `createIndexLifecycleV1(indexId, source)` создаёт запись со статусом `stale`, `index_generation=0`, отсутствующим опубликованным поколением.
3. `transitionIndexLifecycleV1(record, event)` — чистый автомат состояний. `BUILD_STARTED` увеличивает номер поколения и переводит `stale`/`failed` в `building`; точное завершение `BUILD_SUCCEEDED` переводит в `fresh`; `BUILD_FAILED` — в `failed`; `SOURCE_CHANGED` — в `stale` и инвалидирует незавершённую сборку. Запоздавший callback старого поколения отклоняется.
4. `validateIndexLifecycleV1` проверяет внутренние инварианты состояний: `fresh` возможен только при совпадении поколений и отпечатка; `failed` не стирает опубликованную историю; источники разных пользователей не образуют одинаковый отпечаток при разных владельцах.
5. `describeIndexLifecycleV1(record)` выводит административную диагностику со статусом, поколением и причиной fallback; `vector_path_eligible=true` **не** означает разрешённый пользовательский доступ и **не** является подтверждением существования SQL-индекса.

## Обязательная последовательность

`stale(0) -> building(1) -> fresh(1) -> stale(1) -> building(2) -> failed(2) -> building(3) -> fresh(3)`.

Источник сохраняется в `source_hash`, опубликованное состояние — в `published_generation` и `published_source_hash`. Даже после неудачного обновления предыдущее опубликованное поколение остаётся в метаданных; **публикация или чтение устаревших векторов автоматически не разрешается**.

## Границы текущего шага

Никаких миграций, `pgvector`, изменений Supabase, операций с БД, вызовов OpenAI, автоматического биллинга, изменения прав доступа или деплоя. Код не строит индекс и не подменяет real E2E; диагностика пока локальная, её реальные источники будут подключаться позже согласно плану.

Дальнейшие предусмотренные задачи: M-0133 dry-run rebuilding; M-0134 ACL; M-0135 replay pending updates; M-0136 timeout/circuit-breaker/lexical fallback; M-0137 GRANT/RLS; M-0138 latency.

89 новых TAP-тестов, все предыдущие 1891 регрессионных теста, TypeScript strict, демонстрационный JSON с восемью изменениями состояния, приватная квитанция и ledger SHA-256. Журнал изменяется только при полном успехе и явном подтверждении владельца.
