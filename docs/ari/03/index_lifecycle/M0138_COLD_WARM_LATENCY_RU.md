# M-0138 / ARI-03.07.07 — p50/p95 холодного и прогретого каталога

## Цель по утверждённому плану

«Замерить p50/p95 end-to-end на cold/warm catalog и зафиксировать результаты» (CODE).

## Фактически измеряемый тракт

Офлайн-обработка каждого из 36 подтверждённых запросов через настоящий исходный модуль ARI-02 `ari02EnhancedSearch.ts`, косинусный поиск по настоящим ранее сохранённым векторам M-0121 и реальную текущую версию `hybridRankerV1.ts` (с RRF и приоритетами). 18 глобальных ОН, обе модели `text-embedding-3-small` / `text-embedding-3-large`. Прежде чем измерять, ответы проверяются на совпадение с принятым отчётом M-0131.

- **Cold**: для каждого запроса заново считываем локальные исходные данные и векторы, загружаем/транспилируем модули и выполняем поиск. Это *холодный каталог на уровне приложения*, но **не гарантированно холодный OS disk cache** и не новый Node-процесс.
- **Warm**: уже загруженные источники и векторы повторно используются; после одного прогрева выполняется пять проходов по 36 запросов.
- p50 и p95 вычисляются как наблюдаемые процентили по правилу ближайшего ранга, без сглаживания и без придуманного времени.
- Для каждой модели: 36 cold-наблюдений и 180 warm-наблюдений. Выводятся count, min, mean, p50, p95, max в миллисекундах.

## Границы вывода

Отчёт **не измеряет** HTTP/браузер, Supabase/postgres/pgvector, сеть, реальный RLS и весь каталог. Это локальный end-to-end вычислительный тракт существующих модулей, не production E2E. OS кэш файлов нельзя принудительно сбросить, результаты зависят от CPU, нагрузки и JIT. Не выводить универсальные production SLA из этого пилота.

## Безопасность и эксплуатация

- Используются только локальные подтверждённые данные и прежде сохранённые векторы; модели OpenAI не вызываются, счёт не пополняется.
- API-ключ не считывается, SQL не выполняется, никакие данные в Supabase не изменяются.
- В доказательства сохраняются только агрегированные метрики, контракт и техническая среда, без векторов, секретов и текстов запросов.
- При ошибке файл исходного модуля и приватные записи журнала возвращаются из исходного состояния; диагностика формируется автоматически.
- Ручной ввод фразы подтверждения для локального CODE-шага не требуется, согласно решению владельца.
