# M-0137 / ARI-03.07.06 — проверка новых таблиц `public`: GRANT + RLS

**Формулировка мастер-плана:** «Проверить отсутствие новой таблицы в public без явных GRANT и RLS policies». Режим: CODE.

Добавлена чистая программная проверка `auditPublicTableMigrationsV1()` в `indexLifecycleV1.ts`. Модуль не исполняет SQL, не обращается к Supabase, не меняет таблицы и не выдаёт отчёт о БД за доказанный live-аудит. Пакет рассматривает локальные SQL-миграции `supabase/migrations` с датой имени файла **от 2026-10-30 включительно** и отклоняет новые `CREATE TABLE public.*` без явного SQL `GRANT` в той же миграции, `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` и `CREATE POLICY`. Непонятный синтаксис, динамический DDL и неразмеченные имена миграций блокируются до ручной проверки.

Вторая функция `evaluatePublicCatalogAclV1()` проверяет **переданные ей** строки системного каталога PostgreSQL. Для их получения подготовлен исключительно читающий SQL `M0137_PUBLIC_CATALOG_READ_ONLY.sql`. Автоматический доступ к БД не настраивается, ключи и пароли не нужны.

Проверяются отсутствие RLS, клиентский SELECT без политик, отсутствие SELECT у `service_role`. Важные ограничения: текущее состояние прав не доказывает, что `GRANT` был записан именно в миграции; системный каталог не сообщает дату создания таблицы; наличие политики не доказывает её логическую корректность. `service_role` имеет `BYPASSRLS`, поэтому его нельзя использовать как тест обычного пользователя.

**Никаких изменений Supabase, GRANT/REVOKE, CREATE TABLE или запуска миграций.** Подтверждение M-0137 означает принятие программного gate и офлайн-аудита доступных локальных миграций, но не подтверждение E2E реальной БД. Следующий шаг — M-0138, замеры p50/p95, как в исходном плане.
