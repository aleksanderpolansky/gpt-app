# ARI-03 / M-0097 — QueryRequest v1: неизменный контракт входа

**Статус:** `DESIGN_ONLY`, не production-интеграция. Разработанный контракт должен позже быть реализован в `src/lib/ontology-research/semanticSearchContractV1.ts`; этот пакет ничего в `src/` не изменяет.

## Шесть полей

| Поле | Контракт | Безопасность/семантика |
|---|---|---|
| `text` | строка 1–512 Unicode code points после trim; непустая | не заменять пользовательское выражение отдельным словом; нормализация определяется отдельно M-0100 |
| `locale` | `en`, `pl`, `es`, `de`, `cs`, `uk`, `ru`, `und` | `und` — явно неизвестный язык; без подстановки английского |
| `actorScope` | `global_only` или `global_and_own` | только запрос на область; server-side claims и проверка RLS определяют фактический доступ |
| `intent` | `identify`, `suggest`, `explore` | цель запроса, не match_class и не явное получение UUID |
| `limit` | целое 1–20 | без строкового приведения, дробей и неограниченных результатов |
| `filters` | объект; только `rootObjectId`, `parentObjectId`, `objectKindCodes`, `nodeRoleCodes` | это сужения, а не доказательство существования или права доступа |

**`filters`:** UUID-поля, если указаны, имеют канонический синтаксис UUID. Коды видов/ролей в нижнем регистре и ограничены по длине и числу элементов; сервер дополнительно проверяет их по фактическим реестрам. Все дополнительные поля запрещены, включая присланные `actorId`, `ownerActorId`, `userId`, `tenantId`, `privacy_override`, `match_class`, `score`, `includePrivate`.

## Разграничение доверия

1. `actorScope=global_only` никогда не расширяется сервером до частных записей; приватные и неоднозначные строки исключены.
2. `actorScope=global_and_own` требует серверно подтверждённого actor. Клиент не вправе передать чужой UUID владельца или scope в фильтрах. Анонимный запрос отклоняется либо сужается до `global_only` **явным** решением API, но не используется для доступа к private.
3. Нельзя трактовать `scope_code=global` как достаточную публикацию: объект должен иметь однозначный публичный статус и подходить под дополнительные правила; 739 кандидатов M0093 не утверждены для индекса.
4. Сервисные RPC/API с service_role обязаны реализовать независимую проверку tenant-predicate; наличие RLS без E2E не считается доказательством безопасности.
5. Неизвестные язык, статус поля, идентичность переводов, границы приватности, provenance и несовпадение контрольных снимков приводят к отказу/исключению, а не к неявному fallback.

## Отдельные контракты следующих микрошагов

- `M-0098`: SearchResult с UUID, match_class, path, score и provenance/version; неоднозначность => candidates + вопрос, без автоматического утверждения ОН.
- `M-0099`: строго отдельный `exact UUID lookup` и `suggest-by-text` режим. UUID, случайно введённый в `text`, не включает сам собой прямое чтение по идентификатору.
- `M-0100`: Unicode/ё-е/диакритика и омонимы; этот шаг **не** решает нормализацию.
- Методы `exact`, `alias`, `partial`, `lexical`, `vector`, `graph` — это источники сопоставления, не значения `intent`; их score нельзя смешивать без контракта ранжирования.

## Источники и доказательства

`M-0096` подтвердил 803 ОН (791 active), 89 aliases, 822 версий определений и 738 строк локализации. `catalog_snapshot_hash` и вычисленный `translation_version` фиксируют содержимое БД, но не гарантию происхождения/корректности. 89 alias targets остаются неподтверждёнными; две группы коммерческих корней требуют проверки; E2E приватности и качество индексированного поиска не подтверждены. Никакие права на индексацию не выдаются.

**Приёмка M-0097** означает проверку законченности и непротиворечивости дизайна полей, встроенные негативные тесты и сохранение документа; не означает наличие кода обработки запросов в работающем приложении.
