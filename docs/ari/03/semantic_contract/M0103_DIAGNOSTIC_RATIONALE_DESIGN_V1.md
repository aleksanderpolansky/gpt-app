# ARCTor M-0103 — диагностический ответ: unresolved tokens и rationale (DESIGN ONLY)

**План:** ARI-03.02.07, последний проектный микрошаг перед M-0104 CODE. **Состояние до:** M-0102 принят, 100/615; `catalog_snapshot_hash` и `translation_version` из M-0096 закреплены. Эта поставка не изменяет `src/`, Supabase, API или индексацию.

## Цель и границы

1. У `suggest_by_text` диагностический блок объясняет, **какие проверяемые фрагменты пользовательского текста не получили доказанного лексического соответствия**, по каким проверенным источникам попали кандидаты и достаточно ли полон обход. В `exact_uuid_lookup` текстовая диагностика запрещена.
2. `unresolvedTokens[]` — массив фрагментов исходного запроса с `text`, `startUtf16`, `endUtf16`, `reason`. Смещения считаются по UTF-16 (семантика JavaScript `.slice`), не по байтам UTF-8 и не по code-point; парность с текстом проверяется. Не возвращать дубли, перекрытия, токены вне запроса или утверждения об отсутствии объекта, основанные лишь на неполном Top-K.
3. `NO_VERIFIED_DIRECT_MATCH`, `NO_VERIFIED_ALIAS`, `NO_VERIFIED_LOCALE_TEXT` означают только отсутствие **доказанного совпадения в полностью проверенной области запроса**, не отсутствие ОН в базе вообще. Если обход ограничен, используется `NOT_EVALUATED_LIMIT`, `diagnosticsStatus=partial` и никакого утверждения о полноте поиска. Ошибка токенизации — `UNSUPPORTED_TOKENIZATION` и `partial`/`unavailable`, не ложный `no_match`.
4. `candidateRationales[]` только для ранее **авторизованных, активных, верифицированных кандидатов**, каждый со своим UUID, классом совпадения, проверенным source и кратким безопасным объяснением. Пять классов: строгий title, проверенный полный alias, verified partial title, lexical title и verified structural ancestor. Последний **не** становится direct/exact и имеет глубину 1–3.
5. Не раскрывать в reason/токенах посторонние приватные ОН, скрытые пути, внутренние таблицы, имена владельцев, сервисные ключи или диагностические SQL-подробности. `safeExplanation` ограничен предопределёнными публичными формулировками. Сырой пользовательский запрос не записывать в приватные/публичные отчёты установки.
6. При `outcome=blocked` диагностические массивы пустые, `diagnosticsStatus=unavailable`; публичный ответ не позволяет отличить запрещённый от отсутствующего UUID. Для `no_match` массив кандидатов пуст. Для `candidate/ambiguous` кандидат(ы) только с `selectionState=UNCONFIRMED`; неоднозначность требует ответа с вопросом по M0098, не автоматически выбранного UUID.
7. Score из классов exact, alias, partial, lexical, vector, graph не пересчитывается в одну вероятность. `rationale` сообщает конкретное проверяемое основание, а не придуманные AI выводы «почему это именно этот объект».
8. Нельзя считать отсутствие одного конкретного языкового текста `NULL` без identity join и доказанного negative read по M0095; неизвестная привязка — `UNVERIFIED`. В этом шаге никаких переводов не генерируется и не утверждается.
9. `catalogSnapshotHash` и `translationVersion` закреплены значениями M0096. При несоответствии снапшота диагностика должна быть отвергнута или помечена недостоверной; механизм проверки целостности будет внедрён на CODE-стадии.

## Примеры (синтетика, НЕ снимок реальной БД)

- `продолжительность сна xyz`: если первые два слова поддержаны доказательством, а `xyz` не найден в полном проверенном наборе — `unresolvedTokens=[{text:"xyz",startUtf16:22,endUtf16:25,reason:"NO_VERIFIED_DIRECT_MATCH"}]` (конкретные смещения сверяются валидатором и должны соответствовать строке).
- `сон`: несколько верифицированных разных UUID → два `candidateRationales`, `outcome=ambiguous`; нельзя скрывать второй и автоматически выбирать первый.
- `ходьба в гору`: если проверен предок «ходьба», `reasonCode=VERIFIED_STRUCTURAL_ANCESTOR`, `matchClass=ancestor_expansion`, а не `exact`.
- Достигнут `maxEdges` или `maxCandidates` → `diagnosticsStatus=partial`; незакрытые фрагменты не трактуются как доказанное отсутствие.
- Нет доступа к приватному ОН → `blocked/unavailable`, пустые диагностические массивы, без подтверждения его существования.
