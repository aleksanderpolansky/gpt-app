# ARCTor M-0102 — контролируемое расширение по предкам ОН (DESIGN ONLY)

**Дорожная карта:** ARI-03.02.06, 102-й микрошаг из 615. Цель — сделать родительские структурные связи отдельным проверяемым источником кандидатов в текстовом поиске. Это НЕ SQL-миграция, не новый поиск API и не разрешение включить индекс.

## Границы источника

1. Расширение применяется только в режиме `suggest_by_text` (M0099). `exact_uuid_lookup` не расширяет путь и не проводит текстовый поиск.
2. Сначала извлекаются и фильтруются прямые кандидаты по M0097—M0101: авторизация, статус, проверенная локаль, происхождение текста, снимок M0096. Расширение запускается только от этих **разрешённых seed-ОН**, но не от сырого текста или неподтверждённых алиасов.
3. Переход разрешён только по **проверенной структурной** связи `STRUCTURAL_PARENT` от child к parent, соответствующей текущему снимку каталога. Отношения `ASSOCIATED_WITH`, `RELATED_TO`, `PART_OF`, `CAUSES`, коммерческие связи и графовые подсказки **не становятся** структурными родителями.
4. До раскрытия или возврата каждого предка обязательна проверка server-side ownership/RLS, статуса, видимости, актуальной версии и локали. Отказ на любом шаге прекращает ветвь. У клиента не должно быть признака, что недоступный private parent существует; не возвращать такой UUID, имя или счётчик.
5. Многородительская онтология допустима: для одного ОН сохраняются несколько проверенных путей. Нет обязанности создавать фиктивного единственного родителя или переподчинять ОН. Циклы/самоссылки прекращают ветвь и не рождают новых кандидатов.
6. Жёсткие ограничения: `maxDepth` 1–3, `maxEdges` 1–64, `maxCandidates` 1–20, `maxPathsPerAncestor` 1–4. Превышение даёт аккуратное усечение доступных результатов, не утверждение полноты графа.
7. Дедупликация по UUID предка, с сохранением нескольких верифицированных путей. Блокировать попытки повышения глубокой/частичной связи до `strict_title_full_phrase` или `strict_alias_full_phrase`; класс всегда `ancestor_expansion`.
8. Сначала прямой поиск (полное название, полный проверенный алиас, токен/лексика, soft), затем отдельный ancestor-источник с указанием `depth`, `seedObjectId`, `verifiedPath`, `source=fk_or_verified_hierarchy`, `catalog_snapshot_hash`. У оценок предка отдельная семантика, не калиброванная вероятность. При одновременных прямых и предковых совпадениях результат может требовать уточнения.
9. Никакая ветвь не создаёт/не подтверждает ОН, не исправляет алиасы и не делает перевод `NULL` автоматически. Исключение двух системных корней коммерческого каталога по `canonical_key` остаётся допустимым, потенциальные дубли этих корней — на отдельный аудит.

## Примеры

- `Продолжительность сна` → точный листовой ОН выше; `Сон` как проверенный предок может появиться как `ancestor_expansion`, **не** как direct match.
- `Игра на гитаре` → `Игра на музыкальном инструменте` или иной родитель только если данное отношение реально подтверждено. Нельзя придумывать родительскую ветвь по языковой похожести.
- Многородительский ОН → несколько разрешённых путей, общий родитель один раз в списке кандидатов.
- Цикл A→B→A → обход завершается, повторного A-кандидата нет.
- Недоступный или чужой приватный предок → ветвь обрывается без разглашения его существования.

## Доказательства и ограничения

Проверка этого шага — автономные синтетические тесты контрактов, а не выполнение E2E. Реальное дерево Supabase, RLS и API на этой стадии не проверяются. Отпечатки каталога и переводов из M0096 остаются неизменными. `indexableApproved=0`, поиск OFF. Открыты: 89 alias→ON без целей, две группы возможных дублей коммерческих корней, реальная изоляция actor-private, связь локализаций с конкретным ON, достоверность поискового качества.
