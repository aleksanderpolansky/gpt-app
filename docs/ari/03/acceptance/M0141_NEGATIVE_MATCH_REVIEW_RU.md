# ARCTor · M-0141 / ARI-03.08.03 — отрицательные совпадения (REVIEW)

**Master:** «Пройти “ребёнок”, “человек”, “магазины”, “гитара”, “ходьба” на отрицательные совпадения.»

**Режим:** ограниченный офлайн REVIEW без изменения production ранжирования. Источник — утверждённый владельцем набор из 18 реальных ОН M-0121/M-0140 и существующий `hybridRankerV1.ts` с точными совпадениями.

## Правила проверки

1. `ходьба` имеет подтверждённый Gold UUID `97e3009b-7c77-5540-8cec-09339fbcdd72`. Точное совпадение не заменяется «Длительность ходьбы», «Количество шагов», «Подъём по лестнице».
2. `человек` — НЕ идентичная эталонная формулировка `Человеческий организм`; избегаем автоматического точного сопоставления без контекста. `Человеческий организм` проверяется как положительный контрпример.
3. `ребёнок`, `магазины`, `гитара` не имеют owner-approved exact label в Gold-18. Тест не утверждает, что соответствующих ОН нет в полном каталоге; не придумываем UUID.
4. Не повышаем ранжирование от неподтверждённых/отозванных алиасов, ложной локали или совпадения только по части запроса. Контролируем порядок и отсутствие дублирования UUID.
5. Проверяем отсутствие несанкционированного расширения графа. Просматриваем результат отдельно от слоя реального решения: ранкер выдаёт порядок кандидатов, но не умеет самостоятельно решать, когда спрашивать уточнение.

## Критерии ограниченной приёмки

- 5/5 тематических отрицательных проверок, 1 подтверждённый точный якорь «Ходьба», 4 явно неутверждённых exact-мишени.
- Исходный Gold цел, не создаются системные ОН, не подменяется scope, не производится запись в Supabase.
- 2698 предыдущих регрессий + 80 новых тестов = 2778 PASS (требуется фактическое выполнение на ПК владельца).
- Не заявлять, что проверены все блокирующие категории production или все 740 ОН. Для этого требуются отдельные Gold, полнота поиска, HTTP/UI E2E и RLS.

Отсутствие результатов в ограниченном эталоне **не является доказательством отсутствия ОН**. Проверка не завершает ARI-03 production E2E, предусмотренный в M-0146.

Не производятся SQL, OpenAI/платные вызовы, commit/push/deploy. Приёмка сохраняет лишь REVIEW-результат в приватном ledger `docs/recovery/ARI_MASTER`.
