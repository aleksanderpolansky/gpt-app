# ARCTor M-0140 / ARI-03.08.02 — «Продолжительность сна»: эпизод и фазы

## Точное требование мастер-плана

> Пройти «продолжительность сна» с различением целого эпизода и фаз.

Режим **REVIEW**. По реестру целевой административный интерфейс: `/admin/ontology-research/diagnostics`; испытание живого интерфейса не имитируется.

## Основание контрольных запросов

Используется ранее явно утверждённый владельцем набор 18 глобальных ОН и RU exact-запросов (M-0121). Существующие UUID и тексты не изменяются:

| Смысл | Русский контрольный запрос | UUID |
|---|---|---|
| Целый ночной эпизод | Продолжительность ночного сна | `84d2f41f-4068-518a-b9d9-047b0d0e0762` |
| REM-фаза | Продолжительность REM-сна | `a620cf08-9cdb-5c7a-b428-721f356e2d8e` |
| Глубокий сон | Продолжительность глубокого сна | `45d472b0-88fe-5642-b7d0-cbe2502c4ca9` |
| Лёгкий сон | Продолжительность лёгкого сна | `607c0db7-d29d-5b5f-89a4-8317bb37fc62` |

В исходном Gold **нет** утверждённого точного запроса «Продолжительность сна» без уточнения. Для него обзор фиксирует неоднозначность и не привязывает автоматически один UUID. Это правило обзорного сценария, а не внедрённый в действующий API механизм диалога.

## Проверка действующего алгоритма

Используется принятой версией `hybridRankerV1.ts` функция `rankHybridCandidatesStableTiesV1`. Для каждого из четырёх запросов вводятся 18 кандидатов из обеих ветвей, нужный UUID преднамеренно помещён последним. Затем проверяется, что подтверждённое точное название поднимает его на позицию № 1, остальные три измерения не подменяют целевое понятие, не срабатывают неподтверждённые алиасы и подстроки, порядок устойчив к перестановке остальных кандидатов.

Различение содержимого: продолжительность **целого эпизода** не тождественна продолжительности его отдельных фаз. Система не должна автоматически приравнивать один показатель к другому. **Не утверждается**, что сумма фаз должна в точности совпадать с продолжительностью эпизода: контракты источников и методов измерения различаются.

## Границы приёмки

Это локальная REVIEW-проверка ранжирования по ранее утверждённым русским формулировкам и реальным UUID. Она не доказывает наличие всех локализаций в живой базе, работу Admin Diagnostics/HTTP E2E, RLS или правильность медицинских измерений. Кандидаты ранжированы в контролируемом тестовом наборе, а не получены через живой search API.

Нет SQL, OpenAI API, генерации embeddings, новых обязательных подтверждений, commit/push/deploy. При установке повторно исполняются 2618 предыдущих тестов и 80 новых; всего 2698.
