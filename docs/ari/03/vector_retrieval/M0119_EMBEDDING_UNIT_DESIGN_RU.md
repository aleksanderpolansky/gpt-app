# M-0119 / ARI-03.05.02 — проект единицы embedding

**Режим MASTER:** DESIGN. Формулировка исходного плана: «Сформировать единицу embedding: title+definition+approved aliases per ON/locale/version». Этот шаг не применяет миграцию Supabase, не устанавливает `pgvector`, не генерирует векторы и не вызывает OpenAI API.

## Структура

Проверяемый проектный модуль: `src/lib/ontology-research/vectorRetrievalV1.ts`.

- Ключ единицы: `(ON UUID, locale, ontologyVersion, dictionaryVersion, scope)`; scopes `global_system` и `owner_private` (со строгим ownerActorId).
- Содержимое: **утверждённое** название + **утверждённое** определение + только подтверждённые алиасы того же ОН, языка и версии словаря.
- Источники: идентификаторы источников названия/определения/утверждённых алиасов; сортировка и сериализация детерминированы. Значимая диакритика не удаляется.
- Блокирующие обстоятельства: отсутствующее/неодобренное название или определение, несовпадение UUID, неподтверждённые источники, чужая/неправильная версия, недопустимые управляющие символы, переполнение лимитов.
- Алиасы со статусом `pending`, `rejected`, `revoked` исключаются; межъязыковые алиасы не проникают в единицу другого языка. Дубликаты без изменения смысла сворачиваются **только по точному Unicode NFC**, не по общей «похожести».
- Политика пользовательских данных: функция принимает уже авторизованные и правильно отфильтрованные данные; **не доказывает наличие RLS**. Вызывающая серверная сторона обязана проверять разрешение и принадлежность каждого источника. Тестовые UUID синтетические.
- Семантические *broader/narrower*, структурные родственные, географические и причинные связи не являются алиасами. Их автоматическое включение запрещено.
- Пустое определение блокирует единицу; не выдумывать текст и не подменять его связанными ОН. Отсутствие подготовленной единицы не означает отсутствие ОН.
