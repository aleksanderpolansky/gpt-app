# M-0124 / ARI-03.05.07 — Экономика batch/query embeddings и запрет auto billable flow

## Формулировка реестра

«Подготовить отчёт затрат на batch embeddings и query embeddings; запретить auto billable flow».

**Режим DESIGN.** Существующий код векторного поиска и кеширования не переписывается. Реальный вызов провайдера, SQL, подключение к сайту, выбор production-модели и Git push не выполняются этим шагом.

## Источники данных

- M-0121, реальная квитанция OpenAI: 896 входных токенов на модель, всего 54 текста (18 ОН + 36 запросов), 2 модели, фактические векторы были получены только в M-0121. Нет достоверного раздельного учёта токенов для названий ОН и запросов.
- M-0123: принятый пилот exact/ANN на локальных векторах; статус 121/615.
- Снимок тарифов 03.11.2026: `text-embedding-3-small` $0.02/1M входных токенов, `text-embedding-3-large` $0.13/1M входных токенов; **настоящий Batch API** — коэффициент 0,5. Это НЕ скидка для массивов `input[]` в обычном `/v1/embeddings`.
- Тарифы и eligibility могут меняться; перед реальной отправкой запросов обязательна повторная верификация.

Официальные источники: https://developers.openai.com/api/docs/models/text-embedding-3-small ; https://developers.openai.com/api/docs/models/text-embedding-3-large ; https://developers.openai.com/api/docs/guides/batch

## Формула

`billable_inputs = ceil(inputs * (100 - cache_hit_percent)/100)`

`estimated_usd = billable_inputs * assumed_tokens_per_input * standard_rate_per_1M / 1,000,000 * (batch_api ? 0.5 : 1)`

Значения для `assumed_tokens_per_input`: 17 / 64 / 256, это сценарии **не замер**. Из 896 токенов M-0121 известен только общий расход на смешанный набор; арифметическое 896/54≈16,59 не следует считать нормой на все ОН. Для планирования нужны консервативные более длинные сценарии.

## Путь информации и запрет автоматических затрат

1. Получить ОН и утверждённые описания через модуль M-0119; вычислить ключ содержимого в M-0122.
2. При `REUSE_READY` использовать кеш: цена нового embedding = $0.
3. При отсутствии вектора для query или изменённого ОН рассчитать предложение в M-0124, сохранив стоимость, модель, тариф, количество токенов, scope/владельца и версию; **это не право отправить запрос**.
4. До отдельной ручной санкции с максимальной суммой, временем жизни, idempotency key, моделью, перечнем версий и централизованным счётчиком расхода -> `LEXICAL_ONLY`.
5. Никогда автоматически не создавать Batch API задания по таймеру, при чтении, при поиске или по фону индексации.
6. После последующего разрешения нужны фактические usage, лимит расходов, повторная проверка тарифов, отработка таймаута и запрет повторной оплаты за тот же контент. Этот шаг ещё не вводит этот исполняемый контур.

## Что реализовано здесь

- Чистый расчётный модуль `scripts/benchmarks/ari03-m0124-embedding-economics.cjs`, 3 сценария объёма × 3 длины × 2 модели.
- Проектный TypeScript модуль `src/lib/ontology-research/embeddingSpendPolicyV1.ts`, все решения о расходах возвращают `callAllowed:false`, `automaticBillingAllowed:false` и `LEXICAL_ONLY`.
- Репродуцируемые входные данные M-0121/M-0123, формулы, автоматические тесты, отчёт в JSON.

## Граница приёмки

Проектируемой экономике и явному fail-closed правилу соответствует. **Это не доказательство, что все другие, уже существующие пути вызова OpenAI на сайте защищены этим новым модулем.** Подключение и общая интеграция предусмотрены последующими шагами.

Ни API-ключ, ни SQL, ни перезапуск paid endpoints в M-0124 не нужны.
