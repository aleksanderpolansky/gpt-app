# ARCTor — ADR-ADM5B4-001: контроль качества и экономичности контекста

Дата: 2026-10-17. Версия: 2026-10-17.v1. Статус: **proposed**. agentEnabled=false. Запуск ИИ запрещён.

## Назначение

ADM-5B.4 расширяет независимую административную диагностику ADM-5B.1–5B.3. Библиотека ADM-4K1 хранит эту инструкцию для чтения человеком; она не утверждается автоматически и не добавляется к задачам `commercial_fact_preflight`, чтобы регистрация документа сама по себе не изменяла ранее согласованный контрольный снимок.

## Четыре разных SHA-256

1. `manifestDigest` (ADM-5B.2) — SHA-256 канонического JSON с идентификаторами дела, поручения, списком включённых и исключённых документов, причинами блокировок, источниками и хешами секций. Изменение перечня **исключённых** документов меняет этот хеш, даже если три включённых текста остались прежними.
2. `includedTextDigest` (ADM-5B.4) — SHA-256 списка упорядоченных включённых секций: ordinal, sourceType, reference, sha256 точного текста, длина. Помогает понять, менялось ли содержимое реально включённого контекста.
3. `policyMetadataDigest` (ADM-5B.4) — SHA-256 выбора/исключений документов, проверки источника и блокирующих причин. Показатель для диагностики, а не механизм утверждения.
4. `snapshotDigest` (ADM-5B.3) — SHA-256 точного `frozenJson` сохранённого снимка, включающего полный манифест и исходные тексты. Сравнивать его напрямую с B2-дайджестом **нельзя**.

Результат `metadata_or_exclusions` означает только: включённые тексты идентичны, а общий хеш B2 различается. Причина может быть не только в документах, но и в других полях манифеста; её нужно проверять по версиям. Если старый B2-манифест не сохранён, конкретную причину исторической смены 8cb…→510… доказать невозможно.

## Сохранённый снимок

Проверяются SHA-256 сериализованного снимка, вложенный `manifest.digestSha256` и SHA-256 каждой вложенной секции. При повреждении JSON или несогласованности полей результат только `invalid`/`unknown`; нельзя повышать статус до подтверждённого. Сравнение проводится только по фактически доступной текущей записи и последнему снимку для того же дела/поручения/типа задачи.

## Минимально достаточный контекст

`case`, `assignment` и публичный первоисточник для текущего коммерческого сценария — обязательны и не удаляются автоматически. Утверждённые инструкции имеют особые версии и могут предлагаться к сокращению только отдельным человеческим решением и повторным манифестом. Урезание по порогу без проверки не допускается. `proposed` документы исключены. Рекомендации на странице **не меняют** отбор.

## Лимиты и стоимость

Лимит 8000 символов ADM-5B.1 и 32000 байт сериализованного снимка ADM-5B.3 — два независимых предохранителя. Диапазон токенов `ceil(chars/5) … ceil(chars/2)` — только эвристика, не реальный токенизатор и не данные биллинга. Таблица планового расчёта принимает вручную тарифы в USD за 1 млн входных/выходных токенов, ожидаемый вывод и накладные токены. Без введённых тарифов цена считается неизвестной. Не учитывать коэффициенты кеширования, инструменты и валюту кошелька означает, что это **не** фактическая стоимость.

## Защитные границы

Страница доступна только `owner/admin` после серверной проверки. Данные читаются через доверенный серверный Supabase client; пользователь не получает service key. Нет POST/PUT/PATCH/DELETE, вызовов OpenAI, записи в Supabase, запуска ИИ, выдачи прав, утверждения инструкций, изменения ADM-4 или автоматического сокращения.

Три блокировки `NO_APPROVED_INSTRUCTIONS`, `OUTBOUND_POLICY_NOT_APPROVED`, `RUNTIME_NOT_IMPLEMENTED` не снимаются внутренним `reviewed_internal`. Дополнительная проверка безопасности и конкурирующих операций остаётся в ADM-5E.

## План приёмки

1. Запустить локальный патч с проверкой источников и полным откатом в случае ошибки.
2. Проверить 1 действующее дело ADM-000001 и поручение engineering / commercial_fact_preflight. Убедиться, что показываются 3 секции и 1233 символа при неизменных источниках.
3. Убедиться, что в БД один снимок с событием `captured`, одно `reviewed_internal` — без новых записей после открытия B4.
4. Проверить отличающиеся хеши и возможность подтвердить целостность сохранённого полного JSON. Для оценки прошлой смены B2-хеша использовать только имеющиеся доказательства.
5. Ввести вручную примерный тариф и сверить расчет с арифметикой; это не списание и не тариф OpenAI.
6. Проверить отказ неавторизованному пользователю, сохранение блокировок и отсутствие сетевых вызовов моделей.
7. Зафиксировать нерешённые вопросы: точный токенизатор для модели, официальный тариф и правила бюджета, а также обновление метаданных/библиотеки до релиза.
