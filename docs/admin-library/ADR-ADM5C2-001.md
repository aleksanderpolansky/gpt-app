# ARCTor — ADR-ADM5C2-001: реестр кандидатов и бюджет административных ИИ-поручений

Дата: 2026-10-17. Версия: 2026-10-17.v1. Статус: **proposed**. Применение агентами: **запрещено**.

## Назначение

ADM-5C.2 вначале только читает один существующий кейс и поручение ADM-4 и считает **плановый** диапазон затрат. Не создаёт новых дел, не записывает факты, не выбирает модель для реального запуска, не осуществляет резерв средств и не передаёт никакие данные внешнему ИИ.

## Фактически используемые источники

- `arctor_admin_cases_adm2_v1`, `arctor_admin_assignments_adm2_v1`, действующая роль — через readAdminContextPreviewV1 / ADM-5C.1.
- ADM-5B.3: последняя версия неизменяемого снимка и журнал принятия внутреннего решения.
- ADM-5B.4: проверка целостности и приблизительная оценка токенов; расчёт **не по токенизатору модели**.
- `lib/ai/platformModelCatalog.ts`: список *кандидатов*, не матрица допусков к задаче. Каталог версии 2026-09-30; после 2026-10-07 требует ревалидации.
- `src/lib/ai-billing/runtime.ts`: только существующий `readActiveModelPriceSnapshot`, читающий `ai_model_price_snapshots`; берёт активную запись по модели/уровню и действующей дате, проверяет валюту, курс и множитель. Вызовы gateway/reserve/debit запрещены.
- Wallet, лимиты предприятия, разрешённый плательщик **не** читаются, т.к. административный бюджет не равен средствам личного кошелька пользователя.

## Плановый расчёт

`input_low / input_high` из ADM-5B.4, системная обвязка вводится вручную, вывод — вручную, safetyFactor от 1 до 3, maxAttempts от 1 до 20. Расчёт использует тарифы активного снимка. Кэшированных токенов предполагается **ноль**. Для валюты USD применяется снимковый FX USD→EUR и markup. `guardedAttempt=ceil_6(high*safetyFactor)`, `guardedCase=ceil_6(guardedAttempt*maxAttempts)`.

Проектные лимиты на попытку/кейс вводятся вручную и существуют только на странице в браузере. Положительное арифметическое сравнение лимитов **не** означает наличия денег, права потребления или прохождения бюджетного допуска. Никакого локального или серверного сохранения введённых лимитов.

## Непреодолимые сейчас запреты

- Каталог моделей не доказан как действующий; DB-тариф не подтверждает API доступность модели.
- Не существует отдельного утверждённого соответствия `roleCode+taskCode → allowedModelId`.
- Не существует контракта владельца/плательщика административного бюджета и защищённого реестра лимитов ADM-5C.
- Не реализован валидированный исходящий перечень полей и политика получателя.
- ADM-5C.1 ещё сообщает блокировки по инструкциям, outbound и runtime.
- Человеческий `reviewed_internal` подтверждает только состав снимка, не право отправки/расхода.
- Общий `agent_execution_enabled` **не включать**: прежний контракт ADM-4 может затронуть назначение людям.

## Что создадут дальнейшие этапы

ADM-5C.3: отдельная запись *намерения попытки* с владельцем расхода, объёмом, контрактом модели и снимка, идемпотентностью, неизменяемым журналом. ADM-5C.4: реальный серверный шлюз с атомарным бюджетным резервированием через существующую систему AI Billing и fail-closed. ADM-5C.5: структурированный отчёт (источники, выполненное, ошибки, предлагаемые изменения), который не вносит правки автоматически. ADM-5C.6: человек утверждает отчёт и отдельно выдаёт разрешение на конкретное действие. ADM-5C.7: тесты двойных запросов, смены цены, конкуренции, недостатка средств, старых снимков, запрета приватных активностей, полного аудита.

## Приёмка ADM-5C.2

Owner/admin-only, Node server GET only, отсутствуют новые SQL и POST, модель определяется из имеющегося каталога без внешних API, отсутствующая/невалидная цена блокирует quote, никакой подстановки фальшивых тарифов. Проверить USD→EUR и EUR, нижнюю/верхнюю оценку, запас безопасности и число попыток, пустые/превышенные бюджеты, отсутствие перехода к EXECUTION_ALLOWED при любой комбинации. Сообщение о свежести каталога обязательно. Ввести контрольный пример без реального расходования средств. Документ не включать в агентный контекст до отдельного утверждения.
