# ARCTor — ADR-ADM-DIAG-001: объяснение незавершённой работы

Дата: 16.10.2026. Статус: архитектурное решение для плановой реализации. Никаких изменений БД, фактов, ОН, исходных активностей или существующих дел сейчас не требуется.

## Правило

Каждый незавершённый шаг должен указывать: **что требовалось**, **что реально выполнялось**, **что проверено и с каким охватом**, **почему остановились (доказанный факт / вероятная причина / неизвестно)**, **что осталось** и **какие следующие действия доступны с учётом полномочий**.

Запрещено считать равнозначными «результат не найден», «поиск не запускался», «проверена только часть кандидатов», «кандидат найден, но не утверждён», «операция запрещена» и «проверка завершилась ошибкой».

## Состояния и сообщения

| Подтверждённая ситуация | Сообщение администратору | Возможное действие |
|---|---|---|
| Поиск не выполнялся | «Подбор листового ОН ещё не запускался» | Запустить разрешённый поиск или выбрать вручную |
| Ожидается решение человека | «Варианты доступны, ожидается выбор куратора» | Посмотреть кандидатов и подтвердить |
| Не определена промежуточная ветвь | «Путь поиска не установлен; полный просмотр листьев не выполнялся» | Уточнить ветвь/контекст |
| Поиск был ограниченным | «Проверена часть ветви; полнота поиска не подтверждена» | Уточнить критерий или расширить охват |
| Полная проверка без точного текстового совпадения | «В проверенных листьях не найдено точного названия или утверждённого синонима в исходном тексте» | Проверить синонимы и семантическое соответствие, выбрать вручную |
| Найдено несколько | «Найдены несколько возможных листовых ОН» | Сравнить и утвердить один |
| Предложен неподтверждённый ОН | «Кандидат найден, но его выбор не подтверждён» | Подтвердить/отклонить |
| Запрет/нет права | «Операция не выполнялась из-за ограничения доступа/настройки» | Запросить разрешение, использовать разрешённый маршрут |
| Техническая ошибка | «Проверка прервана: [человеческое описание]» | Повторить или передать техруководителю |

Причина должна иметь класс достоверности: `confirmed`, `probable`, `unknown`. Не превращать предположения в факты.

## Уточнение по текущему P2.5 (исходники ветви GitHub, проверены 16.10.2026)

`src/lib/activity/parameterizedLeafCandidatesP25.server.ts` реализует проверку, а **не полноценный ИИ-поиск**: сужает иерархию промежуточных ОН, затем ищет точные названия листьев и утверждённые синонимы в тексте. Если нет однозначной промежуточной ветви и дерево велико, полный обход листьев может вообще не выполняться; для небольшой ветви есть ограниченный запасной обход. Даже результат `P25_NO_EXACT_LEAF_OR_APPROVED_ALIAS_IN_TEXT` не означает, что в модели нет подходящего листового ОН — лишь что алгоритм не нашёл точного текстового совпадения в проверенном охвате.

Проверка соответствия этой версии локальным неопубликованным изменениям — при следующем проектном интейке.

## Пример `87ee8565`

Из исходного текста извлечено измерение `price: 12 usd`. В профиле фигурирует `money_value → Food products` без подготовленного значения, а также два параметра `count`, подготовленные из настроек профиля. Следовательно, верное сообщение: «Цена распознана, но для связи `money_value` значение пока не подготовлено; причина сопоставления требует исследования», а не «цена не извлечена». Листовые ОН не подтверждены; нельзя утверждать без журналов, что для каждого из них был выполнен полный семантический поиск.

## Требования к администраторским панелям

В карточке работы показывать: этап, результат, что реально проверено, объём работы, доказанную/предполагаемую причину, доступные действия, ответственного, ссылку на первоисточник и историю попыток. Машинные коды скрывать в «Технических деталях»; основные сообщения — понятным языком. Кнопки «Выбрать вручную», «Повторить проверку», «Проверить с ИИ», «Запросить уточнение», «Передать ответственному» показывать только если действуют соответствующий механизм и разрешения. Любая запись в глобальную модель требует отдельного подтверждения.

Для будущей наблюдаемости потребуются: шаг/попытка, исполнитель и версия метода, статус запуска, вид поиска, охват и полнота обхода, число кандидатов, результат, код причины, достоверность причины, доказательства, разрешённые следующие действия. **Сначала использовать существующие журналы и контракты, не создавать дублирующее хранилище без инвентаризации.**

## Дорожная карта

- **Сейчас, ADM-4:** зафиксировать правило; не исправлять специально эту активность. Вернуться к приёмке создания/привязки дел, защите от дублей и подготовке публикации.
- **Плановое развитие административских панелей:** внедрить точные статусы проверки и человеческие объяснения.
- **ADM-5:** интегрировать прозрачные журналы фактической работы ИИ-исполнителей с контролем и утверждением человека.

**Критерий приёмки:** администратор по любой незавершённой операции способен узнать, предпринималась ли попытка, как именно, почему она не завершилась и что конкретно делать дальше, без ложных выводов о действиях ИИ.
