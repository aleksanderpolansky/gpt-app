Purpose:
Define the safe first boundary for the next major phase:
"user adds an activity" -> controlled activity_event intake -> future semantic derivation pipeline.

This step starts the transition from isolated controlled state-fact proof to full activity semantic pipeline:
activity input -> activity_event -> derivation_run -> categoryCandidates -> contextual categories -> VO bridge -> stateHookCandidates -> controlled facts/deltas/snapshots where allowed.

- Previous pushed commit: 39b00e7

- N-D removed the proof-only successful rollback route and browser payload.
- No production controlled rollback route exists.

Core rule:
Activity Event is the source of truth for user-entered activity.
AI output, category candidates, state hooks, and resolver suggestions must never replace the activity_event source record.

Controlled activity intake means:
1. A user submits a natural-language activity input.
2. The system normalizes only safe structural fields.
3. The system creates or prepares a controlled activity_event record.
4. The record belongs to the authenticated user/actor.
5. The record carries source/provenance and timing fields.
6. The system does not yet derive categories, VOs, hooks, facts, deltas, or snapshots in this first contract step.
7. Later semantic layers attach to this activity_event through controlled, auditable links.

Allowed input fields for first controlled intake:
- inputText: string
- title: optional string
- startedAt: optional ISO datetime
- endedAt: optional ISO datetime
- durationMinutes: optional number
- timezone: optional IANA timezone or inferred application timezone
- source: manual | chat_ai_assisted | import | calendar | system_test
- status: draft | planned | completed | confirmed
- privacyLevel: private by default
- clientTraceId: optional idempotency/correlation key
- metadata: optional bounded json

Derived safe structural fields:
- normalizedTitle
- normalizedInputText
- durationMinutes if exactly derivable from startedAt and endedAt
- startedAt/endedAt if derivable from explicit user input and current timezone rules
- sourceRoute
- createdByUserId / actorId from authenticated session only
- intakeContractVersion

Forbidden at O-A:
- no categoryCandidates persistence
- no contextual_categories resolution
- no Value Object creation
- no Value Object linking
- no stateHookCandidates persistence
- no value_object_state_facts writes
- no activity_state_deltas writes
- no snapshots writes
- no AI direct persistence
- no uncontrolled active categories from AI
- no medical/hormonal/financial overclaims
- no automatic "closed deal", "income received", "high cortisol", "burnout", or similar fact claims
- no production rollback route
- no generic update/delete endpoint
- no use of old canonical /api/activity/complete proof for new production-like tests

Idempotency rule:
The first controlled intake route must accept a clientTraceId/idempotencyKey.
Repeated same request with same authenticated user and same key must not create duplicates.

Ownership rule:
The authenticated user/actor is always resolved server-side.
The client must not be trusted to choose user_id directly.

Timing rule:
If only duration is provided, store duration.
If start and end are provided, calculate duration.
If only a natural phrase is provided, keep unknown timing fields null unless confidently derivable.
Do not invent exact timestamps from vague language.

Semantic boundary rule:
O-A/O-B creates or prepares only the activity_event source record.
Semantic derivation starts later in O-C/O-D.
State hooks and state facts start later after derivation and resolver contracts.

Review boundary:
The first end-to-end UI may show:
- source input
- normalized title
- detected duration if safe
- status
- privacy
But it must not yet show categories/VO/state hooks as confirmed facts.
