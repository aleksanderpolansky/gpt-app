Contract purpose
The future auth session read layer must convert a verified server-side auth/session result into a minimal controlled-intake server identity.
That identity is then passed into serverSideAppUserMapping.ts.
The auth session layer must not perform app-user Supabase mapping reads.
The auth session layer must not create or update users.
The auth session layer must not write activity_events.

Input shape: server-side auth session read input
The helper should receive an injected server-side session read model in its first static version.
Actual Auth0 SDK/session runtime call must be introduced only after a separate implementation gate.

Recommended input fields:
- source?: "auth0_server_session" | "test_injected_session_read_model"
- sessionReadModel?: ControlledActivityIntakeServerSideAuthSessionReadModel | null
- requestSource?: string | null

Input shape: session read model
Recommended fields:
- provider?: "auth0" | "unknown" | string | null
- authSubject?: string | null
- email?: string | null
- sessionId?: string | null
- userId?: string | null
- name?: string | null
- picture?: string | null
- expiresAt?: string | number | null
- issuedAt?: string | number | null
- rawSessionAvailable?: boolean
- readSource?: "auth0_server_session" | "test_injected_session_read_model" | string

Rules:
- authSubject must be the stable identity anchor.
- email must not be used as primary identity.
- userId may be kept only as non-primary metadata.
- name and picture must not be returned to route response by default.
- raw session object must not be returned.
- tokens must never be returned.

Output shape: failure
A failure result should be:

  ok: false,
  layer: CONTROLLED_ACTIVITY_INTAKE_SERVER_SIDE_AUTH_SESSION_LAYER,
  source: "auth0_server_session" | "test_injected_session_read_model",
  code: string,
  message: string,
  guardrails: same guardrails
}

Required failure codes
- CONTROLLED_INTAKE_SERVER_SESSION_REQUIRED
- CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED
- CONTROLLED_INTAKE_AUTH_SESSION_INVALID
- CONTROLLED_INTAKE_AUTH_PROVIDER_UNSUPPORTED
- CONTROLLED_INTAKE_AUTH_SESSION_READ_FAILED

Required fail-closed behavior
- Missing session read model -> fail with CONTROLLED_INTAKE_SERVER_SESSION_REQUIRED.
- Missing authSubject -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Blank authSubject -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Unsupported provider -> fail with CONTROLLED_INTAKE_AUTH_PROVIDER_UNSUPPORTED.
- Malformed session -> fail with CONTROLLED_INTAKE_AUTH_SESSION_INVALID.
- Session read exception -> fail with CONTROLLED_INTAKE_AUTH_SESSION_READ_FAILED.
- Email-only identity -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Ambiguous identity -> fail rather than guess.
- Any uncertainty about the identity anchor must fail.

Allowed future provider assumptions
- auth0 is allowed as the first explicit provider.
- unknown provider must fail until explicitly supported.
- provider may be inferred only from trusted server session.
- provider must not be inferred from request body.

Forbidden identity sources
- request body identity
- query string identity
- client local storage
- preview headers in production write mode
- AI-inferred identity
- email-only identity without authSubject
- unverified frontend user object
- raw user-provided user_id
- raw user-provided appUserId
