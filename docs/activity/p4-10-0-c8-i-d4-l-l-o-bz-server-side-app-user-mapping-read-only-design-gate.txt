Design target
The next implementation corridor must map:

trusted server-side auth session
-> provider
-> authSubject
-> internal app user
-> trusted controlled-intake auth context

The browser/client must not be allowed to provide:
- appUserId
- actorId
- organizationId
- spaceId
- ownership fields
- productionWriteEnabled
- DB write flags
- semantic persistence flags
- state fact/delta/snapshot fields

Server-side mapping principle
Only the server may derive the internal app user from the authenticated session.

Allowed input into the mapping corridor:
- provider, expected value: auth0
- authSubject / subject from sanitized session
- optional email only for diagnostics and error context
- optional sessionId only for sanitized diagnostics if already available
- no raw session
- no raw profile
- no token
- no cookie dump
- no full provider payload

Forbidden input into the mapping corridor:
- client-supplied appUserId
- client-supplied user_id
- client-supplied actorId
- client-supplied organizationId
- client-supplied spaceId
- client-supplied ownership information
- client-supplied RLS bypass indicator
- access_token
- refresh_token
- id_token
- raw session
- raw profile
- full Auth0 user object
- full provider payload

Read-only mapping contract to design next
The next block must define a read-only contract with at least these cases:

1. mapped_user_found
   Auth0 provider + authSubject maps to exactly one active internal app user.

2. session_missing
   No authenticated server-side session is present.

3. auth_subject_missing
   Auth session exists but sanitized auth subject is missing.

4. provider_unsupported
   Provider is not auth0 or provider is missing.

5. app_user_not_found
   No internal app user exists for provider + authSubject.

6. app_user_duplicate
   More than one internal app user candidate exists for provider + authSubject.

7. app_user_inactive
   Internal app user exists but is inactive/disabled/blocked, if such field exists.

8. provider_mismatch
   Internal user record exists but provider does not match the authenticated provider.

9. mapping_read_failed
   DB read failed in the future read-only corridor.

10. unsafe_payload_detected
   Mapping output or error output attempts to expose raw session/token/provider payload.
