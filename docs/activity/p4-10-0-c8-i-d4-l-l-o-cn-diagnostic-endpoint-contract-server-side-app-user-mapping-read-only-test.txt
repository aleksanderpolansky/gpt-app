Future diagnostic endpoint guard
- The endpoint must require an explicit diagnostic header.
- Header name: x-controlled-intake-server-side-app-user-mapping-read-only-test.
- Recommended accepted value: enabled.
- If the header is missing or invalid, the endpoint must fail before Auth0 session read and before DB lookup.
- Header failure response must set diagnosticHeaderAccepted false.
- Header failure response must set authSessionReadExecuted false.
- Header failure response must set dbReadExecuted false.

Future diagnostic endpoint runtime source
- Read server-side Auth0 session using the existing server-side auth/session bridge.
- Do not accept provider from the browser.
- Do not accept authSubject from the browser.
- Do not accept appUserId from the browser.
- Do not accept userId, actorId, organizationId or spaceId from the browser as trusted ownership.
- Provider and authSubject must come only from trusted server-side session/context extraction.

Future diagnostic endpoint mapping flow
1. Verify diagnostic header.
2. Read trusted server-side Auth0 session/context.
3. Build trusted context from the server-side Auth0 session.
4. Call mapServerSideAppUserReadOnly with trusted provider and trusted authSubject.
5. Return a sanitized diagnostic response.
