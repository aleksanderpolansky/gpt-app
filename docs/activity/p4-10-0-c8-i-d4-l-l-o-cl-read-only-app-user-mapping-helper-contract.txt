Future helper purpose
The helper should map a trusted server-side Auth0 subject to an internal app user id using a read-only query against public.app_users.

Future helper import contract
- Import getSupabaseAdminClient from lib/supabase/admin.
- Do not import browser/client Supabase helpers.
- Do not import from files containing use client.
- Do not import the helper into client components.

Future helper input contract
The helper should accept a trusted context object with these fields:
- provider.
- authSubject.

Input rules
- provider must equal auth0.
- authSubject must be a non-empty string.
- Client-supplied appUserId, userId, actorId, organizationId and spaceId must not be accepted as trusted ownership.
- The helper must not parse raw cookies.
- The helper must not parse raw Auth0 tokens.
- The helper must receive trusted server-side values only from the existing auth/session bridge.

Future helper query contract
- Use getSupabaseAdminClient.
- Query public.app_users.
- Select id and auth0_sub only.
- Filter auth0_sub equals trusted authSubject.
- Limit defensively to 2 rows.
- Do not select email, name, picture or timestamps in the first implementation.
- Do not query auth.users.
- Do not query auth.identities.
- Do not execute raw SQL.

Future helper result statuses
The future helper should return a discriminated result with mappingStatus:
- provider_not_supported.
- missing_auth_subject.
- app_user_not_found.
- mapped_user_found.
- app_user_duplicate.
- app_user_lookup_error.

Success result contract
For mapped_user_found:
- mappedUserFound: true.
- appUserId may be returned only as sanitized proof if the implementation contract explicitly allows it.
- appUserInactiveSupported: false.
- appUserInactiveCheckExecuted: false.
- selectedColumns should be id and auth0_sub.
- dbReadExecuted may be true only in the future implementation/diagnostic runtime gate, not in O-CL.

Failure result contract
For provider_not_supported:
- mappedUserFound: false.
- dbReadExecuted: false.
- The helper must fail before DB lookup.

For missing_auth_subject:
- mappedUserFound: false.
- dbReadExecuted: false.
- The helper must fail before DB lookup.

For app_user_not_found:
- mappedUserFound: false.
- dbReadExecuted: true in future runtime implementation.

For app_user_duplicate:
- mappedUserFound: false.
- failClosed: true.
- This should be defensive because UNIQUE (auth0_sub) exists.

For app_user_lookup_error:
- mappedUserFound: false.
- failClosed: true.
- Error details must be sanitized.

Inactive/status rule
- Current public.app_users schema has no active/status field.
- The helper must not pretend to execute inactive/status checks.
- appUserInactiveSupported must be false.
- appUserInactiveCheckExecuted must be false.
- Adding inactive/status support requires a later migration/status gate.

Safe response boundary
- Do not return raw DB rows.
- Do not return raw Supabase error objects.
- Do not return raw Auth0 session.
- Do not return raw Auth0 profile.
- Do not return cookies.
- Do not return access_token, refresh_token, id_token or any token.
- Do not return full provider payload.
- Do not return full user record.
- Do not return service-role configuration details.
