Contract purpose
Server-side app user mapping must convert trusted server identity into controlled activity trusted context:
- authenticated server identity -> app user mapping -> trusted activity context

This mapping must be fail-closed.
It must never trust request body ownership fields.
It must never use production preview headers in production write mode.
It must not create or update users during controlled intake.

Input shape: server identity
The mapping layer may receive only server-side identity input.

Required fields:
- authSubject: string
- provider?: string
- email?: string
- sessionId?: string
- requestSource?: string

Rules:
- authSubject must be non-empty after trimming.
- authSubject must come from server-side session/Auth0 middleware/verified server context.
- authSubject must not come from request body.
- email is not sufficient as primary identity.
- sessionId may be included for audit/debug, but must not replace authSubject.
- requestSource may describe route/context, but must not grant permissions.

Input shape: app user read model
This read model is the future output of a server-side read resolver.
O-AK does not perform this read.

Required fields:
- appUserId: string
- internalUserId?: string
- authSubject: string
- mappingSource: "user_profile" | "auth_user_sync" | "manual_verified_mapping" | "test_injected_read_model"
- mappingStatus: "active" | "blocked" | "missing" | "ambiguous"
- email?: string
- createdAt?: string
- updatedAt?: string

Rules:
- appUserId must be non-empty.
- authSubject in read model must match server identity authSubject.
- mappingStatus must be active for success.
- blocked mapping must fail.
- missing mapping must fail.
- ambiguous mapping must fail.
- email mismatch alone must not override authSubject.
- mapping must be treated as server-side evidence only.

Input shape: optional membership/context read model
This read model is for future actor/organization/space context.
O-AK does not perform this read.

Optional fields:
- actorId?: string
- organizationId?: string
- spaceId?: string
- actorStatus?: "active" | "blocked" | "missing" | "not_allowed"
- organizationMembershipStatus?: "active" | "blocked" | "missing" | "not_allowed"
- spaceMembershipStatus?: "active" | "blocked" | "missing" | "not_allowed"
- role?: string
- membershipSource?: "organization_membership" | "space_membership" | "actor_space_role" | "test_injected_read_model"

Rules:
- actorId/organizationId/spaceId are optional.
- If supplied, they must be server-verified.
- If a context id is requested but not verified, fail.
- blocked/not_allowed context must fail.
- missing optional context may be omitted from trusted context.
- request body must never provide ownership context.

Required fail-closed behavior
- Missing server session -> fail.
- Missing auth subject -> fail.
- Blank auth subject -> fail.
- Missing app user read model -> fail.
- Missing appUserId -> fail.
- Ambiguous app user mapping -> fail.
- Blocked app user mapping -> fail.
- Auth subject mismatch -> fail.
- Requested actor context not verified -> fail.
- Requested organization context not verified -> fail.
- Requested space context not verified -> fail.
- Any client-provided ownership field remains rejected before mapping.
- Any uncertainty about owner/context must fail rather than guess.

Forbidden mapping sources
- request body user_id
- request body appUserId
- request body actorId
- request body organizationId
- request body spaceId
- query string ownership fields
- client-side local storage
- production preview headers in production write mode
- AI-inferred owner
- email-only match without authSubject match

Allowed future mapping sources
Only after explicit read gate:
- server-side session/Auth0 identity
- server-side Supabase read by authSubject
- existing user sync/profile mapping
- server-verified actor/organization membership
- server-verified space membership
- injected static read model for no-I/O tests
