Schema interpretation
1. public.app_users remains the trusted internal user anchor after Auth0 mapping.
2. public.spaces has owner_user_id referencing app_users(id), so it can be used as a direct app-user-to-space ownership anchor.
3. public.organizations has created_by_user_id referencing app_users(id), so it can be used as a creator-owned organization anchor.
4. public.actors can represent person or organization actors, but it does not directly contain app_user_id.
5. public.actor_space_roles links actors to spaces and contains function_type, is_active, authority_level and responsibility_level.
6. public.activity_events already has user_id plus actor fields: performed_by_actor_id, acting_as_actor_id and acting_for_actor_id.
7. No dedicated organization_memberships table was found.
8. No dedicated space_memberships table was found.

Decision: safest resolver path
The next resolver should be no-write and read-only.
The resolver must require a mapped internal app user id from the existing Auth0-to-app-user mapping step.
The resolver must treat client-supplied actorId, organizationId and spaceId as hints only.
The resolver must not trust client-supplied ownership/context identifiers as proof.
