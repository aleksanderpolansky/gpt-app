Future runtime helper role
The future runtime helper should read a real server-side Auth0/session using the project-approved auth boundary and convert it to the injected read-model shape accepted by serverSideAuthSession.ts.
The runtime helper should not decide appUserId.
The runtime helper should not read Supabase.
The runtime helper should not write anything.
The runtime helper should not be called by route.ts until a separate route integration gate.

Approved architectural boundary
The controlled-intake route must not call the Auth0 SDK directly.
A small server-only runtime adapter may call the project-approved Auth0/session helper after a later implementation gate.
That adapter returns a sanitized read model only.
Then serverSideAuthSession.ts validates and normalizes that read model.

Runtime helper output contract: failure
A failure runtime helper should return:

{
  ok: false,
  layer: CONTROLLED_ACTIVITY_INTAKE_SERVER_SIDE_AUTH_SESSION_RUNTIME_LAYER,
  source: "project_auth0_server_session",
  code: string,
  message: string,
  sessionReadModel: {
    provider?: "auth0",
    authSubject?: null,
    rawSessionAvailable: false,
    readSource: "project_auth0_server_session",
    readFailed: true,
    readFailureMessage: string
  },
  guardrails: same guardrails, but auth0RuntimeReadExecuted may be true if the read was attempted
}

Required future failure codes
- CONTROLLED_INTAKE_SERVER_SESSION_REQUIRED
- CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED
- CONTROLLED_INTAKE_AUTH_SESSION_INVALID
- CONTROLLED_INTAKE_AUTH_PROVIDER_UNSUPPORTED
- CONTROLLED_INTAKE_AUTH_SESSION_READ_FAILED
- CONTROLLED_INTAKE_AUTH_SESSION_EXPIRED
- CONTROLLED_INTAKE_AUTH_SESSION_RUNTIME_UNAVAILABLE
- CONTROLLED_INTAKE_AUTH_RUNTIME_NOT_APPROVED

Required fail-closed behavior
- Runtime helper called without explicit implementation approval -> fail with CONTROLLED_INTAKE_AUTH_RUNTIME_NOT_APPROVED.
- Missing Auth0/project auth helper -> fail with CONTROLLED_INTAKE_AUTH_SESSION_RUNTIME_UNAVAILABLE.
- Missing session -> fail with CONTROLLED_INTAKE_SERVER_SESSION_REQUIRED.
- Expired session -> fail with CONTROLLED_INTAKE_AUTH_SESSION_EXPIRED.
- Missing subject/sub -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Blank subject/sub -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Unsupported provider -> fail with CONTROLLED_INTAKE_AUTH_PROVIDER_UNSUPPORTED.
- Malformed session payload -> fail with CONTROLLED_INTAKE_AUTH_SESSION_INVALID.
- Runtime exception -> fail with CONTROLLED_INTAKE_AUTH_SESSION_READ_FAILED.
- Email-only identity -> fail with CONTROLLED_INTAKE_AUTH_SUBJECT_REQUIRED.
- Any uncertainty about identity anchor -> fail.

Auth0/project helper decision
O-AZ contract does not hard-code a concrete SDK call.
The next implementation gate must choose the exact project auth helper after inspecting the current Auth0 integration.
The controlled-intake route must remain decoupled from the SDK.
The runtime adapter is the only future place where a project-approved Auth0/session read may occur.

Next.js runtime assumptions
- Controlled-intake route is treated as server-side only.
- Runtime read should be Node/server compatible unless a later gate proves Edge compatibility.
- Direct cookie/header reads are forbidden in serverSideAuthSession.ts.
- Cookie/header reads, if required by the project Auth0 helper, must stay inside the future runtime adapter.
- Route integration must be a later separate gate.
