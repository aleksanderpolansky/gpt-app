Decision 1 — Unified Value Object:
Value Object remains a single unified entity.
Do not introduce mandatory Value Object subtypes such as context_value_object, biological_value_object, process_value_object, baseline_value_object or similar structural subtype axes.

Reason:
One object may simultaneously be a process, context, goal, factor, commercial object, personal analytics object and source of influence.
Mandatory subtypes would create sorting, filtering and future-extension conflicts.

How VO roles are determined instead:
- semantic category signature
- parent/child hierarchy
- actor ownership/context
- source activity/event exposure
- state dimensions
- similarity edges
- relevance/influence edges
- current and baseline context

Decision 2 — State tables instead of object types:
State must be stored outside the Value Object type system.
The platform should use universal state contracts/tables such as:
- state_dimensions
- value_object_state_facts
- activity_state_deltas
- value_object_state_snapshots
- state_relevance_rules
- value_object_similarity_edges
- value_object_relevance_edges

Decision 3 — Category is not a state fact:
A category candidate may become a hook or signal, but it must not automatically become a state fact.
State facts require a separate source/confidence/evidence/window/status/correction contract.

Allowed:
- category candidate
- semantic hook
- metric candidate
- possible state signal
- risk flag

Not allowed:
- converting AI category output directly into active ontology truth
- converting category candidate directly into state fact
- claiming medical, hormonal, emotional or financial facts without evidence contract

Decision 4 — Direct measurement vs semantic hook vs inferred state:
C8-I must separate:
- direct measurement
- user self-report
- semantic hook
- inferred state
- risk flag
- forbidden overclaim

Examples:
- walking can be a physical activity hook, but not automatic muscle growth.
- coffee can be an alertness/sleep-risk signal, but not exact dopamine/cortisol state.
- lead-generation can be business effort, but not income received or closed deal.
- childcare/helping child learn can be family care load hook, but not automatic family climate improvement.

Decision 5 — Similarity is not relevance:
Similarity and relevance are separate mechanisms.

Similarity:
- based mostly on weighted semantic category overlap.
- example: two language-learning activities are similar.

Relevance:
- based on influence/rules/current constraints.
- example: sleep is relevant to language learning even if it is not semantically similar.

Decision 6 — Baseline Context is graph-compatible:
Baseline Context is not one questionnaire and not one Value Object.
It is a graph-compatible layer of:
- long-term factors
- historical activities
- stable and slow-changing Value Objects
- actors
- relationships
- state facts
- influence/relevance links
- source/confidence/evidence metadata

Baseline Context must not become:
- social rating
- deterministic destiny model
- uncontrolled medical/social claim layer

Sensitive baseline factors must remain:
- voluntary
- private by default
- editable/correctable
- source/confidence/evidence based
- protected by privacy level

Decision 7 — Next Best Action v0:
First recommendation layer must not start with automatic “do X now”.
It starts with weakest-direction detection.

Process:
1. Detect weakest or under-attended directions.
2. Sort directions from weakest to strongest.
3. Ask user which direction they want to work on now.
4. After user choice, produce action candidates.
5. Filter candidates by current state, baseline modifiers, obligations, environment, time window and risk filters.
6. Offer variants from light/game-like to deep analytical or revenue-oriented.
7. Collect feedback/correction as Semantic Capital.

Initial top-level directions may include:
- health
- recovery
- family
- finance
- career
- languages
- project
- work
- rest
- social
- user-defined strategic directions
