============================================================
2. Migration design principles
============================================================

Principles:
- additive first
- no destructive changes
- no required backfill at first pass
- nullable fields where semantics may evolve
- categories, hooks, facts, deltas, snapshots and edges stay separate
- similarity and relevance stay separate
- personal state is private by default
- user correction must be possible
- source, evidence, confidence, privacy, sensitivity and lifecycle fields are required where needed
- RLS and explicit GRANT are required
- no broad anon access to personal state tables

============================================================

13. RLS / GRANT design
============================================================

Future SQL migration order:
create table -> indexes -> enable row level security -> policies -> explicit GRANT.

Policy direction:
- authenticated select/insert/update only own rows for personal tables
- no anon access to personal state tables
- service_role for backend/server routes only
- catalog tables may be authenticated-read
- public read only for explicitly public non-sensitive directory/commercial data

GRANT direction:
- grant select/insert/update/delete to authenticated only where RLS allows it
- grant select to anon only for intentionally public read-only tables
- do not grant broad anon access to state facts, state deltas, state snapshots, resolver runs or personal edges
- GRANT does not replace RLS
