# ARCTor UI Design Standard V1

Дата фиксации: 2026-09-07
Статус: active design contract
Область: desktop/web workspace, dashboard pages, catalog pages, shared controls

## 1. Источник стандарта

Стандарт фиксирует уже используемый High-Fidelity Dashboard как визуальную основу ARCTor. Базовые токены подтверждены в `src/styles/theme.css` переданного High-Fidelity Dashboard Design. Файл `guidelines/Guidelines.md` в исходном дизайн-пакете является шаблоном и не содержит собственного стандарта, поэтому этот документ становится рабочим контрактом проекта.

## 3. Workspace и ширина

Основные dashboard/catalog страницы используют фон `#f0f2f7`, `p-5` и занимают всю доступную ширину рабочей области. Произвольный `max-width` для основного dashboard-контента не добавляется, если это не отдельная узкая форма или документ.

## 4. Карточки и панели

Базовая карточка: `rounded-xl border border-[rgba(0,0,0,0.06)] bg-white shadow-sm`. Внутренний padding выбирается по плотности данных; базовое значение dashboard — `p-4`. Радиусы 18/20 px не используются для обычных dashboard-карточек без отдельного утверждённого основания.

## 5. Segmented switch

Переключатели области вида «Мои / Системные / Все» используют единый компонент `ArctorSegmentedSwitch`.

Внешний контейнер: `rounded-xl border border-[#dfe3f1] bg-white p-1 shadow-sm`.
Пункт: `rounded-lg px-4 py-2 text-[13px] font-semibold`.
Активный пункт: `bg-[#3b6ef8] text-white shadow-sm`.
Неактивный: `text-[#5a5f7a] hover:bg-[#f5f6fb]`.

Нельзя копировать эти классы в новые страницы: используется общий компонент.

## 6. Фильтры

Компактные фильтры используют `rounded-lg px-3 py-1.5 text-[12px] font-medium`. Активный фильтр — primary blue; неактивный — белый с границей `rgba(0,0,0,0.07)`. Scope switch и структурные фильтры являются разными уровнями управления и визуально не смешиваются.

## 7. Действия

Обычное основное действие использует primary `#3b6ef8` и `rounded-xl`. Вторичное действие — белая кнопка с `#dfe3f1` border. Positive/contextual действие, включая «Добавить суперпредложение», использует существующий зелёный вариант: `border-[#22c55e]/35 bg-[#ecfdf3] text-[#16a34a] hover:bg-[#dcfce7]`.

Одинаковое действие должно иметь одинаковую визуальную семантику на разных страницах.

Контекстное действие создания основной сущности раздела на desktop размещается в отдельной верхней action-row справа. Scope/navigation switch размещается отдельной следующей строкой слева; create action и scope switch не объединяются в одну горизонтальную строку. Подпись и маршрут должны соответствовать сущности текущего раздела: каталог ОН не должен показывать CTA коммерческого раздела, сертификаты не должны показывать CTA создания ОН.

## 8. Текст и локализация

Цвет заголовков и ключевых чисел — `#1a1d2e`. Вторичный текст — `#7c8099` или согласованный промежуточный `#5a5f7a`. Локализация не должна менять визуальную иерархию компонента; длинные подписи допускают перенос.

## 9. Правило повторного использования

Если один и тот же паттерн встречается на двух и более production-страницах, предпочтение отдаётся общему компоненту или общему token contract. Запрещено создавать локально новый визуальный вариант только потому, что страница находится в другом разделе.

## 10. Текущая нормализация V1

В рамках V1:

- общий `ArctorSegmentedSwitch` подключается к сертификатам и объектам наблюдения;
- каталог ОН получает workspace background/padding без дополнительного max-width;
- обычные surfaces каталога ОН приводятся к `rounded-xl` и общей границе;
- структурные фильтры ОН приводятся к dashboard filter-chip pattern;
- каталог ОН использует одну зелёную contextual-action «Добавить ОН» → /value-objects/new/root; универсальный selector /value-objects/new не используется из каталога ОН;
- на странице сертификатов contextual-action «Добавить суперпредложение» → /offers/new размещается в отдельной верхней action-row справа, а scope switch — отдельной следующей строкой слева;
- API, БД, RLS и семантическая логика не меняются.
