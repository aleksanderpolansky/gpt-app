- Offer is certificate terms / commercial package.
- Current target logic has one type of offer.
- Certificate is created from offer.
- Purchase confirmation is organization-level external purchase confirmation.
- Purchase confirmation must not become a cart, order or item-list.
- Existing offer item/package structure, if present, must be interpreted separately from purchase confirmation.

## 8. Semantic decision

### 8.1 Offer items

- If offer_items exist, they are not automatically a problem.
- They may represent internal composition of an offer/certificate package.
- They must not be interpreted as a platform checkout basket unless the code/schema clearly implements checkout/order semantics.
- If offer_items link several value_objects to one offer, then the correct wording is: offer is a commercial package over one or more Value Objects.
- This does not make offer equal to Value Object.

### 8.2 Purchase confirmation items

- purchase_confirmation_items must not be added.
- purchase_confirmations must remain organization-level and amount-based.
- The platform does not need to know what exactly was bought for points awarding.
- The platform needs organization_id, buyer_user_id, purchase_amount, currency, status, points_awarded and audit timestamps.

### 8.3 A4b conclusion

- Offer item/package logic, if present, belongs to offer/certificate packaging.
- Purchase confirmation item/cart/order logic remains explicitly out of scope.
- A5 must use precise wording: 'Offer may have internal package items if already implemented, but purchase confirmation has no item list.'
- A6 must not create purchase_confirmation_items.
- Before any migration, verify whether offer_items table exists and whether it needs no change.

## 9. A5 wording to reuse

Offer is a commercial certificate package. In the current code it may already have item/package composition around Value Objects. This is not the same as purchase confirmation items and does not turn purchase confirmation into a cart/order. Purchase confirmation remains an organization-level external purchase confirmation based on amount.
