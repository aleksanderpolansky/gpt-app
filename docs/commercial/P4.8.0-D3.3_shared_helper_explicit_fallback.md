# P4.8.0-D3.3 — Shared Helper Explicit Fallback Support

Status: HELPER PATCH / NO ROUTE ADOPTION YET

Runtime route adoption: NO

## 1. What changed

Updated:

- src/lib/commercial/currency.ts

Added explicit fallback support to:

- getDefaultCurrencyByCountryCode(countryCode, options)

New options type:

- CurrencyFallbackOptions

Supported option:

- fallbackCurrency

## 2. Why this was needed

D3.2 found that direct route adoption would not be behavior-preserving:

- existing organization routes return PLN for unknown/unsupported country codes;
- shared helper previously returned null for unknown/unsupported country codes.

To keep D3.4 route adoption behavior-preserving, helper now supports explicit fallback usage.

## 3. Default behavior remains target-safe

Default helper behavior remains:

- unknown country -> null

Example:

- getDefaultCurrencyByCountryCode("XX") returns null

This preserves target architecture:

- unknown country should not silently create arbitrary currency by default.

## 4. Legacy behavior can be requested explicitly

Organization routes can later preserve old behavior by calling:

- getDefaultCurrencyByCountryCode(countryCode, { fallbackCurrency: "PLN" })

This makes legacy fallback visible and deliberate.

## 5. Scope limitation

No existing route was changed.

No route imports the helper yet.

Route adoption remains a separate D3.4 block.

## 6. Forbidden changes remain forbidden

- Do not add purchase_confirmation_items.
- Do not add purchase_confirmations.offer_id.
- Do not add purchase_confirmations.value_object_id.
- Do not turn purchase confirmation into cart/order/item flow.
- Do not let organization currency become arbitrary manual user input.
- Do not transfer burned points to seller.
- Do not bypass certificate/points RPC.
