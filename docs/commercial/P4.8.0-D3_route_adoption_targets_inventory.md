## 6. Preliminary adoption candidates

### 6.1 First safe adoption candidates

- src/app/api/organizations/route.ts
- src/app/api/organizations/[id]/location/route.ts

Reason:

- These files contain duplicated local getDefaultCurrencyByCountryCode and normalizeCountryCode logic.
- Replacing those local implementations with imports from src/lib/commercial/currency.ts should be behavior-preserving if done carefully.

### 6.2 Not first adoption candidates

- src/app/api/directory/organizations/route.ts
- src/app/api/offers/route.ts
- purchase confirmation routes

Reason:

- Directory route contains MINIMUM_PURCHASE_THRESHOLDS and should be handled later with commercial_currency_rules planning.
- Offers route has offer-specific currency logic and should not be changed during the first helper adoption.
- Purchase confirmation currency sync is a separate D4 block.

## 7. D3 decision

- D3 does not change runtime code.
- First route adoption should be limited to organization routes only.
- The next implementation step should be D3.1: replace local duplicate functions in organization routes with shared helper imports.
- Behavior must remain unchanged.

## 8. Forbidden changes remain forbidden

- Do not add purchase_confirmation_items.
- Do not add purchase_confirmations.offer_id.
- Do not add purchase_confirmations.value_object_id.
- Do not turn purchase confirmation into cart/order/item flow.
- Do not let organization currency become arbitrary manual user input.
- Do not transfer burned points to seller.
- Do not bypass certificate/points RPC.
