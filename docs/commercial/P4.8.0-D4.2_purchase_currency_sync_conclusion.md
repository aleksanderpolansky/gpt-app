# P4.8.0-D4.2 — purchase_currency / currency sync conclusion

Date: 2026-05-18
Status: READY FOR D4.3

## Decision

purchase_confirmations.purchase_currency remains the single active runtime/business currency field.

purchase_confirmations.currency is treated as a duplicate less-integrated field.

## Evidence

D4.1 confirmed:

- submit_purchase_confirmation accepts p_purchase_currency
- submit_purchase_confirmation computes v_purchase_currency
- submit_purchase_confirmation inserts purchase_currency
- submit_purchase_confirmation does not explicitly insert currency
- purchase_confirmation_events use purchase_currency
- current table drift between purchase_currency and currency is 0

## D4.3 direction

Prepare safe migration that:

1. checks that purchase_currency exists
2. checks whether currency exists
3. checks drift between purchase_currency and currency
4. aborts if drift exists
5. drops only purchase_confirmations.currency when safe
6. does not touch purchase_currency
7. does not change RPC logic
8. does not introduce cart/order/item semantics

## Conclusion

Proceed to D4.3 safe migration.
