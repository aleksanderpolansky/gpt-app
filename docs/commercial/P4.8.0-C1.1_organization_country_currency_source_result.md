## 4. C1 interpretation

- Organization currency source is already represented by organizations.default_currency.
- organizations.currency is not needed at this stage.
- organizations.country_code is the country source on the organization record.
- organization_locations provides location-level country/city/geo linkage.
- geo_areas provides geographic hierarchy support.
- commercial_currency_rules does not exist yet and remains a future platform-rules table candidate.

## 5. Correct source-of-truth decision

For the current MVP, use this canonical interpretation:

- organization.country_code determines organization.default_currency.
- organization.default_currency is the stored organization currency.
- purchase_confirmations.purchase_currency should be derived from organization.default_currency.
- purchase_confirmations.currency is currently a duplicate/additive field and should not become a separate business source.
- offers.currency and certificates should stay aligned with organization.default_currency unless an explicitly approved exception is introduced later.

## 6. Future technical debt

- purchase_confirmations has two currency fields: purchase_currency and currency.
- Current values match, but future writes could drift.
- Later technical alignment should synchronize or consolidate these fields.
- commercial_currency_rules table is absent; it should be planned later for the 10 EUR equivalent threshold.
