# P4.8.0-D4.3 — corrective migration for obsolete purchase_confirmations.currency

Date: 2026-05-18
Scope: commercial currency cleanup
Status: READY FOR COMMIT

## Why this migration exists

Live SQL inspection confirmed:

- public.purchase_confirmations.purchase_currency exists.
- public.purchase_confirmations.currency does not exist.
- public.submit_purchase_confirmation writes to purchase_currency.
- Existing rows have purchase_currency = PLN.

Repository audit found that historical migration:

- supabase/migrations/025_p4_8_0_add_commercial_usage_and_purchase_currency.sql

still contains obsolete references that add:

- public.purchase_confirmations.currency
- purchase_confirmations_currency_check

## Decision

Do not edit old migration 025 directly at this step.

Instead, add a safe corrective migration:

- supabase/migrations/026_p4_8_0_drop_obsolete_purchase_confirmations_currency.sql

This preserves migration history and ensures that any future reset/new environment does not keep the obsolete column.

## What the corrective migration does

It safely runs:

- drop constraint if exists purchase_confirmations_currency_check
- drop column if exists currency
- adds a comment to purchase_confirmations.purchase_currency

## Safety

The migration is idempotent.

If currency does not exist, it does nothing dangerous.

If an older migration creates currency, this migration removes it.

## Commercial currency contract after D4.3

The active contract is:

organization.country_code -> organization.default_currency -> purchase_confirmations.purchase_currency

purchase_confirmations.currency must not be reintroduced.
