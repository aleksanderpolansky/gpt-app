## Why this route was needed

Existing /api/activity/record is still template-first.

When naturalInput is submitted without a resolved template, /api/activity/record creates a draft event, not a completed free-text activity event.

/api/activity/intake captures raw signals only and does not automatically create completed activity events.

/api/activity/intake/signals/[id]/promote creates activity events through templateMapping.

Therefore a small debug-only route was needed to test the new controlled free-text fallback honestly.

## New route

- src/app/api/activity/debug/free-text-value-object-test/route.ts

Endpoint:

- /api/activity/debug/free-text-value-object-test

Purpose:

- create a completed activity_event without activity_template_id
- store input_text from inputText/naturalInput
- set activity_template_id: null
- set template_id: null
- run processActivityValueObjectBridge
- return mapping and bridge details in JSON

## Fix applied

Initial route version incorrectly assumed getActivityUserContext returns ok/error/status.

Actual ActivityUserContext does not expose ok/error/status.

Fixed route now uses:

- const userContext = await getActivityUserContext();
- const { appUser, personActor } = userContext;
- if (!appUser || !personActor) return 401
