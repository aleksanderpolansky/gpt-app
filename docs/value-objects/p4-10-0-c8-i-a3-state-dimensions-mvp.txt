## 1. Purpose

This document defines the first stable MVP set of state dimensions for GPT-APP / AI-NAVIGATOR.

The goal is to prepare the platform for:

- state facts,
- state deltas,
- state snapshots,
- weakest direction detection,
- Next Best Action v0,
- similarity/relevance resolver.

This step does NOT implement state tables.

This step only defines which dimensions are allowed in the first MVP scope and how they should be interpreted safely.

## 2. Core principle

State dimensions are not Value Object subtypes.

A Value Object remains unified.

State dimensions describe measurable, inferred or proxy aspects of a Value Object, actor, direction, context or baseline graph.

Correct model:

Unified Value Object
+ category signature
+ parent/child hierarchy
+ actor context
+ state dimensions
+ state facts/deltas/snapshots
+ similarity/relevance edges

Incorrect model:

Different Value Object subtype for every state domain.

## 3. MVP dimension groups

The first MVP state dimensions are grouped into seven domains:

1. Energy / fatigue / recovery.
2. Focus / cognitive load.
3. Emotional / stress proxy.
4. Physical load / mobility / pain signal.
5. Family / care load.
6. Finance / career pressure.
7. Goal balance / overfocus / underattention.

These groups are enough to support the first Next Best Action v0 logic:

weakest direction
-> user chooses direction
-> action candidates
-> feedback/correction

## 4. Dimension status types

Each dimension can have one of these implementation statuses:

### MVP_READY

Safe enough to include in first state dimension dictionary.

### MVP_PROXY_ONLY

Can be used only as proxy, not as direct fact.

### MVP_REQUIRES_SOURCE

Requires direct measurement, user input, calendar, wearable, transaction or another source.

### LATER

Useful but not needed in the first MVP.

### BLOCKED_AS_DIRECT_CLAIM

Cannot be used as direct factual dimension without strong source and claim policy.

## 5. Unit types

Allowed MVP unit types:

- numeric_0_100
- numeric_1_5
- minutes
- count
- boolean
- enum
- qualitative_low_medium_high
- json_value
- score
- ratio
- currency
- unknown

A dimension must declare its unit type before it can be used in future SQL/schema design.

## 6. Privacy levels

Every dimension must have a default privacy level.

Suggested levels:

- public_safe
- user_private
- sensitive_personal
- sensitive_health
- sensitive_family
- sensitive_financial
- sensitive_work
- sensitive_child_related

Default rule:

State dimensions are private unless explicitly designed otherwise.

## 7. Claim policy types

Each dimension must have a claim policy.

Allowed policy types:

- direct_fact_allowed
- proxy_only
- user_confirmation_required
- source_required
- sensitive_proxy_only
- forbidden_without_medical_source
- forbidden_without_transaction_source
- forbidden_without_user_feedback

## 18. Weakest direction MVP formula

Weakest Direction v0 may use these state dimensions:

- goal_attention_score;
- underattention_score;
- overdue_direction_score;
- overfocus_score;
- fatigue_level;
- recovery_need;
- focus_readiness;
- family_care_load;
- financial_pressure;
- job_search_attention;
- income_action_attention.

Initial conceptual formula:

direction_score =
underattention_score
+ deterioration_score
+ overdue_direction_score
+ goal_priority_weight
+ financial_or_family_pressure_if_relevant
- overfocus_score
+ availability_fit

The output is an ordered list of directions from weakest to strongest.

The system then asks the user:

"Какое направление сейчас отрабатываем?"

## 21. Anti-errors

Do NOT:

- add VO subtypes;
- create SQL migrations;
- create state tables now;
- write runtime state engine;
- treat proxy dimensions as facts;
- treat AI output as state fact;
- create medical/hormonal direct claims;
- rank user socially;
- infer family quality;
- infer child development outcomes;
- treat business effort as confirmed revenue;
- merge similarity and relevance;
- start UI before backend/data contracts.
