WHY THIS PROOF WAS NEEDED

The normal endpoint /api/activity/complete cannot fully prove routeRunner adapter idempotency.

Reason:
- first POST completes the event and runs the full pipeline;
- second POST for the same event returns already_completed;
- already_completed skips the full pipeline;
- therefore the second POST does not re-enter the routeRunner adapter.

The new debug route solves this by calling:

runCategoryDerivationForCompleteRoute

directly twice for the same non-completed activity_event.

ARCHITECTURAL MEANING

Before this proof:
shadow_persist worked through /api/activity/complete, but repeated complete-route POST could not prove adapter idempotency because of the already_completed early return.

After this proof:
The Category Derivation complete-route adapter itself has a verified idempotency path:
- it checks for an existing completed routeRunner run;
- it returns existing_completed_run_found;
- it avoids duplicate persistence.

This reduces the risk of enabling a future production-like persistence mode, but does not yet mean production_persist should be enabled.

IMPORTANT LIMITATION

The proof is debug-route based.
It proves adapter idempotency outside the complete-route lifecycle early return.

It does not yet prove:
- production_persist rollout safety;
- Value Object Bridge migration to routeRunner-derived category rows;
- failure behavior when persistence errors occur;
- whether routeRunner failure should block activity completion;
- final removal of legacy Category Derivation logic.
