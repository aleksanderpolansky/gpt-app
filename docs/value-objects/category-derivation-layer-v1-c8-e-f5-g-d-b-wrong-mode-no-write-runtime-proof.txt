WHY THIS PROOF WAS NEEDED

The previous validation-failure proof confirmed that the adapter can safely handle a controlled missing activityEvent.id validation failure when the server is correctly running in shadow_persist mode.

This proof checks a different safety boundary:

wrong server mode.

The debug route is intended to run only when the local dev server is explicitly configured for:

CATEGORY_DERIVATION_ROUTE_RUNNER_MODE=shadow_persist

If the server is in disabled mode, the debug route must refuse before calling the adapter.

This proves:
- no accidental adapter execution;
- no routeRunner execution;
- no DB write path reached;
- no misleading success status;
- no production_persist.

ARCHITECTURAL MEANING

This is an important rollout safety proof.

The debug failure route is protected by server-side mode validation. It will not accidentally execute adapter tests just because the browser request asks for shadow_persist.

This reduces the risk of:
- accidental persistence in disabled mode;
- accidental routeRunner execution during ordinary development;
- confusing debug output when the server is not configured for the intended test.
