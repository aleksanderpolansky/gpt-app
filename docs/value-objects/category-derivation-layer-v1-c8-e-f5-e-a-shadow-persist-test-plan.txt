IDEMPOTENCY RISK

The complete route endpoint changes event status to completed.
A repeated POST for the same event normally returns already_completed and skips the full pipeline.

Therefore, idempotency should not be tested by simply calling /api/activity/complete twice on the same completed event.

Safer idempotency checks for F5-E:
1. Verify that the first shadow_persist call creates exactly one routeRunner-specific run.
2. Verify that no duplicate routeRunner-specific completed runs exist for the same activity_event_id.
3. Defer advanced idempotency testing to a later controlled debug endpoint or direct adapter test where the same event can be processed without the complete-route lifecycle early return.

Do not force-reset the completed event back to started just to test idempotency unless a separate controlled plan is created.
