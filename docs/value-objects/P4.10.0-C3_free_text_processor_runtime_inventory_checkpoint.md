## Runtime finding

The existing known-template pipeline is already reusable:

1. Activity routes create/update activity_events.
2. Routes call ensureActivityEventRubricatorClassificationForKnownTemplate.
3. That lifecycle creates or reuses entity_classifications for known templates.
4. Routes call processActivityValueObjectBridge.
5. activityValueObjectLifecycle calls rubricatorValueObjectMapper.
6. activityValueObjectLifecycle then calls valueObjectBridge.
7. valueObjectBridge writes legacy and v4.2 projections.

## Existing v4.2 projection support

valueObjectBridge already writes/updates:

- activity_event_value_object_links
- value_object_usage_aggregates
- value_object_category_links
- value_object_instances
- value_object_state_deltas
- value_object_daily_aggregates
- value_object_state_snapshots

Therefore valueObjectBridge is not the first place to change for free-text v1.

## Main design conclusion

Free-text v1 should be added above the bridge layer.

The likely minimal change is in the classification/mapping layer:

- known-template path remains unchanged;
- unknown/free-text input_text receives a simple deterministic or manual-review classification/mapping path;
- the existing bridge should consume resulting mappings and continue writing projections.

## Important guardrails

- Do not create new schema now.
- Do not rewrite valueObjectBridge first.
- Do not break known-template flows.
- Do not introduce typed relation edges.
- Do not introduce tags/entity_tags.
- Do not build full UI/UX now.
- Keep existing routes stable: record, complete, confirm.
