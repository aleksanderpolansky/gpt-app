WHY THIS STEP IS NEEDED

F5-E proved that shadow_persist works through /api/activity/complete.

However, /api/activity/complete cannot fully prove routeRunner adapter idempotency because the complete route lifecycle changes the activity_event status to completed.

Current complete route behavior:
1. First POST completes the event and runs the full pipeline.
2. Second POST for the same event normally returns already_completed.
3. The already_completed branch skips the full pipeline.
4. Therefore the second call does not re-enter the routeRunner adapter path.

Conclusion:
Idempotency cannot be proven by calling /api/activity/complete twice on the same completed event.

GOAL OF F5-F-B

Design a controlled proof that calls the Category Derivation complete-route adapter directly, outside the complete-route lifecycle early return.

The proof must show:

First adapter call:
- creates exactly one routeRunner-specific category_derivation_runs row;
- creates exactly five activity_category_derivations rows for walked to work for 15 minutes;
- returns reason = route_runner_completed;
- returns non-null derivationRunId;
- returns persistenceDerivationRowsCreated = 5.

Second adapter call with the same activity_event_id:
- detects the existing completed routeRunner run;
- does not create another category_derivation_runs row;
- does not create duplicate activity_category_derivations rows;
- returns reason = existing_completed_run_found;
- returns the same derivationRunId;
- returns persistenceDerivationRowsCreated = 0.

DATABASE FINAL STATE:
- exactly one routeRunner-specific completed category_derivation_runs row exists for the event;
- exactly five activity_category_derivations rows exist for that routeRunner derivation_run_id;
- no duplicate completed routeRunner run exists for the same activity_event_id.
