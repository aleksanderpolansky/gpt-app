3. Decision summary

Decision:

Proceed with a minimal additive semantic coverage patch focused first on family/childcare role semantics.

First implementation target:

- B1 учил математику с ребёнком
- B2 ребёнок учил математику рядом со мной
- F1 I was with my child while they did homework

Reason:

These cases prove the most important semantic distinction that the user explicitly identified:

- active teaching
- passive supervision
- family duty
- childcare / parental care / caregiving
- helping child learn
- ambiguity preservation

4. What must not happen

The system must not flatten these activities into only:

- math
- child
- learning
- family

This is technically insufficient.

The required layer is:

- role / duty / responsibility / care / purpose

11. Governance decision

Decision:

If a category slug is missing in the current seed/resolver support, the patch should not block the pipeline.

Preferred behavior:

- use existing suggested / needs_review / draft governance if available
- otherwise add deterministic fallback in the benchmark route/report, without schema change
- document missing seed as a seed gap for later patch

Do not create broad automatic public categories without review.

12. Resolver strategy decision

Decision:

Do not change resolver semantics broadly until the exact current resolver file is inspected.

The next step must identify the exact files for patching.

Likely patch surfaces:

- candidate-to-category resolver
- category seed/migration files
- benchmark/debug test route
- Value Object Bridge category link consumption only if needed

13. Benchmark route decision

Decision:

Before patching production behavior, create or inspect a dedicated benchmark/debug route or script for deterministic semantic coverage.

Purpose:

- run B1/B2/F1 without OpenAI
- show candidate slugs
- show resolved/unresolved categories
- show ambiguity markers
- show whether Value Object Bridge can consume the resolved categories
- avoid normal user activity pollution

The benchmark route must not require SQL in PowerShell.

14. OpenAI decision

Decision:

Do not use OpenAI for C8-F-D/E deterministic proof.

Reason:

The deterministic baseline must be stable before AI-assisted interpretation is added.

OpenAI can later improve recall and natural-language nuance, but the platform must first have a deterministic semantic contract.

19. Risk notes

Risk 1:

If the current resolver only resolves pre-seeded slugs, new role/care/purpose candidates may remain unresolved.

Mitigation:

Treat unresolved candidates as expected output and document seed gap.

Risk 2:

If the Value Object Bridge only consumes resolved categories, unresolved care/purpose candidates may not influence VO links yet.

Mitigation:

Keep the first proof focused on candidate extraction and resolution visibility.

Risk 3:

If the deterministic extractor uses English-only patterns, Russian B1/B2 may require explicit Russian phrase handling.

Mitigation:

Add narrow Russian deterministic patterns only for B1/B2 first.

Risk 4:

If category governance is missing, do not invent broad governance in this patch.

Mitigation:

Record missing governance and plan a separate governance block.
