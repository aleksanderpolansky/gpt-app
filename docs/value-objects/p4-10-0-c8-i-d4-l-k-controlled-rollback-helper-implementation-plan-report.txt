Required ownership/permission sequence:
1. Resolve authenticated user.
2. Resolve app user/person/actor context.
3. Resolve target Value Object by valueObjectId.
4. Verify actor/owner permission.
5. Load target state fact by stateFactId + valueObjectId.
6. Reject if state fact does not belong to target VO.
7. Reject if state fact already has correction_status = rolled_back/superseded/corrected/invalid if those statuses are defined.
8. Check rollback idempotency.
9. Build update payload.
10. Build audit payload.
11. Execute state fact update + audit insert in safe server-side sequence.
12. Return deterministic result.

Required proof cases:
1. Missing auth -> rejected_not_authenticated.
2. Placeholder UUID -> rejected_invalid_input.
3. Missing reason -> rejected_invalid_input.
4. Wrong valueObjectId -> rejected_value_object_mismatch.
5. Wrong user / non-owner actor -> rejected_not_owner.
6. Already rolled back -> already_rolled_back or deterministic idempotent result.
7. Same idempotency key repeated -> no duplicate audit events.
8. Successful rollback -> state fact correction_status changes; valid_to set; audit event inserted.
9. Audit event references same value_object_id, state_fact_id, dimension_key.
10. State fact value_json/evidence/source/dimension fields unchanged.
11. No delete/upsert.
12. No generic state_fact_id-alone update.

- postpone runtime rollback until a transaction-safe RPC is designed.
This decision must be explicit before production rollback.
