## Architectural conclusion

The parent/child schema is present but not yet populated.

The current object-cloud read model can already be extended with parent/child fields because:

- value_objects.parent_value_object_id exists;
- value_object_cloud_profiles_v1 exposes value_object_id;
- joining the cloud profile to value_objects works;
- root/child classification can be computed read-only.

## Important interpretation

No hierarchy currently exists in data.

This is expected because previous P4.9 blocks focused on:

- runtime projection
- usage aggregates
- category links
- cloud read view
- API
- UI
- debug/security guard

P4.9.11 confirms readiness for the next layer, not that hierarchy already exists.

## Recommended next step

P4.9.12 should decide how to introduce controlled parent/child data.

Safe options:

1. create a read-only hierarchy view first, even with empty child data;
2. create a controlled SQL seed/test for one parent/child relation;
3. add a debug-only hierarchy endpoint after the hierarchy model is verified;
4. postpone writing parent/child data and first document the hierarchy rules.
