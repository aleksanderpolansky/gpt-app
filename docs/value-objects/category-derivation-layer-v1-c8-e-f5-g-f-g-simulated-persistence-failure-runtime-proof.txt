1. Purpose

This proof documents the runtime behavior of the Category Derivation complete-route adapter when a persistence-layer failure is simulated safely before real DB run creation.

The tested scenario is:

- endpoint:
  /api/activity/debug/category-derivation-complete-route-adapter-failure-test

- scenario:
  simulated_persistence_failure

- mode:
  shadow_persist

- failActivityComplete:
  false

The purpose is to prove that the adapter and routeRunner can handle a controlled persistence-boundary failure as a non-blocking result when failActivityComplete=false, without corrupting data and without modifying the production complete route.

4. Implementation summary

The implementation adds a debug-only simulated persistence failure path.

The debug failure route now supports:

- missing_activity_event_id
- missing_actor_id
- simulated_persistence_failure

For simulated_persistence_failure:

- the debug route passes adapterMetadata.simulatePersistenceFailure = "before_run_create";
- routeRunner reads this flag from metadata, including nested adapter metadata;
- routeRunner stops before createCategoryDerivationRun;
- routeRunner returns a failure result with error "simulated_persistence_failure";
- completeRouteIntegration normalizes this into adapterResult.reason = "simulated_persistence_failure";
- because failActivityComplete=false, adapterResult.ok remains true;
- no derivation run is created;
- no activity category derivation rows are created.

5. Important correction during implementation

Initial runtime test showed that the simulation flag did not reach routeRunner at the expected metadata depth.

Observed initial failed runtime result:

- adapterResult.ok: true
- adapterResult.skipped: false
- adapterResult.reason: route_runner_failed
- adapterResult.errors: ["category_derivation_run_create_failed"]
- routeRunner.executed: true
- persistenceDerivationRowsCreated: 0
- safety flags: all safe

Diagnosis:

- the simulation flag was nested deeper than the helper originally checked;
- routeRunner was checking direct metadata and adapterMetadata;
- actual metadata nesting included deeper paths.

Correction:

- routeRunner helper was expanded to check:
  - direct simulatePersistenceFailure
  - direct adapterMetadata.simulatePersistenceFailure
  - nested metadata.simulatePersistenceFailure
  - nested metadata.adapterMetadata.simulatePersistenceFailure

After this correction, runtime proof passed.

8. What this proof demonstrates

This proof demonstrates that in shadow_persist mode with failActivityComplete=false:

- the adapter is enabled;
- routeRunner executes;
- derivation candidates are produced;
- the simulated persistence failure occurs before real run creation;
- the failure is normalized as simulated_persistence_failure;
- the adapter remains non-blocking;
- no category_derivation_runs row is created;
- no activity_category_derivations rows are created;
- no production_persist is enabled;
- OpenAI is not called;
- schema, migrations, RLS and permissions are not modified;
- /api/activity/complete remains unchanged.

9. Anti-regression notes

Do not simulate persistence failure by damaging the real DB.

Do not use DROP, ALTER TABLE, broken RLS, broken permissions or schema corruption for this proof type.

Do not rely only on raw exception messages.

The stable signal for this simulated failure is:

- adapterResult.reason = "simulated_persistence_failure"

The routeRunner error array may contain:

- "simulated_persistence_failure"

The first safe proof intentionally uses zero created rows.
