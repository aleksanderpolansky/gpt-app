4. Transition question

The next transition question is:

Can we safely move from debug-only failure proofs toward a controlled complete-route shadow_persist proof, without changing production behavior and without repeating already completed canonical proof work unnecessarily?

This must be answered by inspection first, not by immediate runtime code changes.

5. F6 block objective

The objective of F6 is to decide and implement the smallest safe transition after F5-G.

Possible direction:

- inspect current complete route integration;
- verify that complete route behavior can be observed in shadow_persist;
- decide whether a new controlled complete-route proof is needed;
- avoid canonical proof repetition unless the next proof gives new information;
- preserve all F5-G anti-regression rules.

9. Anti-regression rules inherited from F5-G

Stable failure signals:

- missing_activity_event_id
- missing_actor_id
- simulated_persistence_failure

Do not rely only on raw error messages.

Use normalized adapterResult.reason as the primary signal.

Do not generalize strict debug-route guard exceptions to other scenarios without separate proof.

Do not simulate DB failure by damaging the real DB.
