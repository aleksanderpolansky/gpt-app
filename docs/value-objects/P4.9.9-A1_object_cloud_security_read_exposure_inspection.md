## Preliminary findings to verify

### Positive controls already visible in code

- API endpoint uses auth0.getSession().
- API endpoint returns 401 when no Auth0 session exists.
- API endpoint looks up app_users by auth0_sub.
- API endpoint filters value_object_cloud_profiles_v1 by user_id = current app user id.
- API endpoint validates valueObjectId as UUID.
- UI page uses GET fetch only.
- UI page calls the debug API, not the database directly.

### Main security concern

- The endpoint uses the shared Supabase client from lib/supabase.
- If that client uses SUPABASE_SERVICE_ROLE_KEY, RLS is bypassed at the database layer.
- Therefore the TypeScript user_id filter is currently the main ownership boundary for this debug endpoint.

### Recommended production decision

- Keep /api/value-objects/debug/cloud-profile and /value-objects/debug/cloud-profile debug/admin-only until a formal exposure policy is decided.
- Do not add the page to public navigation yet.
- Before production exposure, either add an explicit admin/dev guard or switch to an RLS-respecting user-scoped Supabase client pattern.
