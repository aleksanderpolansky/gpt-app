- Personal Value Objects should only allow the owner/user context.
- Enterprise/organization Value Objects need organization/actor permission logic.
- Public/catalog visibility must not imply state-fact write permission.

7. Recommended helper reuse / new helper map
============================================================

Future helper contract should be split as follows:

7.1 resolveAuthenticatedStateFactActor
- Reuse Auth0/session conventions.
- Reuse or extract logic from activityUserContext and sync-user mapping.
- Must reject placeholder UUIDs.
- Must not trust client-provided user_id.

7.2 resolveStateFactTargetValueObject
- New dedicated resolver is required.
- It should inspect value_objects ownership/access fields.
- It should not treat public visibility as write permission.

7.3 resolveStateFactDimension
- New dedicated resolver is required.
- It should load state_dimensions server-side.
- It should reject unknown/inactive dimensions.

7.4 validateStateFactCandidateAgainstContract
- New dedicated validator is required.
- It should re-run D4-C / D4-F-A gates.
- It should block AI-only direct persistence.
- It should block forbidden overclaims.

7.5 buildValueObjectStateFactInsertPayload
- New dedicated payload builder is required.
- It should match existing value_object_state_facts constraints from D4-B.
- It should always include rollback/correction metadata.

7.6 checkStateFactIdempotency
- New dedicated idempotency check is required before insert.
- Final strategy remains to be chosen in a later step.

7.7 persistStateFactControlled
- Final insert helper should exist only after the above gates are implemented.
- It must be server-only.
- It must be covered by before/after count proof tests.
