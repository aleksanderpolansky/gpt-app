# P4.9.1-A7 — first v4.2 runtime projection implementation plan

Date: 2026-05-18
Status: READY FOR CODE CHANGE

## Decision

The first runtime integration point is:

- lib/activity/valueObjectBridge.ts

## Why this file

P4.9.1-A6 confirmed that valueObjectBridge.ts already has the required runtime data in one hot path:

- event.user_id
- event.id
- event.duration_minutes
- mapping.valueObjectId
- valueObjectInstanceId
- existing activity_event_value_object_instance_links insert/upsert
- value_object_daily_aggregates upsert
- value_object_state_snapshots upsert

## Implementation target

Add a small additive helper in valueObjectBridge.ts after the existing VOI link succeeds.

The helper should populate:

1. public.activity_event_value_object_links
2. public.value_object_usage_aggregates

## activity_event_value_object_links logic

Insert/upsert by unique key:

- event_id
- value_object_id
- source

Fields:

- user_id = event.user_id
- event_id = event.id
- value_object_id = mapping.valueObjectId
- exposure_minutes = event.duration_minutes ?? 0
- source = rule/bridge-compatible source
- confidence = mapping.confidence or 1
- metadata_json = minimal audit metadata

## value_object_usage_aggregates logic

Upsert by unique key:

- user_id
- value_object_id

Fields:

- usage_count += 1
- exposure_minutes += event.duration_minutes ?? 0
- first_used_at = existing first_used_at or event.started_at or now
- last_used_at = event.ended_at or event.started_at or now
- last_event_id = event.id
- source = rule
- metadata_json = minimal audit metadata

## Compatibility rules

Do not:

- remove activity_event_value_object_instance_links
- change relation_type logic
- change value_object_instances creation
- change value_object_daily_aggregates
- change value_object_state_snapshots
- create value_object_category_links in this step
- change API routes yet

## Error handling

If v4.2 projection insert/upsert fails, the old VOI pipeline should not be rolled back at application level.

Recommended behavior:

- log warning in processing logs / console if current pattern supports it
- continue returning existing bridge result
- use post-check SQL to catch projection failures

## Test target

After code change:

1. run npx.cmd tsc --noEmit
2. create or confirm one known-template test activity
3. verify old VOI link exists
4. verify new activity_event_value_object_links row exists
5. verify value_object_usage_aggregates row exists
6. verify existing daily aggregates and snapshots still exist
