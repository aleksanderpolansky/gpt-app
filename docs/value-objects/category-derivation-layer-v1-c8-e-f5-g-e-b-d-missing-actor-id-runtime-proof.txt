1. Purpose

This proof documents the runtime behavior of the Category Derivation complete route adapter when actorId is intentionally missing.

The tested scenario is:

- endpoint:
  /api/activity/debug/category-derivation-complete-route-adapter-failure-test

- scenario:
  missing_actor_id

- mode:
  shadow_persist

- failActivityComplete:
  false

The purpose is to prove that the adapter handles missing actor id as a controlled non-blocking validation skip when failActivityComplete=false, without executing routeRunner and without creating Category Derivation persistence artifacts.

4. Implementation summary

The failure debug route now supports two validation scenarios:

- missing_activity_event_id
- missing_actor_id

For missing_actor_id, the route:

- builds a synthetic debug activity event with a stable non-empty activityEvent.id;
- intentionally passes an empty actorId to runCategoryDerivationForCompleteRoute;
- expects adapterResult.reason = "missing_actor_id";
- expects adapterResult.ok = true when failActivityComplete=false;
- expects adapterResult.skipped = true;
- expects no derivation run id;
- expects no candidates and no resolved candidates;
- expects no category derivation rows;
- expects routeRunner not to execute;
- checks safety flags to ensure no production or schema side effects.

The original too-strict validation expected an actor-related error string in adapterResult.errors. Runtime showed that adapterResult.errors can be empty while adapterResult.reason correctly reports missing_actor_id. Therefore the debug-route validation harness was relaxed to accept result.reason as the validation signal.

7. What this proof demonstrates

This proof demonstrates that in shadow_persist mode with failActivityComplete=false:

- missing actor id does not crash the complete-route adapter;
- missing actor id does not execute routeRunner;
- missing actor id does not create category_derivation_runs;
- missing actor id does not create activity_category_derivations;
- missing actor id does not call OpenAI;
- missing actor id does not enable production_persist;
- missing actor id does not modify schema or permissions;
- missing actor id returns a controlled adapter skip with reason missing_actor_id;
- the debug failure harness can verify validation by adapterResult.reason, not only by adapterResult.errors.

8. Anti-regression notes

Do not reintroduce the old assumption that validation failure must always populate adapterResult.errors.

For this adapter contract, reason is the primary validation signal for these skip cases:

- missing_activity_event_id
- missing_actor_id

The errors array may be empty when the adapter has already normalized the failure into a controlled reason.
