## Interpretation

The live DB inventory and local code inventory show that the project already has an Activity + Category + Value Object foundation.

The v4.2 work should therefore be additive and compatibility-preserving:

- do not delete existing value_objects / value_object_instances tables;
- do not remove activity_event_value_object_instance_links now;
- do not make relation_type the central semantic model for v4.2;
- add a clear category-to-ValueObject bridge;
- add or introduce an event-to-ValueObject exposure projection with exposure_minutes;
- keep Activity Event as source of truth for real time;
- keep parent/child as the only base hierarchy relation for MVP;
- keep free text as the first input source;
- do not start full UI/UX yet.

## Preliminary target for next migration design

The next design block should prepare a minimal additive schema with:

1. value_object_category_links
2. event-to-value-object exposure projection
3. parent_value_object_id on value_objects or an equivalent parent/child-only structure
4. entity_protocol_characteristics_json on value_objects
5. needs_user_review as interface/moderation flag
6. object cloud support through usage_count / exposure_minutes aggregates
