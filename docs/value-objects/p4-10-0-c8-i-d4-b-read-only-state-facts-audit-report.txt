value_object_state_facts Constraints
------------------------------------
Confirmed constraints include:

- primary key on id
- user_id FK to app_users(id) ON DELETE CASCADE
- value_object_id FK to value_objects(id) ON DELETE CASCADE
- dimension_id FK to state_dimensions(id) ON DELETE SET NULL
- confidence range: 0..1
- claim_strength range: 0..5
- dimension_key not blank
- value_json must be json object
- evidence_json must be json object
- metadata_json must be json object
- privacy_level limited to:
  private, shared_with_org, public_masked, public
- source_type limited to:
  manual, user_confirmed, rule, ai, system, import, correction
- correction_status limited to:
  active, corrected, revoked, superseded
- valid time order check:
  valid_to must be null or valid_from must be null or valid_to >= valid_from

Assessment:
DB constraints provide a good structural safety foundation, but semantic governance
cannot be fully enforced by table constraints alone. Claim policy, source policy,
forbidden overclaims and safe wording must be enforced by the future controlled
internal creation path.

WARN / CONTRACT GAPS:
1. dimension_id is nullable while dimension_key is required.
   D4-C must define a consistency rule:
   - lookup state_dimensions by dimension_key;
   - if found, store dimension_id;
   - if missing, reject unless a future explicit draft-dimension mechanism is approved.

2. source_id is generic uuid without direct FK.
   D4-C must define source_type/source_id semantics and evidence requirements.

3. claim_policy is not enforced by DB constraints.
   D4-C must enforce dimension claim policy before insert.

4. forbidden overclaims are not enforceable by DB constraints.
   D4-C must define forbidden claim rejection before persistence.

5. privacy/sensitivity inheritance from state_dimensions is not automatically enforced.
   D4-C must require privacy_level to be compatible with state_dimensions.default_privacy_level
   and is_sensitive.

6. no runtime persistence path should be implemented yet.
   D4-C must come first.
