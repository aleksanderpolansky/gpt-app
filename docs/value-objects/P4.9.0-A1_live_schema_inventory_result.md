# P4.9.0-A1 — Category-Derived Value Object Foundation live schema inventory

Date: 2026-05-18
Status: DONE

## Purpose

P4.9.0-A1 inspected the live Supabase schema before designing the v4.2 Category-Derived Value Object Foundation.

The goal was to identify existing tables for:

- value objects
- value object instances
- activity events
- category / rubricator structures
- event links
- aggregates
- snapshots
- routines and views

## Existing value_objects shape

Current value_objects fields include:

- id
- owner_actor_id
- value_type
- title
- description
- unit_type
- default_price
- default_currency
- default_duration_minutes
- is_marketplace_sellable
- is_free_possible
- status
- organization_id
- commercial_usage
- created_at
- updated_at

This is useful for commercial and generic Value Object storage, but it is not yet the full v4.2 category-derived model.

## Existing value_object_instances shape

Current value_object_instances fields include:

- user_id
- value_object_id
- source_event_id
- owner_actor_id
- organization_id
- status
- started_at
- ended_at
- duration_minutes
- instance_title
- instance_note
- result_status
- quality_score
- confidence
- source
- metadata_json

This table already connects a user and source event with a value object instance.

## Existing activity_event_value_object_instance_links shape

Current link table fields include:

- user_id
- event_id
- value_object_instance_id
- relation_type
- weight
- confidence
- source
- metadata_json

Important mismatch with v4.2:

- it links events to value_object_instances, not directly to value_objects
- it has relation_type
- it does not have exposure_minutes

## Existing category layer

contextual_categories already has:

- context_id
- parent_id
- slug
- name
- description
- status
- source_type
- sort_order
- is_active

object_action_contextual_categories connects object-action affordances with contextual categories.

This layer can serve as the initial global category/rubricator material for v4.2, but it still needs a clear bridge to user/enterprise Value Objects.

## A1 conclusion

The database already contains a strong Activity + Category + Value Object foundation.

However, v4.2 should be implemented as an additive compatibility layer, not by deleting the existing layer.

P4.9.0-A1 is complete.
