## 1. Purpose

This document maps existing semantic category bundles to future state/context hooks.

The purpose is NOT to create state facts yet.

The purpose is to answer:

- which existing categories can already act as state/context hooks;
- which hooks are ready enough for future contracts;
- which hooks need more evidence, metrics, source data or user feedback;
- which overclaims must remain forbidden;
- which areas are missing prerequisites before SQL/state implementation.

This step prepares C8-I-A2: State Fact vs Signal Contract.

## 2. Core rule

A category or category bundle can become a hook, signal, metric candidate, risk flag or relevance clue.

But it must NOT automatically become a state fact.

Correct chain:

Activity Event
-> Category Derivation Run
-> categoryCandidates
-> resolved contextual categories
-> hook candidates
-> fact/signal contract
-> future state deltas/snapshots

Incorrect chain:

categoryCandidate
-> automatic state fact

## 3. Hook readiness statuses

Use the following readiness statuses:

### READY_AS_HOOK

The category bundle is already semantically stable enough to be used as a hook candidate.

It still does not write state facts directly.

### PARTIAL

The category bundle is useful, but requires more context, metrics or evidence before stable use.

### NEEDS_CONTRACT

The category bundle is important, but must wait for the A2 fact/signal contract.

### NEEDS_SOURCE_DATA

The category bundle cannot be interpreted reliably without external/direct data, for example wearable, lab result, calendar, user correction or manual measurement.

### FORBIDDEN_AS_FACT

The category bundle may only be used as a proxy or risk flag. Direct factual claim is forbidden.

## 23. Anti-errors

- create state facts directly from AI output;
- create active ontology entries automatically without governance;
- treat state hooks as medical facts;
- merge similarity and relevance;
- replace parent/child hierarchy with influence edges;
- introduce VO subtypes;
- start UI before data contracts;
- repeat C8-H proofs unless ruleExtractor.ts changes;
- run /api/activity/complete for old canonical proof;
- run OpenAI or Supabase SQL during this doc-only step.
