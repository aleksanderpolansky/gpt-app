Exact route path:

- /api/activity/debug/category-derivation-controlled-production-persist-proof

Exact file path:

- src/app/api/activity/debug/category-derivation-controlled-production-persist-proof/route.ts

This route must be debug-only, authenticated, proof/test-only and non-canonical.

5. Route implementation concept

Preferred implementation concept:

Self-contained controlled proof route.

The route should create its own proof activity_event internally and then run the Category Derivation adapter against that proof event.

Reason:

- avoids relying on the current create-free-text-start-event route as-is;
- guarantees required proof metadata markers are present;
- avoids mixing proof setup with normal business activity setup;
- makes cleanup eligibility explicit;
- keeps /api/activity/complete untouched.

6. Request payload

The route should accept POST JSON only.

Planned request payload:

{
  "proof": "P4.10.0-C8-E-F6-E-controlled-production-persist-proof",
  "mode": "production_persist",
  "callTwice": true,
  "inputText": "walked to work for 10 minutes during controlled production persist proof",
  "title": "F6-E controlled production_persist proof",
  "durationMinutes": 10
}

Required fields:

- proof
- mode
- callTwice

Optional fields:

- inputText
- title
- durationMinutes

Default values should be used if optional fields are omitted.

7. Request validation

The route must reject the request if:

- method is not POST;
- user is not authenticated;
- proof is not exactly P4.10.0-C8-E-F6-E-controlled-production-persist-proof;
- mode is not exactly production_persist;
- callTwice is not true;
- durationMinutes is invalid;
- inputText is empty after defaulting;
- title is empty after defaulting.

8. Environment requirements for later runtime proof

The later runtime proof must run only when the dev server is explicitly started with:

- CATEGORY_DERIVATION_ROUTE_RUNNER_MODE=production_persist
- CATEGORY_DERIVATION_ROUTE_RUNNER_FAILS_ACTIVITY_COMPLETE=false
- CATEGORY_DERIVATION_ROUTE_RUNNER_INCLUDE_RESPONSE_DEBUG=false

The route must verify in the response safety object that:

- config.mode is production_persist;
- config.isProductionPersistMode is true;
- config.shouldPersist is true;
- config.shouldResolve is true;
- config.failActivityComplete is false.

10. Adapter call requirements

The route must call:

- runCategoryDerivationForCompleteRoute

The route must not call routeRunner directly.

The route must not call /api/activity/complete.

The route must use completeRouteIntegration adapter-level idempotency.

The route must run:

- first adapter call;
- second adapter call when callTwice=true.

Expected first call:

- ok=true
- reason=route_runner_completed
- derivationRunId exists
- persistenceDerivationRowsCreated > 0
- routeRunner executed
- rows persisted

Expected second call:

- ok=true
- reason=existing_completed_run_found
- derivationRunId equals first derivationRunId
- persistenceDerivationRowsCreated=0
- routeRunner skipped
- no duplicate rows created
