4. Core decision

Decision:

Adapter-level idempotency is sufficient for the current completeRouteIntegration path.

This means:

- /api/activity/complete integration can rely on completeRouteIntegration adapter-level runLookup protection;
- repeated adapter calls for the same event and version tuple do not create duplicate completed runs;
- the second adapter call skips routeRunner and returns the existing derivationRunId;
- routeRunner-level idempotency is still absent, but it is not required before the next narrow production-readiness planning step as long as production-facing callers do not bypass completeRouteIntegration.

6. RouteRunner-level idempotency decision

Decision:

Do not implement routeRunner-level idempotency now.

Reason:

- adapter-level idempotency is proven for the current completeRouteIntegration path;
- immediate routeRunner modification would be architectural churn without current necessity;
- routeRunner should remain the lower-level derive/resolve/persist executor for now;
- routeRunner-level idempotency should be reconsidered only if a real production caller bypasses completeRouteIntegration or if future design requires routeRunner as a public production API boundary.

7. Production-readiness implication

The adapter-level idempotency proof removes the previous hard blocker identified in F6-E-B for the completeRouteIntegration path.
