4. Runtime proof goal

The goal of the runtime proof is to verify that production_persist can persist Category Derivation rows through the completeRouteIntegration adapter in a controlled, proof-marked, cleanup-eligible way.

The proof must verify:

- proof event is created
- proof event has required metadata markers
- first adapter call creates one derivation run
- first adapter call persists derivation rows
- second adapter call finds the existing completed run
- second adapter call does not persist duplicate rows
- same derivationRunId is returned by both calls
- dbVerification.pass is true
- safety object confirms no /api/activity/complete call
- safety object confirms no SQL in PowerShell
- safety object confirms no OpenAI call

5. Required environment for runtime proof

The dev server must be started explicitly with these environment settings:

CATEGORY_DERIVATION_ROUTE_RUNNER_MODE=production_persist
CATEGORY_DERIVATION_ROUTE_RUNNER_FAILS_ACTIVITY_COMPLETE=false
CATEGORY_DERIVATION_ROUTE_RUNNER_INCLUDE_RESPONSE_DEBUG=false

The route response must confirm:

- config.mode is production_persist
- config.isProductionPersistMode is true
- config.shouldPersist is true
- config.shouldResolve is true
- config.failActivityComplete is false
- config.includeResponseDebug is false

15. Failure handling

If the runtime proof fails, do not run cleanup immediately.

First capture:

- full browser console output
- HTTP status
- full JSON response
- git status --short
- current dev server environment variables
- whether the user was authenticated
- whether the route returned 401, 409, 500, or another status
- firstCall object if present
- secondCall object if present
- dbVerification object if present
- safety object if present

Then document the failure before making changes.

16. Cleanup handling after successful proof

Even after a successful runtime proof, cleanup must not be executed automatically.

First document the proof result.

Then decide separately whether cleanup is needed.

If cleanup is needed, create a separate reviewed cleanup SQL document.

No SQL may be executed in PowerShell.
