# ARCTor.app — CUX6 Task Shelf

Дата: 2026-07-29
Базовая точка: `main @ 2a00f9e43ee2af8bcbe9e9ee92f2dd923f5c175a`

## Цель

Добавить над календарём компактную полку плановых активностей, которые не должны теряться только потому, что у них нет почасовой календарной проекции.

Полка содержит три группы:

1. **Без даты** — плановые `activity_events` с `schedule_mode_code = unscheduled`.
2. **Срок скоро** — плановые активности с режимом `date_only`, `date_range` или `deadline`, срок которых наступает в ближайшие 7 дней.
3. **Нужно уточнение** — плановые активности, у которых последний semantic enrichment run имеет статус `needs_clarification`.

## Источник данных

Полка читает непосредственно `public.activity_events`.

Она не строится только по `calendar_events`, потому что календарная проекция создаётся лишь для точного времени, а `unscheduled`, `date_only`, `date_range` и `deadline` остаются полноценными плановыми активностями без почасового блока.

## Владение и приватность

Read API использует существующий `getActivityUserContext()` и фильтрует:

- `user_id = appUser.id`;
- `acting_as_actor_id = personActor.id`;
- `activity_role_code = planned`;
- активные статусы `draft`, `planned`, `confirmed`.

Данные другого пользователя или активного профиля не возвращаются.

## Правила группировки

### Без даты

Включаются только `unscheduled`.

Порядок: сначала недавно изменённые.

### Срок скоро

Включаются:

- `date_only` по `scheduled_date`;
- `date_range` по `schedule_end_date`;
- `deadline` по `deadline_at`.

Период: от текущего момента до следующих 7 суток.

`exact` не дублируется на полке, потому что точная активность уже представлена календарной проекцией.

Порядок: ближайший срок первым.

### Нужно уточнение

Для каждой активности выбирается самый новый semantic run из полученных записей.

Активность включается, только если именно последний run имеет статус `needs_clarification`. Старый запрос на уточнение не показывается, если более новый run уже обработан.

Порядок: недавно обновлённое уточнение первым.

## Пользовательский интерфейс

Над календарём отображаются три компактные карточки.

По умолчанию каждая карточка показывает не более трёх элементов. При наличии дополнительных результатов доступно разворачивание списка.

Каждый элемент содержит:

- название активности;
- режим планирования;
- статус;
- дату или срок, если он существует;
- ссылку «Подробнее» в существующий Activity Container по `activityEventId`.

## Побочные эффекты

Read API и полка:

- не создают активность;
- не создают календарную проекцию;
- не запускают и не повторяют semantic analysis;
- не изменяют AI-правила;
- не выполняют подтверждение результатов;
- не входят в CUX7 Timeline/Gantt.

## Приёмка

1. Полка находится над календарём.
2. Есть три локализованные группы.
3. `unscheduled` появляется в «Без даты».
4. `date_only`, `date_range` и `deadline` ближайших 7 дней появляются в «Срок скоро».
5. Последний `needs_clarification` появляется в соответствующей группе.
6. `exact` не дублируется в «Срок скоро».
7. Данные ограничены активным actor/profile.
8. По умолчанию видно не более трёх элементов группы.
9. «Подробнее» открывает существующий Activity Container.
10. Shelf GET не выполняет записи и не запускает анализ.
