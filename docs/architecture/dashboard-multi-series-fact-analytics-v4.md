# ARCTor Dashboard Multi-Series Fact Analytics V4

Дата: 2026-09-26

## Цель

Расширить существующий блок Dashboard «Изменение во времени», чтобы в одном
графике можно было одновременно показывать несколько рядов подтверждённых
фактов, не ломая уже существующие одиночные блоки V3.

Первый целевой сценарий:

- количество выпитых чашек кофе по дням;
- продолжительность глубокого сна по дням;
- факт принятия мелатонина по дням.

## Контракт блока

Новый вариант использует:

- visualization: `line`;
- source: `facts`;
- metric: `multi_series`;
- aggregation: `sum`;
- grouping: `day`;
- period: `7 | 14 | 30` дней;
- `config_json.contract = dashboard-analytics-v4`;
- `config_json.scaleMode = independent`;
- `config_json.series` — массив от 2 до 6 рядов.

Миграция БД не требуется: существующее поле `config_json` уже хранит объект
JSON и подходит для массива конфигураций рядов.

## Виды рядов

### numeric

Числовой ряд хранит:

- `id`;
- `kind = numeric`;
- `valueObjectId`;
- `parameterDefinitionId`;
- `parameterCode`;
- `canonicalUnitCode`;
- display-only названия объекта и параметра.

Исполнение использует существующий V3 resolver одного ряда, включая
`measurementRollupV1`, проверку единицы измерения, политику UNKNOWN и защиту от
двойного счёта direct + derived.

### presence

Ряд присутствия хранит:

- `id`;
- `kind = presence`;
- `valueObjectId`;
- display-only название объекта.

На конкретный день записывается значение `1`, только если существует
подтверждённый факт, непосредственно или через effective semantic link
связанный с выбранным объектом наблюдения.

Если такого подтверждённого факта нет, значение остаётся `null`. Отсутствие
записи не интерпретируется как доказанное отсутствие события и не превращается
в 0.

Это позволяет, например, показывать на одном графике точки дней, когда был
зафиксирован факт принятия мелатонина.

## Проверка и безопасность конфигурации

Сервер не доверяет display text как идентичности.

Для каждого числового ряда повторно проверяются:

- UUID объекта;
- UUID определения параметра;
- leaf-доступность объекта;
- активное назначение параметра;
- numeric value type;
- canonical parameter code;
- canonical unit.

Для ряда presence повторно проверяется leaf-доступность объекта.

Повторяющиеся semantic rows и повторяющиеся series id отклоняются.

## Исполнение

`/api/dashboard/analytics-data` определяет V4 по `metric_key = multi_series`.

Для каждого numeric-ряда вызывается существующий проверенный
`buildObservationFactSeriesResponse`.

Для каждого presence-ряда используется отдельный read-only resolver:

1. читает подтверждённые `activity_object_facts` активного пользователя/актора;
2. ограничивает период;
3. учитывает прямой `value_object_id`;
4. расширяет связь через `activity_fact_value_object_links_effective_v1`;
5. дедуплицирует fact id;
6. возвращает `1` только в дни с подтверждённым фактом, иначе `null`.

Результат объединяется в `kind = observation-fact-multi-series`.

## Разные единицы измерения

V4 допускает совместное отображение рядов с разными единицами, например:

- `count`;
- `minute`;
- `presence`.

Первая версия использует независимые скрытые шкалы Y для каждого ряда. Поэтому
каждый ряд сохраняет реальные значения и собственную единицу, но визуально
масштабируется независимо. Реальные значения показываются во всплывающей
подсказке, а легенда указывает конкретный объект/параметр.

Это предотвращает ситуацию, когда 120 минут сна визуально «подавляют» 3 чашки
кофе только из-за разных порядков величин.

## UI

Во втором шаге мастера V3-выбор одной пары «объект + параметр» остаётся
работоспособным.

Для line-графика добавлены действия:

- добавить числовой ряд;
- добавить факт наличия;
- удалить ранее добавленный ряд;
- добавить до 6 рядов.

Совместный график создаётся после добавления минимум двух рядов.

Старый single-series путь сохраняется: если массив рядов не создавался, мастер
продолжает отправлять старый `numeric_value` + V3 config.

## Обратная совместимость

`isDashboardAnalyticsV4Supported()` добавляет новый V4 вариант и для всех
старых вариантов делегирует проверку в `isDashboardAnalyticsV3Supported()`.

Существующие блоки V1/V2/V3 не требуют миграции и не переписываются.

## Acceptance

Основной сценарий:

1. создать line-блок;
2. выбрать источник «Факты по объектам наблюдения»;
3. добавить ряд «Кофе / Количество»;
4. добавить ряд «Продолжительность глубокого сна / Длительность»;
5. добавить presence-ряд «Принятие мелатонина»;
6. выбрать 7/14/30 дней;
7. создать блок;
8. получить три серии в одном графике, каждая со своей фактической единицей;
9. дни без подтверждённого мелатонина остаются неизвестными (`null`), а не 0;
10. старый одиночный график V3 продолжает работать без изменений.
