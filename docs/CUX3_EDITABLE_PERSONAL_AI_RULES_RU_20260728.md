# ARCTor.app — CUX3: редактируемые персональные правила AI

## Цель

Пользователь получает личную редактируемую копию правил интерпретации календарных сообщений. Глобальный системный текст ARCTor остаётся неизменным.

## Приоритет интерпретации

1. Явные данные текущего сообщения.
2. Персональные правила пользователя.
3. Стандартные правила ARCTor.
4. Уточнение у пользователя при неоднозначности.

Персональное правило заполняет только недостающие данные. Оно не может заменить явно указанную пользователем дату, время, интервал или длительность.

## Хранение

- `calendar_ai_rule_preferences` хранит текущую персональную версию по пользователю и языку.
- `custom_rule_text = null` означает использование неизменяемого системного текста.
- `calendar_ai_rule_revisions` хранит последовательную историю сохранений и восстановлений системного текста.
- Локали: `en`, `pl`, `ru`, `uk`, `de`, `es`, `cs`.
- Fallback: точная персональная локаль → персональный английский текст → системный текст выбранной локали.

## Синтаксис

Поддерживаются два слоя:

1. Инструкции обычным языком, передаваемые semantic model как недоверенный пользовательский контекст.
2. Детерминированные ярлыки, которые работают и при недоступности модели.

Пример:

```text
КОГДА "рыбалка" => НАЗВАНИЕ "Рыбалка"; БЛИЖАЙШЕЕ воскресенье 09:00-12:00; ЦЕЛЬ "Рыбалка по воскресеньям"
```

Строки, начинающиеся с `#`, `//` или `;`, являются комментариями.

## UI

Редактор открывается кнопкой «Правила AI» внутри inline composer календаря. Доступны:

- редактирование текста;
- сохранение персональной версии;
- восстановление системного текста;
- справка по синтаксису и приоритету;
- проверка несохранённого текста правила без создания активности;
- отображение источника и версии правила.

## Интеграция semantic preview

`/api/calendar/activity-review/semantic-preview`:

- читает персональные правила авторизованного пользователя;
- применяет детерминированный ярлык после разбора явных данных сообщения;
- передаёт текст правил модели в отдельном недоверенном блоке;
- не разрешает правилам изменить preview-only границы или JSON-контракт;
- возвращает метаданные о применённом правиле и предложенных целях.

## API

`/api/calendar/ai-rules`

- `GET ?locale=ru` — текущая эффективная версия;
- `PUT` — сохранить персональный текст;
- `DELETE` — восстановить системный текст для локали.

Все операции требуют авторизованного активного actor context. Запись выполняется только server-side через service role. Прямой доступ `anon` и `authenticated` к таблицам запрещён.

## Acceptance

- редактор открывается из inline composer;
- персональный текст сохраняется и доступен после перезагрузки;
- системный текст восстанавливается;
- версия увеличивается при каждом изменении;
- история ревизий создаётся автоматически;
- тест правила не сохраняет активность;
- персональный ярлык применяется к semantic preview;
- явные дата и время сообщения не перезаписываются;
- CUX1 и CUX2 сохраняют работоспособность.

## Вне scope

- полный реестр переводов пользовательского контента;
- автоматический выбор VO по предложенному названию;
- расширенный поиск VO;
- task shelf;
- drag-and-drop;
- multiday bars;
- Timeline/Gantt.

## Контролируемая runtime-проверка базы

Runtime acceptance выполняется в три шага:

1. `20260728_cux3_calendar_ai_rules_runtime_acceptance_and_rollback.sql`
   создаёт временную диагностическую функцию, выполняет 11 проверок,
   удаляет тестовую preference-запись и её ревизии и возвращает таблицу
   результатов.
2. `20260728_cux3_calendar_ai_rules_runtime_helper_cleanup.sql`
   удаляет только временную диагностическую функцию.
3. `20260728_cux3_calendar_ai_rules_runtime_cleanup_postcheck_READONLY.sql`
   проверяет удаление функции, отсутствие preference-fixture и отсутствие
   orphan revision rows.

Runtime acceptance не использует temporary table: Supabase SQL Editor может
выполнять отдельные выражения через разные соединения, из-за чего temp-таблица
может исчезнуть до финального `select`.

Успешный критерий:

- runtime acceptance: `11/11`;
- cleanup postcheck: `3/3`;
- `preferenceResidualCount = 0`;
- `revisionResidualCount = 0`.
