## Scope CUX7C3A

CUX7C3A добавляет только безопасную read-only группировку по прямым `planned_target` связям:

- календарный API читает активные связи плановой активности с ценными объектами;
- exact-проекция получает связи через `calendar_events.related_activity_event_id`;
- `date_only`, `date_range` и `deadline` получают связи через собственный `activity_events.id`;
- List и Timeline получают переключатель «обычный вид / по ценным объектам»;
- группы сворачиваются независимо;
- запись без связи попадает в отдельную группу «Без ценного объекта»;
- запись с одной связью попадает в группу этого ценного объекта;
- запись с несколькими связями показывается в группе каждого связанного ценного объекта;
- на карточке показываются названия всех прямых целей;
- Grid не меняется;
- popup и write paths не меняются.

## Правило множественного членства

Каноническая активность в базе остаётся одной записью.

Если у неё несколько активных `planned_target` связей, представление календаря показывает ту же активность в каждой соответствующей группе ценного объекта. Это повторение только в read-only UI и не создаёт копий `activity_events`, `calendar_events` или связей.

Верхний счётчик периода продолжает считать уникальные канонические записи. Счётчик конкретной группы показывает количество записей, относящихся к этому объекту. Поэтому сумма счётчиков групп может быть больше общего количества записей периода.

На каждой карточке сохраняются chips всех прямых целей. Нажатие на любую визуальную копию открывает один и тот же Activity Container или календарный popup исходной активности.

## Ownership и безопасность чтения

Чтение `activity_value_object_links` фильтруется по:

- `app_user_id`;
- `actor_id`;
- `link_type = planned_target`;
- `status = active`;
- точному набору `activity_event_id`.

Чтение `value_objects` фильтруется по:

- `owner_user_id`;
- `owner_actor_id`;
- точному набору `id`.

Большие наборы идентификаторов читаются чанками.

## Коррекция после Production smoke

Первоначальная специальная группа «Несколько ценных объектов» оказалась непригодной для практической навигации: при пяти или десяти целях она скрывает, к каким именно объектам относится активность.

Исправленное правило:

- одна связь — активность видна в одной группе;
- несколько связей — активность видна в каждой соответствующей группе;
- отсутствие связей — активность видна в группе «Без ценного объекта»;
- специальная группа множественных целей больше не используется;
- канонические данные не дублируются.
