# ARCTor Management OS — ближний backlog и передача контекста

**Дата:** 19.10.2026 · **Статус:** предложенный рабочий порядок, не автоматическое разрешение на код/SQL.

## 1. Первая практическая работа — прямо сейчас

**Цель:** зарегистрировать одно доказанное безопасное дело, исполнить его с внешним ИИ и передать следующему ответственному без устных пояснений автора.  
**Владелец:** платформенный owner/admin.  
**Рекомендуемая предметная задача:** неоднозначная типовая активность (`TA-MATCH-001`). Если такого реального случая нет, выбрать другой подтверждённый неперсональный кейс; не выдавать демонстрацию за пользовательский дефект.  
**В интерфейсе:** `/admin` → `ADM-2B.2` → `create` → `report` → `handoff`.

### Минимальный набор доказательств первого пилота

- CaseCode, assignmentId и первоисточник, степень приватности.
- Версия микропротокола и реально отправленный безопасный промпт.
- Ответ ИИ, проверка существования ID, явные ошибки, неизвестные данные.
- Отчёт `reportText` в истории дела и подтверждение нового назначения.
- Список недоработок UI/API, фактические шаги воспроизведения, ожидание и результат.

## 2. Следующий инженерный MVP — маленькими патчами

| Пакет | Минимальный результат | Готовность / ограничения |
|---|---|---|
| `MVP-1` | Карточка поручения: тип задачи, инструкция, безопасный промпт, сводка ИИ, проверка, следующее действие | Сначала source + DB intake, не плодить второй реестр дел |
| `MVP-2` | Библиотека микропротоколов, версия и закреплённое соответствие taskCode → protocol | Proposed не повышать автоматически до approved |
| `MVP-3` | Формализованные решения человека `accept/revise/reject` и подтверждённые артефакты | Отчёт ≠ приёмка; отдельная серверная авторизация |
| `MVP-4` | Ограниченные права конкретных менеджеров и ролевые кабинеты | Не выдавать `platform_admin owner/admin`; Admin Assist boundary review до multiuser |
| `MVP-5` | Приёмка смены менеджера и история по должности | Смена пользователя не переписывает исторические события |
| `MVP-6` | Минимальный Privacy Gate для того, что копируется во внешний ИИ | Нет исходных личных текстов в промптах без явного допуска |

**Порядок:** сначала ручной пилот; затем выбирать по найденным препятствиям MVP-1/2/3, перед многопользовательским доступом обязательны MVP-4 и граница Admin Assist; MVP-6 в минимальном виде действует с первого дня.

## 3. Шаблон короткой ежедневной записи менеджера

```text
ДАТА / РОЛЬ:
ДЕЛО И ПОРУЧЕНИЕ:
СОБЫТИЯ И ДЕЙСТВИЯ: что делали, ссылки
ПРОМПТ ИИ: ID/version, что передавалось, без личных данных
РЕЗУЛЬТАТ: что доказано / что предложено
ОШИБКИ И ИСПРАВЛЕНИЯ: причина / проверка / статус
ПРИНЯТЫЕ ЧЕЛОВЕКОМ РЕШЕНИЯ: кто и что разрешил
НОВЫЕ ЗНАНИЯ: только verified-кандидаты, provenance
НЕЗАКРЫТО: blockers, риски, вопросы
СЛЕДУЮЩИЙ ШАГ: ответственная должность, ожидаемый результат
```

## 5. Минимальное определение готовности первого релиза для практической работы

Первые доступные функции дают полезный рабочий результат в одном реальном кейсе; новый человек без личного чата получает историю и может продолжить; никакая непроверенная рекомендация ИИ не изменила БД/код/ОН. Если отдельная возможность ещё отсутствует, она честно указана в backlog и не имитируется текстовым обещанием.
