# ARCTor Management OS — пакет пояснительных записок и запуска ручного пилота

**Дата:** 19.10.2026 · **Версия:** 1.0 · **Статус:** документация подготовлена; никаких изменений сайта/БД не выполнено.

## Состав

1. `01_CONCEPT_EXPLANATORY_NOTE_RU.md` — что это за система, зачем она нужна, как должна работать.
2. `02_FACTUAL_STATE_AND_DECISIONS_RU.md` — что именно уже реализовано, проверено и что пока нельзя считать готовым.
3. `03_MANUAL_PILOT_OPERATING_REGULATION_RU.md` — инструкция запуска первого реального дела на текущем `/admin`.
4. `04_MICROPROTOCOL_TA_MATCH_001_RU.md` — готовая узкая инструкция для сопоставления типовой активности.
5. `05_MICROPROTOCOL_ON_REVIEW_001_RU.md` — готовая узкая инструкция проверки необходимости нового ОН.
6. `06_MVP_BACKLOG_AND_HANDOFF_RU.md` — маленькие патчи по приоритету и перенос контекста в другой чат/должность.

Три первых документа также приложены в формате Word (`.docx`) для удобного чтения и редактирования.

## Главное решение

Практический MVP = **человек-менеджер + внешняя модель ИИ + дела/поручения/отчёты/передача в ARCTor**. Встроенные ИИ-исполнители пока не запускаются. Система развивается в процессе реальной работы. Прежде чем подключать независимых менеджеров, нужна привязка конкретного человека к функциональной роли и проверка границ Admin Assist.

## Как начать

Открыть документ `03_MANUAL_PILOT_OPERATING_REGULATION_RU.md`; выбрать подлинный неперсональный случай, зайти на `https://arctor.app/admin`, открыть `ADM-2B.2` и выполнить `create → внешнее AI → report → handoff` по описанным полям. Использовать микропротокол TA-MATCH-001. Не создавать демонстрационное дело, не пометив его `DEMO`.

## Как сохранить документацию в локальном репозитории

Скопировать **MD-файлы** в `C:\Users\Admin\Documents\projects\gpt-app\docs\admin-mvp\`. Скрипт `INSTALL_LOCAL_DOCS_ONLY.ps1` может сделать это с предварительной проверкой хешей, не выполняя commit/push/deploy. Копии Word оставить в Downloads для работы с документами.

Источники: текущие исходники `src/app/admin/ArctorAdminCaseActions.tsx`, `src/app/api/admin/management/actions/route.ts`, `src/app/api/admin/management/registry/route.ts`, акт закрытия P1 и source review P2. Все будущие данные Git/Vercel/DB перепроверять перед действиями.
